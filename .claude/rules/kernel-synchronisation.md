## 6. 同期方針（SMP。BKL）

- カーネル内の共有データは **BKL（big kernel lock）**で守る（ADR-0023）。
  カーネルへの入口で取り、出口で離す。**入口は列挙してあり、取らない入口は
  理由つきで並べてある**（`kernel/src/bkl.rs` の `NON_ACQUIRING_ENTRIES`）。
- **BKL を取らない経路が3種類ある。** 例外・ダブルフォルト・パニックである。
  **取れば、保持者が例外で死んだときに他コアが永久に待つ。**
- 割り込みハンドラは「実行中コードを横から中断する疑似並行処理」であり、
  共有データを触る区間は必ず守る。**同一コアの再入も競合である。**
- BKL より下位の細かい排他は `Locked<T>`（`common/src/critical.rs`）で行う。
  **中身は割り込み禁止 + 取得フラグ + 保持者の記録**で、
  **競合したら待たずに保持者を出して停止する**（fail-fast。ADR-0004）。
- **BKL を保持したまま `Locked<T>` を取ってよい。逆は作らない。**
  向きを固定して循環待ちを構造から消す。
- **BKL を保持したまま眠らない・待たない。** I/O 待ちが入る段（S13）で、
  この前提を明示的に設計し直す。

**この節は S1 から S8 で変わった。** かつては「シングルコア前提」で、
「本格的なスピンロック/アトミックは SMP 対応時に差し替える」と書いていた。
**その SMP が入ったので、書き換えてある。**
