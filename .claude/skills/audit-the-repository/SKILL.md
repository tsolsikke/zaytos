### 12.1 リポジトリ監査の手順

痕跡が残っていないかを確認する際は、次の順序で行う。

1. `git ls-files` と `git rev-list --all --objects` の**全件を目視**し、
   想定外のファイルが無いか確認する。ビルドや実行に不要な個人メモ・
   作業ログが混ざっていないかを見る
2. 非 ASCII ファイル名の検出（`grep -P '[^\x00-\x7F]'`）。日本語名の
   一時ファイルは意図せず混入しやすい
3. **ファイル内容の文字種検査。** 追跡対象ファイルと未コミットの変更を
   対象に、非 ASCII 文字を Unicode ブロック別に集計し、想定外のものが
   無いか確認する。想定しているのは、ひらがな・カタカナ・CJK 統合漢字・
   CJK 記号句読点・半角全角形・矢印・罫線素片・数学記号・`§`、および
   単独の記号 `×`（U+00D7）・`±`（U+00B1）・`µ`（U+00B5）・`⟹`（U+27F9）。
   キリル文字・ハングル・ギリシャ文字・絵文字などが出たら混入である。

   **後半の4字は、公開の作業で追跡下の全ファイルを数え直したときに出た。**
   以前の一覧はブロックだけを挙げており、**`×` と `±` と `µ` はラテン 1 補助、
   `⟹` は補助矢印 C にあって、どのブロックにも入っていなかった。**
   **以前から追跡下にあり、混入ではない**（掛け算・誤差・マイクロ秒・含意）。
   **一覧のほうが実測と合っていなかった。** 件数は書かない。増減するためである。

   **ブロックで挙げると、同じ目的の字が別のブロックに散る。**
   実際、矢印は 2 つのブロックに分かれ（`→` と `⟹`）、
   演算の記号も数学記号とラテン 1 補助に分かれている（`⊕` と `×`）。
   **次に足すときは、ブロックではなく用途で確かめること。**

   ファイル名だけを見ても内容の混入は分からない。見た目が似た別字（キリル
   文字の `с` と ASCII の `c` など）は目視では気づけないため、ブロック別に
   機械的に集計すること。

   **この項目自身が、上の例としてキリル文字を1つ含んでいる。**
   **追跡下にあるキリル文字はその1つで、監査で出るのもそれである。**
   **2つ以上出たら混入である。** 注記にもう一度書き写すと2つになるので、
   **ここでは字そのものを繰り返さない。**
4. 現在の追跡ファイルと全履歴パスの差分を取り、削除・改名されたものを
   洗い出す
5. **その後に**キーワード grep（AI 関連・attribution トレーラー・絵文字）

**キーワード grep は補助であって主ではない。** パターンに含まれない
ものは grep では見つからないため、grep の「出力なし」は、そのパターンに
含まれていない対象については何も証明しない。まず全件を見ること。
