**この文書は実装しない。** 欠けている土台を実測で一覧にし、順序の案を出すための材料である。
**運用者が順序を決めたら、決まったものは`roadmap.md`の段になる。この文書は材料として残る。**

**現在地（第1節）はすべて実測である。** 出所はコードと、外の道具（`debugfs`）と、ビルドが生成した定数である。

**費用の目安（第2節）はすべて見積もりである。実測ではない。** **順序の案（第5節）はこの見積もりを根拠にしているので、そこが動けば順序も動く。**

- **`brk`と`mmap`のどちらが安いかは測っていない。** **H段の入口で測ってから決める前提である。** **この文書は「どちらかを決める判断が要る」とまでしか言っていない。**

## 1. いまの現在地（実測。2026-08-22）

### 1.1 システムコールは12個で、実装は11である

**`kernel/src/syscall.rs`の`dispatch`が腕を持つのが11、定数が12である。**
**12個目の`SYS_NEVER_IMPLEMENTED`（`0x10FF`）は永久に実装しない的で、`-ENOSYS`が返ることを確かめるために予約してある。**

| 番号 | 名前 | 出所 |
|---|---|---|
| 0 | `read` | Linux |
| 1 | `write` | Linux |
| 2 | `open` | Linux |
| 3 | `close` | Linux |
| 4 | `stat` | Linux |
| 16 | `ioctl` | Linux（`TIOCGWINSZ`だけ） |
| 60 | `exit` | Linux |
| 217 | `getdents64` | Linux |
| 0x1001 | `check_ptr` | 私用（検査） |
| 0x1002 | `checksum` | 私用（検査） |
| 0x1004 | `spawn` | 私用 |
| 0x10FF | `never_implemented` | 私用（永久に実装しない） |

**私用の基点は`ZAYTOS_PRIVATE_BASE = 0x1000`である**（Linuxの番号表と衝突しない）。

### 1.2 POSIXの中核と突き合わせる

**「小さなCのプログラムが動く」までに要る番号で見る。** `sbase`や`toybox`の`ls` / `cat` / `echo`が呼ぶ範囲である。

| 名前 | 状態 | 無いと何が作れないか |
|---|---|---|
| `read` / `write` / `open` / `close` | 有 | —— |
| `stat` | 有（`fstat`は無い） | `ls -l`相当。**`fstat`はfdから引く形で、開いてから調べる道が無い** |
| `getdents64` | 有 | —— |
| `lseek` | **有**（DIR(1)。`SEEK_SET`だけ受ける） | —— |
| `mmap` / `brk` | **無**（1つも無い） | **`malloc`。動的な大きさを扱う全プログラム** |
| `execve` | **無** | シェルの`exec`。**いまは`spawn`が読み込みと実行を1つにしている** |
| `fork` / `clone` | **無** | パイプライン、ジョブ。**`vision.md`と`deferred-decisions.md`が費用を測ってある** |
| `wait4` | **無**（融合して在る） | **`spawn`が同期で、子の終了状態を下位8ビットで返す**（実測）。**非同期の子が無いので、分離した`wait`の利用者がまだ居ない** |
| `dup` / `dup2` | **無** | **リダイレクト（`>`・`<`）とパイプ。fdの付け替えが要る** |
| `pipe` | **無** | パイプライン |
| `rt_sigaction`ほか | **無** | シグナル。**Ctrl+Cは旗で実現してある**（`kernel/src/input.rs`）——**シグナルではない** |
| `clock_gettime` | **無** | 時刻。`date`。ファイルの時刻。**単調なティックは在る**（100Hz）**が、壁時計の源が1つも無い**（RTCを読む箇所は無い。実測） |
| `mkdir` | **有**（DIR(1)。`-p`は無い） | —— |
| `unlink` | **有**（DIR(1)。`rmdir`も入った） | —— |
| `rename` | **無** | 改名。`mv` |
| `chdir` / `getcwd` | **無** | カレントディレクトリ。**いまは全パスが絶対である** |
| `readlink` | **無** | シンボリックリンク。**ext2の読む側もリンクを解決していない** |
| `fcntl` | **無** | `O_NONBLOCK`ほか。**`read`が既に非ブロックなので、当面の利用者は薄い** |
| `uname` / `getpid` | **無** | 名乗り。**Cの移植で当たる見込み** |

### 1.3 6つの軸ごとの現在地

**プロセスの一生**
- **起動時の約束は既に正しい形である（実測。ここが今回いちばん大きい発見である）。** `kernel/src/userland.rs`の`build_initial_stack`が積むのは、`rsp`から順に`argc`・`argv`のポインタ列・NULL・`envp`の終端・`auxv`の`AT_NULL`である。**SysVの形そのもので、`crt0`がそのまま書ける。**
- **`argv`は積んでいる**（上限8。`MAX_ARGV`）。**`envp`は「終端だけ」の空である。** **`auxv`は`AT_NULL`だけである。**
- **`spawn`は同期で、終了状態を返す**（`status & 0xFF`。畳みと中断は旗で区別する）。**`zash`は`status < 0`しか見ていない**——**`$?`が無い。**
- **`exec`は無い。** `fork`も無い。深さの上限で再入を制限している。

**ファイルの一生**
- **作成は在る**（`O_CREAT`。zi-e）。**削除・改名・ディレクトリ作成は無い。**
- **fdの表は16個**（`MAX_OPEN_FILES`）。**複製と付け替えは無い。**
- **書き込みはRAM複製までである**（ADR-0037）。**再起動で消える。**
- **像の中身は実測で`/bin`・`/data`・`/etc`・`/lost+found`の4つだけである**（`debugfs`で読んだ）。`/bin`に8本、`/etc`に`motd`が1つ。

**メモリ**
- **ユーザーヒープが無い。`brk`も`mmap`も1つも無い**（実測）。
- **ユーザースタックは1ページ（4096バイト）である。** **`argv`と文字列もこの1ページに載る。**
- カーネルヒープは1MiB固定。

**時間**
- **壁時計の源が無い**（RTCを読む箇所が1つも無い。実測）。
- **単調なティックは在る**（LAPICタイマ100Hz。`idt::timer_ticks`）。TSCも読める。

**端末**
- **`ioctl`は`TIOCGWINSZ`だけである。** 設定の変更（`termios`相当）は無い。
- **生モードの切り替えが無い。** **`read`は常にバイトを返し、行編集はユーザー側が持つ**（`zash`と`zi`がそれぞれ自前で持っている）。

**プロセス間**
- **パイプもシグナルも無い**（実測。痕跡が1つも無い）。

## 3. 環境変数が解く連鎖

**運用者の指示で明示する。** **`envp`が入ると、いま塞がっている項目が3つ解ける。**

| 塞がっている項目 | いまなぜ塞がっているか | `envp`が入るとどうなるか |
|---|---|---|
| **キーボード配列を選べるようにする** | **選ぶ手段そのものが無い**（`deferred-decisions.md`の行。**だからJISに固定した**） | **解けない。** **配列を読むのはカーネルのデコーダで、Ring 3の`envp`を見ない**（下の訂正） |
| **`TERM`の名乗り** | 端末の種類を伝える道が無い | `TERM=zaytos`を渡せる。**Cの移植で`ncurses`相当に当たるときに要る** |
| **`PS1`相当** | プロンプトが固定 | シェルが読める |

**逆向きも書いておく。** **`envp`が無いままでも、上の3つはカーネルの定数として実現できる。** **できるが、そのたびにカーネルを建て直すことになる**——**「設定」ではなく「ビルド」になる。**

### 訂正——配列の選択は`envp`では解けない（2026-08-22。ADR-0041の設計で判明）

**この節は最初、3つとも`envp`で解けると書いていた。誤りだった。**

**`envp`が届く先はRing 3のプロセスである。** **キーボードの配列を読むのはカーネルのデコーダ（`kernel/src/keyboard/decode.rs`）で、あれはRing 3のスタックを見ない。**
**解くには「カーネルが読む設定の源」が別に要る**——`/etc/environment`を`init`が読むか、設定を伝えるシステムコールか、のどちらかである。

**そしてその源は、永続化（P段）が入るまで運用者が変えられない**（書き込みがRAM複製に留まるので、ファイルにしても像を建て直すことになる。ADR-0037）。

**したがって`envp`が直接解くのは`TERM`と`PS1`の側だけである。** **表の行はそのように直した。**

**訂正したことを残すのは、EVの段で解ける範囲を次に読む者が誤らないためである**（第5節でEVの理由を入れ替えたときと同じ作法）。

## 4. Cのプログラムを動かす道筋

**3段階で見る。** 費用はすべて見積もりである。

1. **自作の小さな`ls`**——**既に在る**（`kernel/userland/ls.rs`。135行）。**Rustで書いており、Cではない。**
2. **自前の小さなlibcで、Cの`hello`を動かす**——**要るのは`crt0`と、`write`・`exit`の薄い包みだけである。** **初期スタックの形が既にSysVなので、`crt0`はそのまま書ける**（実測）。**ここが最初の的として現実的である。**
3. **`sbase` / `toybox`のような依存の浅い実装**——**`malloc`が必ず要る**（したがって`brk`か`mmap`）。**`fstat`・`lseek`・`getdents64`・`opendir`相当も要る。** **`getdents64`は在る。**
4. **GNU coreutils**——長期。**`fork` / `exec` / シグナル / ロケールまで要る。**

**自前libcの見積もり（見積もりである。測っていない）。**
**いまの`userlib.rs`は419行で、`open` / `read` / `write` / `close` / `getdents64` / `ioctl` / `spawn` / `exit`の包みと、`winsize`の扱いを持っている。**
**Cから使う形にするには、これに加えて`crt0`（`_start`から`main`へ）、`malloc`、`printf`族、`str*` / `mem*`が要る。**
**`str*` / `mem*`はコンパイラの組み込みで足りる場合がある**（未確認。**測ること**）。
**`printf`は自前で書くと大きい。** **最初は`puts`と`write`だけで進むのが現実的である。**

## 5. 順序の案

**運用者が決めた大枠は「基盤の棚卸し → H段（ヒープ）→ P段（永続化）→ C移植 → GUI（FHD）」である。**
**要望の3件（SE / EV / DIR）をどこへ差し込むかが、この棚卸しの答えである。**

**案。**

1. **EV（環境変数）を最初に置く。**
   **理由は「後から変えると高いから」ではない。** **実測で、約束の枠が既にSysVの形で在ると分かった**（`build_initial_stack`が`envp`の終端を積んでいる）。**したがって「作り直しになる」危険は小さい。**
   **置く理由は2つである。** **(1) 安い**（見積もり。**空の枠に中身を入れる作業であって、並びを作り直す作業ではない**）。**(2) 連鎖して解ける項目が多い**（第3節。配列の選択・`TERM`・`PS1`）。
   **この理由は棚卸しの途中で変わった。** **着手前は「起動時の約束は後から変えると全ユーザープログラムに波及するので最優先」と見ていた**（`roadmap.md`のEV段の初出もその書き方だった）。**実測が根拠を入れ替えた。** **古い理由のまま読むと、判断の根拠を誤る。**
   **ここで「ユーザースタックを1ページから増やすか」も一緒に判断する**——**同じページに載るので、切り離せない。**
2. **DIR(1)（ただのディレクトリとFHSの規約）を次に置く。**
   理由——**規約は早く決めるほど写しが散らない。** **`mkdir`が要る**ので、`unlink`と`lseek`（どちらも部品が在って入口が無い）を一緒に足すのが安い。
3. **H段（ヒープ）。** ここで**メモリ獲得の約束（`brk`か`mmap`か）をADRで決める。**
4. **SE（シェルの行編集）。** **履歴の置き場がヒープで済むので、H段の後が安い。** **`Ctrl+A`と`Ctrl+C`の層の重なりを実測してから作る。**
5. **P段（永続化）。**
6. **C移植**（まず自前libcで`hello`。次に`sbase`）。**ここで`/dev/tty`が要るなら、DIR(2)をここへ差し込む。**
7. **GUI（FHD）。** **bootloaderが`set_mode`を呼んでいないので、最初に要る作業はそれである**（実測。`roadmap.md`のES段の締めにある）。

**DIR(3)（`/proc`）はこの案に入れていない。** **利用者がまだ居ないためである。** **GUIの情報表示が利用者になる見込みなので、GUIの段で判断する。**

**この案が動く条件を1つ書いておく。** **EVを最初に置くのは「安いから」ではなく「後から変えると高いから」である。** **もし実測でEVが思ったより高いと分かったら、順序ではなく範囲を削ること**（たとえば「シェルが持つ環境を1つだけ」から始める）。

## 5-2. DIR(1)で埋まったもの（2026-08-23）

**この文書は棚卸しの時点の像である。** **埋まったものは表の中で「入った」と書き換えた**——**消さない。** **何が無かったかが分かるほうが、次に読む者の役に立つ。**

**DIR(1)で埋まったのは5つである。** `mkdir` / `rmdir` / `unlink` / `lseek` と、`PATH`（ADR-0043）。**置き場所の規約も決めた**（ADR-0042）。

**残ったのは`rename`である。** **`mkdir`と同じ族の会計を持つ**（ディレクトリを跨ぐと親の参照数が動く）ので、**`mkdir`が入ったいまは、着手の費用が下がっている。**

## 6. 測っていないこと

**3つある。** **どれも順序の根拠に触れるので、名指しで並べる。**

1. **費用の目安はすべて見積もりである。実測ではない。** **第2節の「費用の目安」の欄と、第5節の順序の案が、これに乗っている。** **見積もりが外れたら、順序ではなく範囲を削ること**（第5節の末尾に同じことを書いてある）。
2. **`brk`と`mmap`のどちらが安いかは測っていない。** **H段の入口で測ってから決める前提である。** **この文書が言っているのは「どちらかを決める判断が要る」までで、どちらが良いとは言っていない。**
