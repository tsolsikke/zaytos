# 0049. シェルが`$NAME`を展開する。語が丸ごと空になったら落とす

## Status

Accepted

## Date

2026-08-28

## Context

**SE段で`echo`が要る**（運用者の要望。2026-08-22。**`PATH`の中身を確かめる道が無い**という
DIR(1)の目視から出た）。**`echo`は`/bin/echo`（外部）で確定している**（`ADR-0043`の基準）。

**したがって展開はシェルが行う。** **`echo`の側に値へ変える手段が無い**——外部プログラムは
`argv`を受け取るだけで、受け取った時点で`$PATH`はただの7バイトである。

**いま環境から取れる名前は2つだけである。** `TERM`（`ADR-0041`）と`PATH`（`ADR-0043`）で、
**`export`も`set`も無い**ので、**打つ人が変数を作る手段は無い。**
**2つにしか当たらない規則を決めることになるが、決めないと後から変えられない**——
展開の規則は打ち方そのもので、変えると既存の行の意味が変わり、判定も書き直しになる。

**`zash`の実測**（2026-08-28）。

- **`run_line`が行をその場で語へ切る。** 空白を`0`へ書き換え、`argv`は`line`の中の語を指す。
  **したがって展開は、切る前に行う。**
- **展開は長さを変える。** `LINE_MAX`は128で、`line[length]`に終端を置く形になっている。
  **その場で伸ばすと終端の置き場が壊れる**ので、**写しへ展開する。**
- **いまの値は短い。** `PATH`は`/bin`の4バイト、`TERM`は`zaytos`の6バイトで、
  **128を超えない。** 規則としては上限の扱いが要る。
- **語の上限は`MAX_ARGS` = 8である。**

## Decision

**シェルは、行を語へ切る前に`$NAME`を展開する。** 規則は次の7つである。

1. **認識するのは`$NAME`だけである。`${NAME}`は作らない。**
   `NAME`は`[A-Za-z_][A-Za-z0-9_]*`とする。
2. **未定義の名前は空文字へ落とす。**
3. **展開したあと、語が丸ごと空になったら、その語を落とす。**
   **`echo a $UNSET b`は`a b`である**（空白は1つ）。**空の語を`argv`に残さない。**
4. **展開の結果で語を割らない。** 値に空白が含まれていても、語は増えない。
5. **エスケープ（`\$`）は作らない。** **`$`の直後が`NAME`の先頭になれる字でなければ、
   `$`はそのままの字として残る**（`$`単体、`$1`、`$?`はそのまま残る）。
6. **展開は行の写しに対して行い、写しが`LINE_MAX`を超えたら行全体を断る。**
   文言は既存の`zash: line too long`と同じものを使う。**部分的に展開した行を走らせない。**
7. **展開の対象は環境から取れる名前だけである。`set`と`export`は作らない**（`ADR-0041`のまま）。

**3が要である。** **2だけでは決まっていない**——空へ落とした結果が「語が消える」のか
「空の語が残る」のかで、`argv`の数が変わる。**数が変わることが、打ち間違いに気づく
手がかりである**（`ls $TMP`が`ls`になれば、引数を渡したつもりが渡っていないと分かる。
空の語が残ると`ls ""`になり、受け手が空の名前を開こうとする）。
**この体制のコマンドは空の引数を想定していない。**

## Alternatives Considered

- **案 `${NAME}`も作る。却下。**
  **境界を明示する唯一の手段だが、いま境界が要る場面が無い**——値を連結する行を
  誰も書いていない。**使う者がいない機構は検算が置けない**（この体制の規律）。
  **要る場面が来たら足す**（持ち越しへ行を置いた）。
- **案 未定義の名前をそのまま残す。却下。**
  **打ち間違いが文字列として黙って渡る。** `$PATHH`が`$PATHH`のまま`argv`へ入り、
  **`cannot run`が出るまで気づけない。** **空へ落として語を消せば、引数の数で気づく。**
- **案 展開の結果で語を割る（word splitting）。却下。**
  **`sh`はそうするが、この体制はPOSIX互換を目標にしないと決めてある**（`CLAUDE.md`の
  「スコープ外」）。**割る形は引用（`"`と`'`）とセットである**——割ると決めた瞬間に
  「割らせない書き方」が要る。**割らなければ、`sh`で`"$VAR"`と書く場面が引用無しで得られる。**
  **2つを同時に判断すべきなので、両方を持ち越しにする。**
- **案 エスケープ（`\$`）を作る。却下。**
  **`\`の扱いそのものが無い。** **1文字のために字句の層を1つ増やすことになる。**
  **`$`を字として打ちたい場面が出たら、引用と一緒に判断する。**
- **案 特殊変数（`$?`・`$1`）を作る。却下。**
  **`$?`は終了状態だが、`zash`は0以外を`zash: exit status N`として既に出している**
  ——**読む手段が既に在る。** **`$1`は位置引数で、シェルスクリプトが無いので置き場が無い。**
  **どちらも使う者がいない。**

## 決めないこと

**それぞれ`docs/deferred-decisions.md`に行を置いた。発火の契機で書いてある。**

- **引用（`"`と`'`）**
- **語の分割（word splitting）**
- **`export`と`set`**
- **特殊変数（`$?`・`$1`）**
- **`${NAME}`の境界**

## 判定

**`cargo xtask run --shell-test`を延ばす。** **4つとも、打鍵を流して出力を見る形である。**

1. **`echo $PATH`が`/bin`を出す**（展開が起きている）
2. **`echo a $UNSET b`が`a b`を出す**（**空白が1つ**。**空の語が落ちている**）
3. **`echo $UNSET`が空行を出す**（語が0個になる）
4. **`echo a$TERM b`が`azaytos b`を出す**（**`$`の直後以外の字が壊れない**）

**2と3を両方置く。** **3だけだと、語が0個でも空の語が1個でも空行になり、
2つの形を区別できない。** **区別するのは2の空白の数である。**

## 破壊

**2つ足す。どちらも、その形でしか落ちない判定がある。**

- **`shell-skip-expansion-test`**——**展開を素通りさせる。** 判定1が落ちる
  （`$PATH`がそのまま出る）
- **`shell-keep-empty-word-test`**——**空になった語を落とさない。** **判定2だけが落ちる**
  （`a  b`になり、空白が2つになる）。**判定1・3・4は緑のままである**——
  **これがDecisionの3を守っている唯一の判定である。**

## Consequences

- **`echo $PATH`と`echo $TERM`が動く。** **`PATH`の中身を確かめる道ができる**
  （DIR(1)の目視で出た指摘が閉じる）
- **`$`を字として打つ手段が無くなる**——`$`の直後が名前の先頭になれる字なら、必ず展開する。
  **いま`$`を打つ場面が無いので費用は出ていないが、出たら引用と一緒に判断する**
- **行の写しに`LINE_MAX`ぶんの領域が要る。** **`zash`のスタックが128バイト増える**
  （`kernel/userland/user.ld`の受け皿の位置を見ること）
- **展開の規則が増えるたびに、この判定の4つを数え直すことになる**
