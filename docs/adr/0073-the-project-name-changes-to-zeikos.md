# 0073. OSの名前をZaytOSからZeikOSへ変え、旧い名前を残す識別子を決める

## Status

Accepted（2026-09-28に運用者が決定し、2026-10-01に実施を始めた）。実施は下のR1からR6の順に進める。

## Date

2026-10-01

## Context

- プロジェクトの正式な名前をZeikOSへ変えると、運用者が決めた（2026-09-28）。名前を変えるだけで、機能・設計・開発の順序は変えない。
- 名前は、文書・コメント・画面とログに出る文字列・コードの識別子・起動媒体・運用上の識別子（環境変数・記録とロックの置き場・VMの接頭辞・作業フォルダ）・GitHubのリポジトリ名に出る。2026-10-01に数えると、追跡しているファイルで898件・141ファイルである（`target/rename-survey/`の台本。大文字と小文字を区別しない）。
- 境界の段階の手順2は「名前とパスしか変えていない」ことを、起動ログ・逆アセンブルの関数名・x86の言葉の基準で確かめていた。改名は起動ログの表示名や記号を動かすので、手順2の区切りの後に、独立した段階として行う（運用者の決定）。
- 記録の文書（ADR・troubleshooting・棚卸し）とコミットの履歴は、その時点の事実を残すためにある。書き換えると、当時の実測や判断と名前が食い違う。

## Decision

1. 表記はZeikOS、読みは「ぜいくおーえす」、略した呼び方は「ぜいこす」とする。小文字の識別子が要る所は`zeikos`、大文字の識別子が要る所は`ZEIKOS`とする。
2. 次の順に、1段ずつ確かめてから進める。
   - R1: 文書（今の状態を書く文書と、混ざる文書の今の状態の行）とコードのコメント。報告の書式のファイル名もここで変える。
   - R2: 画面・ログ・端末に出る名前（`TERM`の値を含む）と、それを期待値にしている検査。
   - R3: コードの識別子（`zaytos_`の記号・`zaytos_main`・`ZAYTOS_PRIVATE_BASE`・`ZAYTOS_LIBC_H`・一時の名前）。名前だけの変更であることを、名前を読み替えた逆アセンブルと起動ログで確かめる。
   - R4: 起動媒体（ESPの置き場・FATのラベル・イメージの名前）。VirtualBoxでの起動の確かめは、運用者の了承の上で行う。
   - R5: 運用上の識別子（環境変数・記録とロックの置き場・VMの接頭辞とVDI・作業フォルダと全検査の作業ツリー）。1項目ずつ案を見せてから行う。
   - R6: GitHubのリポジトリ名。運用者が操作し、その後に手元のリモートのURLとREADMEのバッジを直す。
3. 旧い名前を残すものと、その理由は次のとおりである。
   - 記録の文書（ADR・`docs/troubleshooting.md`・棚卸しの文書）と、混ざる文書（`docs/roadmap.md`・`docs/deferred-decisions.md`・`docs/verification-coverage.md`）の日付つきの記録・完了した段階の記録・済の行: 書いた時点の事実を残すためである。記録の中のパスが旧い名前のファイルを指すときは、移したパスの表（`xtask`の`DOC_PATH_MOVES`）で今の在り処へ読み替えて確かめる。
   - コミットの履歴: 書き換えない（`CLAUDE.md`の「書き換えてよい境界」）。
   - 運用上の識別子: R5で1項目ずつ移すまでは、旧い名前のまま動く。移すときは、旧い置き場も1段階だけ読み、ロックは移す間だけ両方を取り、環境変数は1段階だけ旧い名前も受ける。VMの接頭辞は、2つを同時に受ける時期を作らない（接頭辞は、道具が操作してよいVMを限る条件なので、広げない）。
   - GitHubのリポジトリ名と、それを指すURL（READMEのバッジを含む）: R6で運用者が改名するまで、旧い名前のまま残す。
4. `Seinas`と`Kieli`の名前は変えない。途中の候補だった「ZeikuOS」は採らない。アイコンとASCIIアートは、運用者から渡されるまで扱わない。

## Alternatives Considered

- **一度に全部を置き換える**: 採らない。画面の文字列・識別子・起動媒体・運用上の識別子では、確かめ方と戻し方が違う。混ぜると、名前だけの変更であることを機械で示せない。
- **記録の文書と履歴も新しい名前に書き換える**: 採らない。当時の実測と判断が、別の名前の下に書かれていたことが消える。
- **旧い名前を別名として残し続ける**: 採らない。同じものに2つの名前ができ、読む人と検査の両方を迷わせる。移す間だけ旧い名前も受ける所（R5）は、1段階で旧い側を外す。

## Consequences

- 今の状態を書く文書とコードは新しい名前になり、記録と履歴は旧い名前のまま残る。旧い名前で探すときは、記録の側に当たることがある。
- R5とR6が終わるまでは、運用上の識別子とリポジトリ名に旧い名前が残る。
- R5は2026-10-01に終えた。移す間だけ受けていた分（環境変数の旧い名前、記録とロックの旧い置き場を読む処理、旧い名前のまま隣に残る作業ツリーを移す処理）は、同じ日に外した。旧い置き場の記録は、外す前に新しい置き場へ写した。
- R6は2026-10-01に終えた。運用者がGitHubのリポジトリ名を`zeikos`へ変え、手元のリモートのURLとREADMEのバッジを直した。旧い名前で新しいリポジトリは作らない（GitHubの旧いURLからの転送が止まるため）。
