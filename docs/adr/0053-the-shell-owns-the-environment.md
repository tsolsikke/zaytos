# 0053. 環境はシェルが持ち、`spawn`の第3引数で子へ積む——`export`と`set`は組み込み

## Status

Accepted

## Date

2026-08-31

## Context

**f-2である。** **f-1（`ADR-0052`）と同じ発火で動く3件の2件目で、残りは履歴の保存（f-3）である**（`docs/deferred-decisions.md`）。

**`ADR-0041`の却下案(a)が、この段の形まで書いている**——**「採るのは、シェルに`VAR=val cmd`か`export`が来たときである。そのとき`spawn`の第3引数として受ける形になり、`copy_user_argv`と同じ検証をもう1本書くことになる」。** **この文書は、その予約を実行する。**

### 実測——いまの姿（2026-08-31。HEAD = c4ac826）

- **環境の実体はカーネルの単一の表である**（`kernel/src/userland.rs`の`ENVIRONMENT: Locked<Environment>`）。**`MAX_ENVP` = 8、`ENV_LINE_MAX` = 128、いま入っているのは3本**（`TERM` / `PATH` / `HOME`）
- **積むのは1箇所だけである**（`load_user_program`が錠の外へ写して`build_initial_stack`へ渡す。`kernel/src/userland.rs`）
- **`zash`は環境を4箇所で引く**——`PATH`（`remember_path`）、`TERM`（`decide_prompt_color`）、`HOME`（`expand_word`）、`$NAME`（`expand_word`）。**どれも自分の初期スタックから引いている**（`userlib::environment`）
- **`userlib::spawn`の呼び出しは2箇所で、どちらも`zash`である**（`run_line`と`spawn_via_path`）
- **`userlib::spawn`は`syscall3(SYS_SPAWN, path, argv, 0)`と書いてある**——**第3レジスタへ既に0を渡している。** **カーネルは見ていない**
- **`spawn-test`は生の`asm`で`int 0x80`を打ち、RDXを設定していない**（実測。`kernel/userland/spawn-test.rs`）
- **`user-load`のログが`argc=`と`envc=`を既に出す。** **`user-stack`のログが使用量と`over_half=`を出す**
- **ユーザースタックは1ページ（4096バイト）で、`MAX_ARGV_BYTES`は1024である**
- **`MAX_SPAWN_IN_FLIGHT`は2である**（`MAX_EXCURSION_DEPTH`と同じ）

### シェルは、どの形を採っても私有の表を持つことになる

**`$NAME`を展開するのはシェルである**（`ADR-0049`）。**`export FOO=bar`の直後に`echo $FOO`が効くには、シェル自身の引き先が変わらなければならない。**

**シェルの初期スタックは張り替えられない**——**`envp`は起動時に積まれた1ページの中に在り、伸ばす場所が無い。** **したがって、環境の持ち主をどちらに決めても、`zash`は私有の表を持つ。** **決めることは「子へ何を積むか」だけである。**

## Decision

**6つ決める。**

### 1. 環境はシェルが持つ。カーネルの表は「起動時の環境」へ退く

**`zash`は起動時に、自分の初期スタックの`envp`を私有の表へ写す。** **以後、引くのも子へ積むのもその表である。**

**カーネルの表は、カーネルが直に起こすプロセスにだけ積む**——**`init`が起こす`/bin/zash`と、起動シーケンスの直線上のプログラムである**（`kernel::userland::spawn`をカーネル側から呼ぶ経路）。

**打ち消す先は3つである。**

- **`ADR-0041`のDecision 2の後半**（すべてのプロセスへ同じものを積む）
- **`ADR-0049`の規則7**（`set`と`export`は作らない）
- **`ADR-0052`のDecision 6**（全プロセスへ同じものを積むのは変えない）——**3つ目である。** **引き継ぎは2つを挙げていたが、実測で3つ目が出た。** **あの決定は「プロセスごとに違う環境を持つのは f-2 の話である」と自分で書いており、ここがその f-2 である**

**丸ごとSupersededにしない。** **`ADR-0037`と`ADR-0041`の前例に従い、偽になったDecisionだけを打ち消して指す。**

### 2. `spawn`は第3引数で`envp`を受ける。NULLは`-EFAULT`である

**`argv`の規則をそのまま使う**——**「配列を要求している。引数が無いことは空の配列で表す」**（`copy_user_argv`のdoc）。**新しい規則を作らない。**

- **検証は`copy_user_argv`を一般化して両方で使う**（要素数の上限と緩衝の大きさを引数に取る形）
- **上限は要素数`MAX_ENVP` = 8、バイト数`MAX_ENVP_BYTES` = 1024。越えたら`-E2BIG`**（`argv`と同じ族）
- **カーネル側の緩衝は`SPAWN_ARGVS`と同じ形の`static`へ置く**（深さぶん。2 × 1024 = 2KiB）

**ユーザーポインタが1本増える。** **面が増えるので、この段はレビュー必須である**（`CLAUDE.md`の§5）。**「増えない見込み」は実測で否定された**——**シェルが持つ形でも、子へ渡す口が要る以上、境界を越える配列が1本増える。**

**`spawn-test`のasmを直す。** **あれはRDXを設定していない**（実測）。**RDXに意味を与えると、あの`spawn`は`-EAGAIN`ではなく`-EFAULT`を返しうる**——**写しは深さの判定より前に走る**（`spawn_from_ring3`が`copy_user_argv`を呼んでから`userland::spawn`へ入り、深さを見るのはその中である）。**判定1（`-EAGAIN`）が静かに別のものを見はじめる形なので、空の`envp`を明示的に渡す。**

**RDXがたまたま0であっても直す。** **偶然に頼った捕捉は捕捉ではない**（`CLAUDE.md`の検査文化）。

### 3. `export`は組み込みである。書式は`export NAME=VALUE`だけにする

**`ADR-0043`の基準(1)——シェル自身の状態を変えるので外部では実装できない——に当たる。** **`ADR-0043`のDecision 2が「対象ができた段で、この決定に従って組み込みになる」と予約しており、これはその実行である。新しい判断ではない。**

- **`export NAME`（既にあるシェル変数を環境へ移す形）は作らない。** **シェル変数という層が無い**——作ると`$NAME`が2つの表を引くことになり、**`ADR-0049`の規則2（未定義は空へ落とす）が「どちらの表で未定義か」を含むようになる**
- **名前の規則は`classify_env_line`と同じ`[A-Za-z_][A-Za-z0-9_]*`である。** **同じ判定を2つ持たない**——**`common/src/env.rs`へ移し、カーネルとシェルの両方が`#[path]`で取り込む**（`ADR-0045`の形）
- **1行に複数書ける**（`export A=1 B=2`）。**左から順に適用し、最初に断ったところで止める。** **既に適用したものは残る**
- **引数が無ければ誤りを出す。** **一覧は`set`の仕事である**
- **値の`$NAME`は既に展開されている**——**展開は行を語へ切る前に済んでいる**（`ADR-0049`）。**`export`は`argv`を受け取るだけで、何もしない**

### 4. `set`は組み込みである。一覧を出すだけにする

**基準に当てると外部にも書ける**——**`set`はシェルの状態を変えない。** **それでも組み込みにする理由は、一覧の対象がシェル自身の表だからである。**

**外部が見られるのは、積んだ写しである。** **いま両者が一致しているから同じに見えるにすぎない**——**シェルの表と積む中身が食い違ったとき、外部の`set`は食い違いを見せられない**（緑の4形の「状態が変わらない」）。

- **出す形は`NAME=VALUE`を表の順に1行ずつ。** **並べ替えない**（並べ替えの規則を作る対象が無い）
- **選択肢の切り替え（`set -e`相当）は作らない。** **切り替える対象が無い**（運用者の判断）

### 5. 上限は`ADR-0041`のDecision 5の形をそのまま使う。越えたら断る

- **`MAX_ENVP`は8のままにする。** **いま3本なので、打つ人が足せるのは5本である**
- **既にある名前への`export`は上書きで、枠を消費しない**
- **`NAME=VALUE`が`ENV_LINE_MAX`（128）を超えたら断る**
- **黙って切り詰めない・落とさない。** **`ADR-0052`のDecision 3（ファイルは超えたぶんを落とす）と分ける。** **理由は伝える先である**——**`export`は打つ人の明示の行為で、誤りを返す口が在る**（エコー領域。`ADR-0046`）。**起動時のファイル読みには、その口が無い**

**面積の実測。** **最悪で`envp`が1024 + 表72バイト、`argv`が1024 + 表72バイトで、初期データは2.2KiB前後である。** **1ページ（4096）には収まるが、残りはプログラム自身のスタックである。** **`user-stack: used ... over_half=`が既に出しているので、越えたらそこに出る**（`ADR-0041`のDecision 4）。**上限を上げる判断は、その行が半分を越えてから行う。**

### 6. 起動時に控えている2つをやめ、使うたびに表から引く

**`PATH_VALUE`と`COLOR_PROMPT`である**（`kernel/userland/zash.rs`）。**控えたままだと`export PATH=...`が効かない**——**「変えたのに効かない」が残る。**

**これで`export`がシェル自身の振る舞いを変えることが観測できる**——**`ADR-0043`の基準(1)の実物である。**

## 決めないこと

- **`unset`**——**打つ人が要ると言っていない。上書きで足りる。** 持ち越しへ行を置く（契機=消さないと困る場面が出たとき）
- **`VAR=val cmd`（1回限りの環境）**——`ADR-0041`の却下案(a)が並べていたもう片方である。**`export`で足りる**
- **`env`コマンド / `export -p`**——**外部から環境を見る道。** **`set`が在れば足りる**
- **シェル変数（`export`しない変数）**——Decision 3の理由と同じ
- **`/etc/profile`と`~/.profile`**——**f-3の前である**（次の段。順序は運用者の決定）
- **書き戻し**——**`export`は再起動で消える。** **残したければ`zi /etc/environment`である**

## Alternatives Considered

### (a) 環境をカーネルがプロセスごとに持ち、`setenv`システムコールで変える

**却下する。** **面では勝たない**——**`setenv`もユーザーポインタを1本増やす**（文字列1本）。

**そして`execve`が来たときに作り直しになる。** **`ADR-0041`が「`execve`が来たら、第3引数として`envp`を受ける形になる」と予測しており、その形はこちらではない。**

**入れ子の問題もある。** **`MAX_EXCURSION_DEPTH`は2で、`spawn`は同期の入れ子である**（実測）。**プロセスごとの表を持つと「深さと表の対応」という概念が要り、`SPAWN_ARGVS`と同じ形の場所取りがもう1つ増える。**

### (b) カーネルの単一の表を`setenv`で書き換える（全プロセスに効く）

**却下する。** **変更はいちばん小さい**——**`ADR-0041`のDecision 2の後半が生き残り、打ち消しが1つ減る。**

**却下の理由は、意味が違うことである。** **子が親の環境を変えられる。** **いま呼ぶ者が1人（`zash`）なので観測できないが、観測できない差を残すことになる**——**Cの移植で`setenv`を持つプログラムが来た日に、静かに壊れる。**

### (c) `export`した中身を`argv`の先頭へ紛れ込ませて渡す

**却下する。** **口を増やさずに済む唯一の案だが、`argc`の意味が壊れる。** **`spawn-test`が`argv`を突き合わせており、`ADR-0049`の判定も`argc`を読んでいる**——**両方が別のものを見はじめる。**

### (d) `envp == NULL`を「起動時の環境を継ぐ」にする

**却下する。** **`argv`と違う規則を作ることになる。**

**そして、シェルの積み忘れが「起動時の3本が届く」に化ける**——**正しく見える**（緑の4形の「状態が変わらない」）。**`-EFAULT`なら、積み忘れはその場で落ちる。**

### (e) `set`を外部`/bin/set`にする

**却下する**（Decision 4）。**`env`という名前で外部を作る案は「決めないこと」へ置いた。**

### (f) `ADR-0041`を丸ごとSupersededにする

**却下する。** **偽になるのはDecision 2の後半だけで、Decision 1・3・4・5は生きている。** **前例は`ADR-0037`と`ADR-0041`に在る。**

## 判定

**`cargo xtask run --shell-test`へ足す。** **打鍵の台本なので、費用は打鍵数である。**

1. **`export ZF2=zaytos`の後に`echo $ZF2`が`zaytos`を出す。** **シェルの表が引けている**
2. **`set`が`ZF2=zaytos`を含む4行を出す。** **表の一覧である**
3. **子へ届いたこと**——**`export`の後に起こした子の`user-load: ... (argc=..., envc=...)`を見る。** **打つ前が`envc=3`、打った後が`envc=4`である。** **前後の両方を見る**
   - **判定1はこれを主張しない。** **展開はシェルが行うので、`echo $ZF2`は子が何も知らなくても`zaytos`を出す**（`ADR-0049`）。**判定1と判定3は別のものを見ている**
   - **`envc`は既に出ている**（実測）。**新しい観測を作らずに済む**
   - **期待値は像の状態に依る。** **台本の回は`disk0.img`を作り直すので変数は3本だが、持ち越した像には手で足した行が入りうる**（実測。2026-08-31に運用者の`disk0.img`へ`KEYMAP=jis`が入っていた）。**`f-1b`の`keymap`の回は像を作り直さない**——**判定を置く回がどちらかを、実装のときに確かめる**
4. **`export PATH=/nonexistent`の後に`ls`が起こせず、`export PATH=/bin`で戻る。** **シェル自身の振る舞いが変わる**（Decision 6）
   - **台本の順序に意味がある。** **`PATH`を壊した状態で次の行が走ると、後続が全部落ちる**——**この2行は続けて打ち、台本の後ろへ置く**

5. **誤りが人に見えること**——**`export 1BAD=x`が名前の規則で断られ、エコー領域に誤りが出る**（運用者の指示。2026-08-31）。
   - **足す理由は、`export`の誤りの経路が台本で一度も通らないことである。** **上限と`ENV_LINE_MAX`超はホストテストで覆うが、あちらは「断る」までしか言わない**——**断ったことが人に見えるか**（`ADR-0046`のエコー領域）**は別の主張である。**
   - **打鍵は短い**（`export 1BAD=x`で13打。**上限を試す形は6行×20打を超える**）。**費用を測って選んだ。**

**上限（Decision 5）はホストテストで覆う。** **台本で6本の`export`を打つのは打鍵が長い**（1行あたり20打鍵を超える）。**表の操作（足す・上書き・上限で断る）を`common/src/env.rs`の純粋な論理に置けば、ホストで固定できる**——**`CLAUDE.md`の絶対ルール5そのものである。**

**2度起こす枠は使わない。** **`export`は再起動で消えるので、持ち越しの主張が無い。** **`--full`の2度起こす項目は3種のままで、所要は伸びない**（`CLAUDE.md`の§10の注意）。

## 破壊

**1つ足す。**

- **`shell-export-not-pushed-test`**——**`export`した表を子へ積まず、自分の初期スタックの`envp`をそのまま渡す。** **判定3だけが落ちる**（`envc`が3のまま）。**判定1・2は緑である**——**シェルの表は引けているからである。** **この形でしか落ちない判定が判定3である**

**上限の破壊は置かない。** **判定が台本に無く、ホストテストで覆うためである**（`CLAUDE.md`の検査文化——**破壊は、その形でしか落ちない判定があるときに足す**）。

## 目視の借り

**プロンプトの色は画面である。** **`export TERM=dumb`で色が消えることは、台本では見られない**（`COLOR_PROMPT`はログに出ない）。**`docs/verification-coverage.md`の「目視の借り」へ1行足す。**

## Consequences

**得るもの。**

- **打つ人が変数を作れる。** **`ADR-0043`のDecision 4の但し書き（`PATH`は固定の既定と同じくらい固定である）が、完全に要らなくなる**——**f-1で起動ごとに変えられるようになり、ここで起動中にも変えられるようになる**
- **`execve`の形へ近づく。** **第3引数で`envp`を受ける口ができる**

**失うもの・引き受ける制約。**

- **ユーザーポインタが1本増える**（`spawn`の第3引数）。**レビュー必須である**
- **`zash`の`.bss`が1KiB増える**（8 × 128）。**像の大きさは増えない**
- **カーネル側の`static`が2KiB増える**（`MAX_SPAWN_IN_FLIGHT` × `MAX_ENVP_BYTES`）
- **初期データが最大2.2KiBまで伸びうる。** **子のスタックの余裕がそのぶん減る**——**`user-stack`の`over_half=`が信号である**

**将来のトレードオフ。**

- **`execve`が来たら、この第3引数がそのまま使える**
- **Cの移植で`setenv`/`getenv`を作るとき、`getenv`は`envp`から引く形が既に在る**（`userlib::environment`）。**`setenv`はプロセス私有の表を触るだけになり、カーネルへ触らない**

## Addendum（2026-08-31。f-2 の実装。設計と違ったところ）

**4 つある。** **どれも実装のときに実測で出たもので、Decision そのものは変えていない。**

### 1. `spawn` を生の`asm`で呼ぶ者が 2 つあった

**設計は`spawn-test`だけを挙げていた。** **実測で`syscall-test`にも 11 箇所あった**——**あちらは`spawn`の答えを 10 通り以上突き合わせている。**

**踏んだ形は設計が予告したとおりである。** **RDX を置かないまま走らせたら、`syscall-test`が状態 36 で終わり、起動が止まった**（`spawn("/bin/hello")`が 0 を返さなかった。実測）。**予告のとおり`-EFAULT`が`-EAGAIN`や 0 の代わりに返っていた。**

**両方に空の`envp`を明示的に置いた。**

### 2. `envp`が NULL のときの判定を`syscall-test`へ足した

**Decision 2 は「`argv`と同じ規則」と書いたが、`argv`の側にだけ判定が在った**（状態 41）。**同じ規則なら同じ判定が要る**ので、状態 68 として足した。

### 3. 破壊はシェル側へ置いた

**設計は「`export`した表を子へ積まず、自分の初期スタックの`envp`を渡す」と書いていた。** **実装では「起動時に積まれていた本数までしか渡さない」形にした**——**同じことを、シェルが持つ表の上で表している。**

**カーネル側で「親が渡した環境を捨てる」形も書けるが、採らなかった。** **主張はシェルが積むことなので、破壊もシェル側に置く**——**カーネル側へ置くと、シェルが積み忘れても捕まらない。**

**実測で、落ちるのは「子が見た`envc`」の 1 本だけだった**（`envc`が 3 のまま）。**判定 1・2・4・5 は緑である。** **設計の見込みどおりである。**

### 4. 判定の添字が既にずれていた（この段で見つけた）

**`echo`の`argc`を見る判定が、生の添字で引いていた。** **f-1 と f-1b が台本の途中へ`echo`の行を 4 つ足したときに、`Ctrl+W`と`$1`を見ている 2 本の添字がずれていた**——**ずれた先の行の`argc`がたまたま同じ 2 だったので、判定は緑のままだった**（実測。2026-08-31）。

**「偶然に頼った捕捉は捕捉ではない」の実例である。** **別のコミットで直した**——**名前の一覧を置き、本数も突き合わせる形にした。** **台本へ`echo`の行を足して一覧へ足さなければ落ちる。**

**この段の判定を足す前に直している**——**ずれたままの上へ 2 本足すと、次にずれたときの被害が増える。**

## Addendum（2026-09-04。HI-1。履歴をファイルへ持ち越す）

**履歴（SE-c）は `.bss` の輪だけで、再起動で消えていた。** **P 段で書き込みが
持ち越されるようになった**（`ADR-0051`）**ので、ファイルに置けるようになった。**

**決めたのは6つである。**

1. **置き場は `$HOME/.zash_history`**（いまの環境では `/root/.zash_history`）
2. **パスは起動時に 1 度だけ組み立てて持つ**——**`/etc/profile` が `HOME` を
   書き換えても、読み書きの先は変わらない**（**シェル自身の状態が、利用者の
   ファイルの中身で動かないようにする**）
3. **書くのは打つたびである**（積んだときだけ。空の Enter と同じ行の
   繰り返しでは書かない）
4. **読むのは起動時で、設定より先である**（2 と同じ理由）
5. **上限は 16 本のままである**
6. **無い / 読めない / 器に入らないの 3 段は `/etc/profile` と同じ形にする**
   （`ADR-0055`）

### 打つたびに書ける——費用を測った

**書きで開いた口を閉じると、像の 2MiB が装置へ書き戻される**
（`kernel/src/syscall.rs` の `SYS_CLOSE`）。**実測で 7.1M〜14.2M サイクル
（約 2.0〜4.1ms。3.48GHz 換算）で、`touch` 1 回・`zi` の `:w` 1 回と同じ費用である。**

**1 行につき 1 回であって、打鍵ごとではない。** **人が Enter を打った後の
3ms は見えない。**

**却下した案は 3 つ。** **終わるときに書く**——**`zash` は終わらないので、
電源で全部消える。** **N 行ごと**——**落ちたときに最大 N 行消える。単純さに
見合わない。** **開いたまま持って閉じない**——**書き戻しは `close` で起きるので、
消えるのは同じである。**

**書き方は「輪を丸ごと書き直す」。** **`O_APPEND` は無く、カーネルが受理する
書きの形は `O_WRONLY|O_TRUNC` と `O_WRONLY|O_CREAT|O_TRUNC` の 2 つだけである**
（`ADR-0037`）。**輪は最大 2,064 バイトなので全置換で足りる。**

### 16 本のままにした——ページが 1 つ増える

**実測（2026-09-04）。** **`zash` の書き込み可の区画は `0x404000..0x404d68` で、
ページの終わりまでの余裕は 664 バイトである。** **32 本にすると 2,176 バイト
増えてページを越え、シェル 1 本につき写像が 1 ページ増える。**

**ファイルにしても輪は `.bss` のままである**——**上限はどちらにせよ要る**
（辿る回数の問題でもある）。**上げるときは、ページが 1 つ増える費用と一緒に決めること。**

### 保存が失敗したときは 1 度だけ言う

**保存が失敗する状態は続く**（装置が答えない、`/root` が無い、など）。
**毎行言うと画面が報せで埋まる。**

**黙る形にしたので、「また言う」条件を決めてある**——**一度でも保存に成功したら
旗を下ろす。** **状態が変わったときにだけ言い直す形で、黙って落とし続けるのとは違う。**

### 判定と破壊

**判定は 3 つ、破壊は 2 つである**（実測。2026-09-04）。

| 判定 | 落とす破壊 |
|---|---|
| 前の起動で打った行が辿って戻る | `shell-history-not-saved-test` |
| ファイルが古い順である | （固有の破壊は無い。上の破壊でも落ちる） |
| 無いときは何も言わない | `shell-history-missing-is-error-test` |

**「新しいものから書く」破壊は置いていない**——**書かない破壊が落とす判定の
部分集合になる。** **実測で確かめてから外した**（`skip-profile` と同じ判断）。
