# 0003. シリアルログを画面描画より先に、最優先の観測手段として用意する

## Status
Accepted

## Date
2026-07-16

## Context
OS自作は「コードを書く」より「なぜ動かないかを実行結果から推理する」比重が高い。
低レイヤのバグは、例外やスタックトレースではなく、無言のハング・リブート・文字化けとして現れることが多く、観測手段がないとデバッグが成立しない。

画面描画（GOP）が動く前の最初期段階でも、状態を外部に出力できる手段が必要。
シリアルポート（COM1 / 0x3F8）は実装が単純で、QEMUの`-serial stdio`によりホスト端末へ直接出力でき、この目的に最適。

ログを機械的に読める形で早期に整えておくほど、失敗原因の特定が速くなり、開発ループの摩擦が下がる。

## Decision
画面描画より先に、シリアルログ出力を確立する。
以降、全機能はその動作がシリアルログで追跡可能であることを担保する。
ログレベル（TRACE/DEBUG/INFO/WARN/ERROR）を最初から設ける。

## Alternatives Considered
- **画面描画を先に作り、そこへログを出す**: GOP初期化前の最初期の不具合を観測できない。却下。
- **観測手段を後回しにして機能実装を優先**: 沈黙のバグに対処できず、かえって遅くなる。却下。

## Consequences
- 最初期からデバッグ可能になり、以降すべての工程の効率が上がる。
- ログを機械的に読める形にしておくことで、実装ループを自動化しやすい。
- シリアル出力の実装を最初に済ませる小さな初期コストが発生する（回収可能）。
