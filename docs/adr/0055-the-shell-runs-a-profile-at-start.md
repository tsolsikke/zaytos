# 0055. シェルは起動時に設定を読んで走らせる

## Status
Accepted

## Date
2026-09-04

## Context

**`export`は在るが、起きるたびに打ち直すしかなかった**（`ADR-0053`）。
**環境の源はファイルである**（`ADR-0052`）**が、あれはカーネルが読む`NAME=VALUE`の表で、コマンドではない**——**`export ZMARK=$ZPROFILE`のような、値を組み立てる行は書けない。**

**利用者が求めたのは「起きたときに走る設定」である**（運用者の指示。2026-09-04）。
**`zash`には既に`run_line`が在るので、読んで渡すだけで足りる見込みだった。**

## Decision

**6つ決めた。**

1. **`/etc/profile`の後に`$HOME/.profile`を読む。** **後のほうが勝つ**（`export`は上書きである）
2. **走るのは対話の前である。** **札（`zash: ready`）の後、最初のプロンプトの前**
3. **ログインシェルと対話シェルを分けない。** **`zash`が起きるたびに読む**（`init`が起こし直したときも読む）
4. **無いときは何も言わない。** **設定はもともと任意である**
5. **行の扱いは打った行とまったく同じである。** **`expand_and_run`を通す**——**`$NAME`の展開も語の切り方も注釈も、対話と同じ規則で動く**
6. **途中の行が失敗しても止めない。** **残りの行を走らせる**

**注釈（`#`）は`run_line`の側へ入れた**——**方言を2つ作らない。** **行頭だけを見る**（下）。

## Alternatives Considered

### (a) `~`の展開を通してパスを作る

**`~`の展開は既に在る**（`expand_word`の規則2）。**通さなかったのは、設定のパスを語として解釈させないためである**——**`open`へ直に渡す。** **出来上がる文字列は同じである**（どちらも`HOME`を引く）。

### (b) `#`を語の先頭でも見る（`bash`の形）

**`bash`は語の先頭を見る**（`echo a #b`の`#b`から後ろが注釈）。**行頭だけにした**——**`zash`には引用も語の分割の規則も無いので、「どこからが注釈か」を語ごとに決める理由が無い。** **行頭だけなら、読む人が1行を見て判断できる。** **途中に注釈を書きたい者が出たら、そこで考えること。**

### (c) 失敗したところで止める

**`run_line`は成否を返さない。** **止める形にするには、走らせた語が失敗したかを持ち回る機構が要る**——**設定のためだけに作るのは高い。** **設定は独立した行の並びなので、1つ落ちたからといって残りを捨てる理由も無い。** **失敗は`run_with_terminator`が画面へ出すので、黙って進むわけではない。**

### (d) ログインシェルだけで読む

**利用者が1人で、端末が1つである。** **分けても言えることが増えない**（運用者の指示）。

### (e) `--shell-test`へ判定を足す

**あちらは QEMU monitor の`sendkey`で1キーずつ打つ**（1キー120ms、1行の後に800ms）。**`echo $ZPROFILE`の1行で約3秒で、`--full`では12構成に掛かる。** **台本の経路（`profile-test`）ならバイトを直に差し込むので、同じ主張が1回の起動で済む。**

## 読めなかったときは3段で決める（`/etc/environment`と同じ形）

- **無い**（`open`が負）——**何も言わずに戻る**
- **在るのに読めない**（`read`が負）——**1行言って、そのファイルをやめる**
- **器に入らない**（1,024バイトを越えた）——**入ったぶんは走らせ、1行言ってやめる**（**黙って切らない**。`ADR-0053`のDecision 5）

**ディレクトリを指した場合は2番目である。** **読み取りで開くのは通る**——**`ls`が`getdents64`で使う道である**——**が、`read`が`-EISDIR`を返す**（`kernel/src/syscall.rs`。`syscall-test`の検算が毎回確かめている）。

## 判定と破壊

**判定は3つ、破壊は3つで、1本ずつ対応する**（実測。2026-09-04）。

| 判定 | 落とす破壊 |
|---|---|
| 2行目まで走り、`$NAME`がその場で展開される | `shell-profile-first-line-only-test` |
| 後のほうが勝つ | `shell-profile-order-swapped-test` |
| 無いときは何も言わない | `shell-profile-missing-is-error-test` |

**「設定を読まない」破壊は置いていない**——**その形でしか落ちない判定を持たない**（運用者の判断）。

**「途中で失敗しても止めない」にも判定が無い。** **主張するには本番の像の`/etc/profile`へわざと落ちる行を置くことになる**——**設定を置いていない人の画面に、毎起動そのエラーが出る。** **理由と道は`docs/deferred-decisions.md`に行を立てた。**

**`SE-d`の破壊（`shell-skip-expansion-test`）が`profile-test`の3本とも落とす**（実測）。**打った行と設定の行が同じ道を通っていることの、構造の側からの主張である。**

## Consequences

- **設定の置き場ができた。** **`PATH`や`TERM`は`/etc/environment`（カーネルが読む表）、コマンドで組み立てる設定は`/etc/profile`である**——**源が2つに見えるが、層が違う**（片方は`envp`、片方はシェルの行）
- **`#`が対話の行でも注釈になった。** **既存の判定で`#`を打っているものは無い**（実測）
- **像に2本増えた**（`/etc/profile`と`/root/.profile`）。**使用ブロックが増え、起動ログの参照の取り直しが要る**
- **`zash`が起きるたびにファイルを2本開く。** **`init`が起こし直すたびにも走る**——**起こし直しが速い形（PERF）を考えるときは、この2本を数に入れること**
