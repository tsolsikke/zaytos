# 0064. unixドメインのストリームソケット——名前で繋ぐ、双方向の通り道を、パイプの核の上に置く

## Status

Accepted

## Date

2026-09-19

## Context

**(b3)でパイプが入り、待ち・EOF・EPIPE・2本のRing 3の同時実行が確かめられた**（`ADR-0063`）。**第1段階の残りはunixドメインのストリームソケット／共有メモリとfdの受け渡し／画面と入力をユーザープロセスへ渡す経路である。**

**Waylandが要求するものを読み直した**（`docs/wayland-inventory.md`）——**接続はUNIXドメインのストリームソケットで、端点は名前（既定は`wayland-0`。`WAYLAND_DISPLAY`で変えられ、継承したfdも認める）。fdの受け渡しは`wl_shm.create_pool`の1つだけで、待ち方は要求しない（`epoll`は要らない）。メッセージは32ビット語の並びで、カーネルは解釈しない。**

**この段階が出すのは、名前で繋ぐ／双方向のストリーム／EOFとEPIPE／`accept`の待ち、である。** **出さないのは、fdの運搬・`mmap`・`poll`である。**

### 遠征スタックの高水位——設計の最初に見積もった（運用者の指示）

**`syscall-test`の深さ0の高水位は31,752 / 65,536（48%）で、半分の監視（32,768）まで1,016バイトだった。** **(b3)の+1,984を関数ごとに切り分けた**（`objdump`で前置きの`sub rsp`を足した。`0a96d56`と`d7937f6`）。

| 関数 | (b3)前 | (b3)後 | 差 |
|---|---|---|---|
| `syscall_entry` | 440 | 456 | +16 |
| `spawn_from_ring3` | 2,888 | 2,888 | 0 |
| `userland::spawn` | 8,328 | 8,328 | 0 |
| `load_user_program` | 4,560 | 6,528 | **+1,968** |
| `run_loaded_program` | 7,768 | 7,768 | 0 |
| `ring3::enter` | 232 | 232 | 0 |
| `dispatch` | 600 | 600 | 0（`spawn`は`dispatch`の外） |
| `sys_read` / `sys_write` | 1,368 / 808 | 1,400 / 840 | +32 / +32（`spawn`の経路に無い） |

**和が合う**——**+1,968 + 16 = +1,984で、起動ログの29,768→31,752と一致する。** **機序は、子が走っている間ずっと載っている6つの枠の和（26,200）＋読み込みか破棄の一時の深さ（5,552）である。** **この6つに触らなければ高水位は動かない。**

**ソケットの入口は`dispatch`の中に置き、5つとも`#[inline(never)]`の関数へ出す。** **6つの枠には触らない。** **見込みは`syscall-test`の高水位±0である**（実測は「測ったもの」）。**枠（64 KiB）はこの段階では動かさない**（運用者の決定Q1の(i)）——**次にfdの受け渡しの段階で`load_user_program`に「継承したfd」を足すなら、(b3)の継承が1,968かかったので余裕1,016に入らない。** **その段階の設計時に`load_user_program`の枠を先に読み、入らなければ先に戻す**（持ち越しの行の見直すきっかけを書き換えた）。

### パイプの核のどこを再利用し、どこを足すか

| 要るもの | パイプで作ったもの | ソケットでの扱い |
|---|---|---|
| 輪（読む・書く・満杯・空） | `Pipe`の`buf`/`head`/`len`（256バイト） | **再利用**——`Ring<const N>`として`pipe.rs`から切り出した（`kernel/src/ring.rs`。単独の`refactor`）。接続1つに2本、1,024バイトずつ |
| 読む側の待ち／書く側の起こし | `Wait::PipeReadable/PipeWritable`＋`wake_tasks_waiting_on` | **再利用（形）**——`Wait::SocketReadable/SocketWritable{conn, side}`を足した。起こす場所は`socket.rs`に集めた |
| EOF | `writers == 0`で0 | **再利用（規則）**——相手側の端が閉じたら0。端は各側1つなので数ではなくフラグ |
| EPIPE | `readers == 0 && !reserved` | **再利用（規則）**——相手側が閉じていれば`-EPIPE`。シグナル無し |
| `File`の種類 | `PipeRead{pipe}` / `PipeWrite{pipe}` | **足した**——`Socket{state}`（`Unbound` / `Listener{listener}` / `Stream{conn, side}`）。1つのfdで読み書き両方 |
| 閉じる経路の一本化 | `File::release_pipe_end`（`close`と`FileTable`の`Drop`） | **再利用**——`release_end`に改め、ソケットの枝を足した。名前の解放もここ |
| 2本目のRing 3 | `SYS_SPAWN_DETACHED` / `start_detached` | **再利用**——`init`がサーバーを切り離して起動する（`concurrent-test`と同じ形） |
| 読み手の予約（次の`spawn`へ） | `create(true)` / `INHERITED_ENDS` | **使わない**——名前で繋ぐので継承が要らない |
| 名前（`bind`/`listen`/`accept`/`connect`） | 無し | **足した**——カーネル内の名前表。ext2にinodeは作らない |
| `accept`の待ち | 無し | **足した**——`Wait::SocketAcceptable{listener}`。`connect`が起こす |
| fdを別プロセスへ運ぶ | 無し | **この段階では作らない**（次の段階） |

## Decision

**7つ決めた**（運用者の承認。2026-09-19）。

1. **遠征スタックの枠はこの段階では動かさない**（上の見積もり。**利用者が居るときに触る**）。
2. **最初の利用者は検査用の組（`/bin/sockd`と`/bin/sockc`）である**（下の「本番の利用者が無い、初めての段」）。
3. **名前はカーネルの表である**（ファイルシステムに現れない。抽象名は`-EINVAL`）。
4. **容量は listener 1本／接続2つ／輪1,024バイト×2／名前31バイトである。**
5. **`syscall-test`に2項目足した**（65: `socket()`が3を返して閉じられる、66: 待ち受けの無い名前への`connect`が`-ECONNREFUSED`）。**既定の起動ログの検算が64から66に動く。** **QEMUの項目を増やさずに「口が在ること」を毎回の`--commit`で見る。**
6. **`Ring`の切り出しを単独の`refactor`で先にした**（`ADR-0063`が「ソケットと共通の核」と決めたものを型にした）。
7. **「待つ理由を2つ持つ形」は作らず、持ち越しに立てた**（見直すきっかけは「画面と入力の受け渡しの段の設計時」）。

### 本番の利用者が無い、初めての段（運用者の足す1点）

**W1-c以降、すべての段階に本番の利用者が居た**——**シェルの`|`、`sleep`、`read`。** **ソケットは初めて、検査用の組だけで進む。**

**原則「利用者の無い機構を先に作らない」との関係。** **本番の利用者はSeinas（コンポジタ。別リポジトリ）で、まだ無い。** **例外にする根拠は、この組が本番の形の予行であることである**——**Waylandの形に合わせてある。サーバーは起動時に起動され、名前で待ち、クライアントはシェルから名前で繋ぐ。** **Seinasが来たときに、カーネルの入口を作り直さずに済む。** **「ソケットのときも本番の利用者は無かった」を次の口実にしないために、ここに書く**——**例外が成り立つのは、本番の形が仕様（`wayland.xml`と`ch04`）で先に分かっている場合だけである。** **仕様の無い機構には当てはまらない。**

**`sockd`/`sockc`はSeinasが来ても捨てない。** **検査（`socket-test`）に残す**——**カーネルの入口の判定を、コンポジタの都合（プロトコルの解釈・画面）から切り離しておくためである。** **Seinasが`socket-test`の代わりになることはない**——**あちらは別リポジトリで、この検査は`--full`の中に居る。**

### 入口——番号と形はLinuxから採る

| 入口 | 番号 | 受けるもの | 断るもの |
|---|---|---|---|
| `socket` | 41 | `AF_UNIX`(1)・`SOCK_STREAM`(1)・`protocol` 0 | 他のdomainは`-EAFNOSUPPORT`(97)、typeのフラグを含めて1以外は`-EINVAL`、protocolが0以外は`-EPROTONOSUPPORT`(93) |
| `bind` | 49 | `sockaddr_un`（`sun_family` u16 = 1、`sun_path[108]`。110バイト） | 空・抽象名（先頭NUL）は`-EINVAL`、31バイト超は`-ENAMETOOLONG`(36)、取られていれば`-EADDRINUSE`(98)、スロットが無ければ`-ENOBUFS`(105) |
| `listen` | 50 | `bind`済みのfd | それ以外は`-EINVAL`。`backlog`は接続の上限（2）で頭を切る |
| `accept` | 43 | `addr`はNULLだけ。待ち行列が空なら待つ | `addr`がNULL以外は`-EINVAL`（相手の名前は返さない） |
| `connect` | 42 | `Unbound`のfd | 待ち受けが無ければ`-ECONNREFUSED`(111)、待ち行列が満杯なら`-EAGAIN`(11)、繋がっていれば`-EISCONN`(106) |
| `read`/`write` | 0 / 1 | `Stream`のfd | 繋がっていないソケットは`-ENOTCONN`(107) |
| `close` | 3 | `Stream`は端を閉じて相手を起こす。`Listener`は名前を返し、accept前の接続のserver側を閉じる | ——— |

**私物にしない**——**パイプの入口が私物だったのは`spawn`の形に付いたからで、ソケットにはLinuxの形そのものが在る**（`ADR-0020`）。**`sendmsg`/`recvmsg`/`socketpair`/`shutdown`/`accept4`は`-ENOSYS`のままである。**

### 核（`kernel/src/socket.rs`）

- **listener**——名前（31バイト）と`listening`のフラグ。**待ち行列は持たない**——**accept前の接続を、接続の表から`listener`と`accepted`で引く。**
- **接続**——`open: [bool; 2]`（各側の端）と`rings: [Ring<1024>; 2]`（各側へ流れる輪）。**`Side`が輪の添字である**——`rings[side]`は「その側へ流れるバイト」。
- **待ち**——`Wait`が5から8になった（`SocketAcceptable` / `SocketReadable{conn, side}` / `SocketWritable{conn, side}`）。**`set_current_waiting`はIF=0の中で呼ぶ**（パイプと同じ）。
- **起こす**——`connect`→acceptor、書き→相手側の読み手、読み→相手側の書き手、端を閉じる→相手側の読み手と書き手。**全部`socket.rs`の中である。**
- **スロットを返す**——両端が閉じたら接続を空にする。listenerを閉じたら名前を返す。
- **計測**——15個（`init`がセッションの後に`socket:`の行で出す）。

### 動いてよいもの——実装前に書き、建ててから読んだ（実測。2026-09-20）

**定型の4つの形すべてを当てた。** **どれも設計どおりで、外れは無かった。**

| 先に書いた見込み | 実測 |
|---|---|
| **ページテーブルの項がイメージの伸びぶん+1される** | **+8**——**イメージが8ページ伸びた**（`0x475880`→`0x47d880`。`0x8000`）。**U/S監査のカーネル側が4247→4255、プロセスごとが2867→2875**（どちらも+8。定型1のとおり） |
| **`syscall-test`の高水位は動かない**（6つの枠に触れない） | **31,752のまま（±0。48%）。** **入口は`dispatch`の中、5つとも`#[inline(never)]`。** **`sys_write`の分岐で深さ0の小物が+16した**（`hello`／`bss-test`が2,786→2,802）が、`spawn`の経路（`syscall-test`）は動かない |
| **`.data`へ行く（`Locked`のholderが非零）／`.bss`へ行く（零の計測）。両方見る** | **`.data` +4,256**（`CONNECTIONS`4,208＋`LISTENERS`48。`nm`で`d`）。**`.bss` +0**——**15の計測（`AtomicU64`。零）は`.bss`に在る**（`nm`で`b`）**が、readelfの粒度では動かなかった**（整列の余りに120バイトが収まった）。**`.text` +23,312、`.rodata` +4,488** |

### (b3)で測ったものとの対応——ソケットの入口は`spawn`の経路に載っていない

**`ADR-0063`の(b3)で`load_user_program`が+1,968して`syscall-test`の高水位が+1,984した。** **今回は入口を`dispatch`の中に置き、`spawn_from_ring3`・`spawn`・`load_user_program`・`run_loaded_program`に触れなかったので、高水位が±0だった。** **見積もり（4.1の機序）が実測で当たった。**

### 検証（実測。2026-09-20）

**既定の`--socket-test`は判定10本すべて`true`で、`[ERROR]`0行、PASS（9.9秒。負荷の低い回）。** **破壊テスト8本は3回続けてすべて落ちた**（24回。落ちる判定は`docs/verification-coverage.md`の表）。**ホストテストは`socket::tests`3本・`ring::tests`3本を含めて381 passed。**

**計測の既定の値**（`--socket-test`の1回）——**listener 取った1返した1、`bind refused` 1、接続 created 5（同時に最大2）released 5、`connect refused` 2、`backlog full` 0、`accept`待ち4、読み手の待ち10（書きが起こした5）、書き手の待ち1（読みが起こした1）、閉じた相手への書き1、EOF 5。**

**`connect refused`が2である内訳を切り分けた**（一時のログを`connect`の入口に入れ、1回走らせて`"nobody"`が2回来ることを確かめ、revertした。`docs/coding-standards.md`の「一時的な破壊・変更の手順」）。**1つは起動時の`syscall-test`の検査66（無い名前への`connect`）、1つは台本の`sockc nobody`である。** **計測は大域なので両方が乗る。** **判定5は`connect refused >= 1`で見る。** **`pipe:`の計測は大域だが起動時に触られない**（`syscall-test`はパイプを使わない）**ので、`pipe-test`の判定は`== 7`で見てよい。**

### `SYS_SPAWN_DETACHED`をそのまま使う

**`init`が`/bin/sockd`を切り離して起動する**（`start_socket_server`）。**`concurrent-test`の`tickera`と同じ形で、Ring 3へ入るまで待ってハンドルを返し、セッションの完了で回収する。** **これは(b2)で作った入口をそのまま使っている**——**ソケットのために足したものは無い。**

### 限界（契機つき。8つ）

1. **接続は同時に2つ、listenerは1本。** 3つ目の`connect`は`-EAGAIN`（`backlog full`）。**見直すきっかけ**——**Seinasに2本目以上のクライアントを繋ぐとき**（ユーザーウィンドウの拡張と同じ。持ち越しに立てた）。
2. **名前はカーネルの表で、ファイルシステムに現れない**（`ls`に出ず、`unlink`で消えない）。**抽象名（先頭NUL）は`-EINVAL`。** **見直すきっかけ**——**Linux向けのクライアントを動かすとき**（目標にしていない）。
3. **`accept`は相手の名前を返さない**（`addr`はNULLだけ、それ以外は`-EINVAL`）。**見直すきっかけ**——**サーバーがクライアントの名前を要る形になったとき。**
4. **双方が読まずに書き続けると互いに待つ**（Linuxも同じ。`big`が1,536 ≤ 2×輪に収めてあるのはこのため）。**見直すきっかけ**——**利用者が輪の2倍を超える往復を1回のwriteでするとき**（回避は利用者の側）。
5. **1つのタスクが待つ理由を2つ同時に持てない。** **見直すきっかけ**——**画面と入力の受け渡しの段の設計時**（Seinasが入力とソケットの両方を待つとき。持ち越しに立てた。運用者の指示Q7）。
6. **カーネルで待っている子にCtrl+Cは届かない**（(b3)の限界の再掲）。**`sockd`は`quit`で終える入口を持つ。** **見直すきっかけ**——**`-EINTR`を作る段階**（`ADR-0063`の(b3)の限界）。
7. **`socket-test`の台本では`|`を使えない**（切り離して起動する1本をサーバーが使っている）。**見直すきっかけ**——**2本目のRing 3を増やす段階。**
8. **fdの運搬（`SCM_RIGHTS`）・`mmap`・`shutdown`・`sendmsg`は無い。** **見直すきっかけ**——**次の段階（共有メモリとfdの受け渡し）。** **そこで`load_user_program`の枠を先に読む**（`docs/deferred-decisions.md`の遠征スタックの行。余裕1,016バイト）。

## Alternatives Considered

- **先にソケットへ行き、パイプを作らない。** **却下した**（`ADR-0063`で決めた）——**同時実行が壊れているのか`accept`が壊れているのかを、同じ段階で切り分けることになる。** **パイプで核（輪・待ち・EOF・EPIPE）を先に確かめたので、この段階は名前と`accept`と双方向だけを足せた。**
- **`Ring`を切り出さず、ソケットに輪を書き直す。** **却下した**（決定6）——**`ADR-0063`が「共通の核」と決めたので、共通にするのが本体である。** **書き直すと、パイプの輪の破壊テスト（`pipe-write-ignores-full`）とソケットの輪が別の実装になり、片方だけが直る形になる。**
- **名前をファイルシステムのinodeにする**（Linuxの`AF_UNIX`は`sun_path`のパスにソケットのinodeを作る）。**却下した**（決定3）——**ext2は読み取りだけで、ソケットのinodeを作る関数が無い。** **Waylandは絶対パスの端点も認めるが、既定は名前（`wayland-0`）で、カーネルの表で足りる。** **「ファイルシステムに現れる名前」は、書けるファイルシステムを作る段階の話である。**
- **`poll`／`epoll`を足す。** **却下した**（決定7）——**Waylandは待ち方を要求しない**（`ch04`に`poll`の語が無い。`docs/wayland-inventory.md`）。**1つのfdを待つ形（`accept`／`read`）で足りる。** **「待つ理由を2つ同時に持つ形」は、画面と入力の受け渡しの段階で決める**（持ち越し）。
- **`accept`が相手の名前を返す。** **却下した**（この段階では）——**`addr`にNULL以外を渡すと`-EINVAL`。** **Waylandのサーバーはクライアントの名前を要求しない**（接続は無名でよい）。**要るようになってから足す。**
- **輪を256バイト（パイプと同じ）にする。** **却下した**（決定4）——**Waylandの初手（`wl_registry.global`の束）が約1 KiBで、256だと双方が書いて互いに待つ形が近い。** **1,024なら初手を相手が読む前に書き切れる。**

## Consequences

**得たもの。** **名前で繋ぐ双方向のストリームが動き、`accept`が待ち、EOFとEPIPEが出る。** **Waylandの接続の形（`docs/wayland-inventory.md`の「接続」）がカーネルに揃った。** **パイプの核をそのまま再利用したので、輪と待ちと閉じの規律は1つである。**

**失ったもの・先送り。** **fdの運搬（`SCM_RIGHTS`）・`mmap`・`shutdown`は無い**——**次の段階（共有メモリとfdの受け渡し）である。** **`accept`は相手の名前を返さない。** **接続は同時に2つ、listenerは1つ。**

**本番の利用者がまだ無い、初めての段階である**（上の節）。**原則との折り合いは「本番の形が仕様で先に分かっている場合の予行」であり、仕様の無い機構には当てはまらない。** **`sockd`/`sockc`はSeinasが来ても検査に残す。**

**待つ理由が5つから8つになった**（`SocketAcceptable`／`SocketReadable`／`SocketWritable`）。**「待つ理由を2つ同時に持つ形」は、この設計で初めて必要が見えた**——**Seinasが「入力とソケットの両方を待つ」形になるときで、`poll`ではなく`Wait`が2つの理由を持つ形が要る。** **持ち越しに立てた**（見直すきっかけは画面と入力の受け渡しの段の設計時）。

**遠征スタックはこの段階では動かない**（見積もりと実測）。**次にfdの受け渡しで`load_user_program`に「継承したfd」を足すなら、余裕1,016バイトに入らない**——**その段階の設計時にフレームを先に読む**（持ち越しの見直すきっかけを書き換えた）。
