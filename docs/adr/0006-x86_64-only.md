# 0006. 対象アーキテクチャを x86_64 のみに固定する

## Status
Accepted

## Date
2026-07-16

## Context
対象アーキテクチャの選択肢には x86_64 / ARM / RISC-V 等がある。
x86_64 + UEFI は QEMU での動作確認環境が最も成熟しており、資料・事例も豊富で、
学習リソースへのアクセスが容易。ARM / RISC-V は資料が相対的に薄く、初期段階で
選ぶ利得が小さい。

将来の移植性を見越して複数アーキテクチャ向けの抽象化を先回りで作ることは、
典型的な過剰設計の入口であり、細く長く・完走優先の方針に反する。

## Decision
対象アーキテクチャを x86_64 のみに固定する。他アーキテクチャへの移植・抽象化は
現段階では行わない。

## Alternatives Considered
- **最初からマルチアーキテクチャ対応の抽象化を設ける**: 過剰設計。実機 1 種すら
  完成していない段階で移植性を作り込むのは投資対効果が低い。却下。
- **ARM / RISC-V を対象にする**: 資料・QEMU 環境の成熟度で x86_64 に劣り、
  学習効率が下がる。却下。

## Consequences
- 資料・事例が最も豊富な環境で学習でき、詰まったときの解決情報が多い。
- コードは x86_64 前提に素直に書ける（アーキテクチャ抽象化の負担がない）。
- 将来他アーキテクチャへ移植する場合、アーキ依存部の切り出しが必要になる。
  ただしその判断はそのとき ADR で行えばよく、今から備える必要はない。
