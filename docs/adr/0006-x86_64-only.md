# 0006. 対象アーキテクチャをx86_64のみに固定する

## Status
Accepted

## Date
2026-07-16

## Context
対象アーキテクチャの選択肢にはx86_64 / ARM / RISC-V等がある。
x86_64 + UEFIはQEMUでの動作確認環境が最も成熟しており、資料・事例も豊富で、学習リソースへのアクセスが容易。
ARM / RISC-Vは資料が相対的に薄く、初期段階で選ぶ利得が小さい。

将来の移植性を見越して複数アーキテクチャ向けの抽象化を先回りで作ることは、典型的な過剰設計の入口であり、細く長く・完走優先の方針に反する。

## Decision
対象アーキテクチャをx86_64のみに固定する。
他アーキテクチャへの移植・抽象化は現段階では行わない。

## Alternatives Considered
- **最初からマルチアーキテクチャ対応の抽象化を設ける**: 過剰設計。実機1種すら完成していない段階で移植性を作り込むのは投資対効果が低い。却下。
- **ARM / RISC-Vを対象にする**: 資料・QEMU環境の成熟度でx86_64に劣り、学習効率が下がる。却下。

## Consequences
- 資料・事例が最も豊富な環境で学習でき、詰まったときの解決情報が多い。
- コードはx86_64前提に素直に書ける（アーキテクチャ抽象化の負担がない）。
- 将来他アーキテクチャへ移植する場合、アーキ依存部の切り出しが必要になる。ただしその判断はそのときADRで行えばよく、今から備える必要はない。
