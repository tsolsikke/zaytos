# 0051. 書き込みは装置まで届き、再起動をまたいで残る

## Status
Accepted

## Date
2026-08-30

## Context

`ADR-0037`のDecision 1は「`:w`の行き先はRAM複製までとする。再起動で消える」だった。**その主張はP段で偽になった。**

**変わったのは3つである。**

- **`ADR-0034`の2つ目のAddendumの発火条件（`disk0.img`を起動間で持ち越す形へ動くとき）が発火した。** **P-eで埋め込みの像を外し、像の出どころを装置1本にした。**
- **`ADR-0036`（I/Oの待ちはBKLを解いて眠る）が本番の利用者を得た。** **`close`から呼ぶ書き戻しは、発行してからBKLを解き、待ち終えてから取り直す。** **`ADR-0037`が「却下」と書いた理由（BKL保持のまま待てない・装置ハンドルが起動シーケンスの中にしか無い）は、どちらも解消した。**
- **装置のハンドルに家ができた。** **`virtio`が置き場と占有の旗を持ち、シェルの文脈から借りられる。**

**`ADR-0037`を丸ごとSupersededにはしない。** **Decision 2（`open`の受理を2形に狭める）・Decision 3（向きの取り違えは両方向とも`-EBADF`）・Decision 4（システムコールは増えない）と、`O_CREAT`のAddendumは、いまも真である。** **実測で、カーネルのコードから11箇所が`ADR-0037`のそれらを指している**（2026-08-30）。**Supersededにすると、生きた決定を指す参照が死んだ文書を指す。**

**代わりに、`ADR-0037`のDecision 1を打ち消し線にして、ここを指す。** **`ADR-0037`は既に同じ形を持っている**——**「決めないこと」の`O_CREAT`の行が、打ち消し線と「下のAddendumにある」の組で書かれている**（「行は消さず状態を書き換える」）。**同じ作法を、Decisionの側へも使う。**

## Decision

1. **書き込みは装置まで届く。** **書きで開いたファイルを`close`したとき、像を装置へ書き戻す。** **主張は「ファイルに書けた」から「ファイルに書けて、次の起動でも在る」へ変わる。**

2. **保証するのは装置の中身までである。** **書き戻しが終わった時点で、装置の上の像は書いた中身を持つ。** **その像が保たれる限り、次の起動で読み戻せる。** **装置の中身を外から作り直した場合は保証しない**——**それはOSの外の話である。**

3. **書き戻しの粒度は全像である。** **2MiBを1回の要求で書く**（`ADR-0033`のAddendum）。**刻まない。** **実測で決めた**——**`:wq`の待ちのうち、書き戻しは0.7%（11.6Mサイクル）だった**（2026-08-30）。**支配項は画面の描き直しで92.7%であり、そちらを直した**（PERF-h）。**刻む判断は`deferred-decisions`へ落とし、契機を2つ書いた**（フラッシュが実測で支配項になったとき／像が大きくなったとき）。

4. **装置が据わっていなければ、書き戻さずに成功を返す。** **起動シーケンスの中で走るプログラムは、装置が据わる前にファイルを閉じる**——**そこで失敗させると起動が止まる**（実測）。**この形は据え忘れも黙らせる**ので、**塞ぎ方を別に持つ**（下の「決定ではないこと」）。

5. **装置が使用中なら`-EBUSY`を返す。** **占有の旗で守る。** **待たない**——**待つ形にすると、誰が誰を待つのかを決める必要が出る。利用者が1人のうちは断るほうが単純である。**

## 決定ではないこと（検査の枠の都合）

**ここはOSの決定ではない。** **`ADR-0048`の基準で言えば、下は「検査の都合」であって「プロジェクトの知識」ではない。** **本体は置かず、所在だけを書く。**

- **手で起こすときは像を持ち越し、検査では毎回作り直す。** **旗で切り替える。** **本体は`docs/roadmap.md`のP-cの締めに在る**（限界の4つ目）。
- **Decision 4（据わっていなければ黙って成功する）の塞ぎ方**——**据えない破壊と、保存が装置へ届いたことを見る判定である。** **本体は`docs/verification-coverage.md`の会計行（P-c-1の項）に在る。**
- **書き戻した像に`e2fsck`を掛けていること。** **構造を壊さないことは、中身が違うことと別に主張する必要がある。** **本体は`docs/verification-coverage.md`の会計行（P-c-3の項）に在る。**

## 決めないこと

- **書くたびに書き戻すか**——**いまは`close`のときだけである。** **`write`のたびに書き戻す形は、費用が実測で問題になるまで採らない。**
- **刻むか**（Decision 3の続き。`deferred-decisions`に行が在る）
- **`fsync`**——**使う者がいない。** **`close`で書き戻すので、いまは同じことである。**
- **複数の装置**——**1台しか無い。**

## Alternatives Considered

- **保証を「旗を付けたとき」と書く——却下。** **旗は`xtask`のものであって、実機には無い。** **実機で起動すれば、持ち越しは無条件で真である。** **旗の話を決定へ混ぜると、実機で何が真かが言えなくなる**（`ADR-0048`の基準）。
- **`ADR-0037`を丸ごとSupersededにする——却下。** **Decision 2/3/4と`O_CREAT`のAddendumが生きており、コードから11箇所が指している**（実測）。**死んだ文書を指す参照を作らない。**
- **Addendumで足す——却下。** **Addendumは「決定は変わらないが、条件や範囲が動いた」ときの形である。** **今回はDecision 1そのものが偽になった。**
- **`write`のたびに書き戻す——却下。** **費用の根拠が無い。** **`close`で足りることを実測で確かめてある**（2度目の起動で読み戻せる）。
- **書き戻しを刻む——却下**（Decision 3。実測で0.7%）。
- **装置が使用中なら待つ——却下**（Decision 5）。

## Consequences

- **「書いたのに消えた」を`ADR-0037`が引き受けていたが、その引き受けが要らなくなる。** **代わりに「旗を付けないと消える」を、このADRが引き受ける。**
- **起動時の演習が前提を失った。** **`/data/writable`の追記の演習は、`build.rs`が蒔いた100バイトを前提にしていたが、利用者が`zi`であのファイルを編集して保存すると、次の起動でその前提が消える。** **実際に踏み、止めずに演習を飛ばす形へ直した。** **飛ばしても黙らない**——**建てたままの像で飛べば、起動ログの突き合わせが落ちる。**
- **能力を足すと既存の判定の前提が消える、という族ができた**（`troubleshooting`）。**これまでの3形は「判定を足したら前提を失った」で、これは向きが逆である。**
- **`ADR-0036`の形が本番で回る。** **これまで検算だけだった「発行→BKLを解く→待つ→取り直す」に、利用者の`close`が乗った。**
- **装置が状態を持つ。** **これまで装置は「読む先」でしかなく、起動のたびに同じ中身だった。** **これからは前の起動が書いたものを持つ**——**「起動が像に対して冪等である」が偽になる。**
