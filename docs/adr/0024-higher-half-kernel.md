# 0024. kernelをhigher-half（0xFFFFFFFF80000000）へ移す（ADR-0009をSupersede）

## Status
Accepted

## Date
2026-07-25

## Context

ADR-0009はkernelを低位固定アドレス`0x100000`へリンクすると決めた。
その却下理由は「higher-halfにするとM2-0c/M2-cの境界がにじむ」という開発プロセス上の都合であり、higher-half自体の技術的欠陥ではないと明記していた（ADR-0009 Alternatives Considered）。
またADR-0009はConsequencesで「ユーザー/カーネル権限分離の実運用（M5）で必要になった段階でhigher-halfを再検討する」と申し送っていた。

M5が進み、その段階に達した。
ADR-0022はM5-fを「int 0x80システムコール」と「プロセス別アドレス空間」に分け、後者をhigher-half B完了後の独立マイルストーンへ切り出した。
プロセス別アドレス空間は「下位半分=ユーザー、上位半分=カーネル」の分割に依存する。
現在kernelは`PML4[0]`（下位半分）に恒等マッピングで居るため、下位を差し替えられない（`deferred-decisions.md`のM5-eユーザー空間暫定配置）。
したがってkernelを上位半分へ移し恒等を外すことが、プロセス別アドレス空間の前提になる。

## Decision

kernelをhigher-half（リンクベース`0xFFFFFFFF80000000`、`code-model=kernel`）へ移す。
ADR-0009をSupersedeする。

移行はADR-0021のAとBに分け、Bをさらに段階分割した。
AとBの全体像はADR-0021とそのAddendumに、**Bの実装機構（トランポリン・静的初期テーブル・段階分割・切替前検査の非対称）はADR-0021のB Addendumに置く。**
本ADRは「低位固定リンクという決定そのものを覆した」ことと、その帰結（アドレス空間レイアウトとSMP非閉塞）を記録する。

### 仮想アドレスレイアウト（B-2a完了時点のスナップショット）

再リンク後のkernelは`0xFFFFFFFF80000000 + 0x100000`（VMA）で走り、物理`0x100000`（LMA）へロードされる。
PML4のインデックス割り当ては次のとおり。**これはB-2a完了時点のスナップショットで、恒等（`PML4[0]`）がまだ残っている状態である**（`architecture.md`のスナップショットが時点を明示するのと同じ扱い）。

| PML4インデックス | 仮想ベース | 用途 |
|---|---|---|
| `0` | `0x0` | 恒等（松葉杖。B-2bで除去する残り） |
| `1` | `0x0000_0080_0000_0000` | M5-eユーザーページの暫定サブツリー（B-2b後に低位へ広げる） |
| `256` | `0xFFFF_8000_0000_0000` | direct physical map（ADR-0021） |
| `257..510` | | 空き（SMPのper-CPU用に温存。下記） |
| `511` | `0xFFFF_FFFF_8000_0000` | kernelイメージ（`code-model=kernel`が要求する上位2GiB） |

B-2b後の変化: 恒等（`PML4[0]`）を外すと`PML4[0]`が空く。これにより、M5-e暫定配置（`PML4[1]`、仮想512 GiB）に置いているユーザーページを、プロセス別アドレス空間（M5-f-3、ADR-0022）で通常の低位（下位半分の数MiB付近）へ広げられるようになる。ユーザー空間の低位化そのものはM5-f-3の仕事でB-2bの範囲外だが、B-2bが何を可能にするかとしてここに記録する。

### SMP非閉塞（ADR-0023との接続）

higher-halfの移行で、SMP（ADR-0023でBKLファーストと決定）の実装を閉塞しないことを数字で担保する。

- `PML4[257..510]`を空きのまま温存する。BKLのper-CPUデータ（コアごとのスタック・TSS・per-CPUアクセサの置き場所）はここへ置く。`PML4[256]`（direct map）と`PML4[511]`（kernel）の間の連続領域で、用途が確定するまで触らない。
- GSベースを温存する（現在GS読み書きの初期化をしていないので、per-CPUのGSベース割り当てをBKL着手時に入れられる）。

ADR-0023 Consequencesが「B-2着手時に非閉塞をBKLの根拠へ更新する」とした申し送りを、本ADRのこの節で果たす。
per-CPUデータの実際の置き場所は、BKL本体（higher-half B完了後）の着手時に確定する。

### EFER.NXEとNXは別段

direct mapもkernelイメージも本来NX（実行不可/データ不可）で細分化すべきだが、`EFER.NXE`を有効化していないためNXビット（bit 63）を立てると予約ビット違反のページフォルトになる（ADR-0018 / ADR-0021）。
NXEの有効化とNXの付与は、higher-half B完了後の独立段として扱う（`deferred-decisions.md`）。
本移行ではNXを立てない。

## Alternatives Considered

- **低位固定リンクのまま、プロセス別アドレス空間を別の方法で実現する**: 下位半分にkernelが居たままでは、プロセスごとに下位を差し替える標準的な形（下位=ユーザー、上位=共有カーネル）が取れない。無理に迂回するとx86-64の慣習から外れ、将来の全機能がその歪みを引きずる。却下。ADR-0009が却下理由を「技術的必然ではない」と明記していたことが、この再検討を素直にした。
- **higher-half化を一括で行う**: 再リンクが全低位参照を一斉に無効化するため、失敗時の切り分け軸が一度に増える。ADR-0021のAddendumとB段階分割で、恒等除去（最もリスクの高い部分）をB-2bに隔離した。却下。

## Consequences

- kernelは上位半分（`PML4[511]`）で走り、下位半分が空く。プロセス別アドレス空間（下位を差し替え上位を共有）の前提が整う。実際の着手はADR-0022のとおりhigher-half B完了後の独立マイルストーン。
- 恒等（`PML4[0]`）はB-2aではまだ残っている。B-2bで低位ポインタ（boot_info・ヒープ・mmapバッファ・恒等前提の検証ヘルパ）を高位化してから外す。恒等除去は本移行の「残り」である。
- ADR-0009はSupersededになる。低位固定リンクを前提にした記述（フレームアロケータのシンボル変換、必須マッピング検証の恒等前提など）は、移行で変換を挟む形へ移った（`deferred-decisions.md`）。
- 移行で見つかった安全性の非対称を記録する。M2-d/A-1のCR3切替は「切替後も必須領域がアクセス可能か」を物理範囲のメンバシップで検査するが、A-1/B-1が確立した「新テーブルを独立walkerで実際に引く」検査は持たない。そのため新テーブルでの高位マッピングの欠落を検出せずに切り替えて#PFで死ぬ（B-2a-5の破壊feature `highhalf-no-kernel-high-in-live-table`で実証）。恒等を外す（B-2b）とkernelを覆うのが高位マッピングだけになるため、walkベース検査の価値が上がる。M2-d/A-1の切替前検査をwalkベースへ強化するかをB-2bの設計調査に含める。
