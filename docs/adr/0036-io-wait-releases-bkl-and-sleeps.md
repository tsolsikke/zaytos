# 0036. I/O待ちはBKLを解いて眠る

## Status
Accepted

## Date
2026-08-18

## Context

S13-eのflushはシェルの文脈（BKL保持・IF=1の後段）から出る書き込みで、完了を割り込みで待つ。`CLAUDE.md`§6が「BKLを保持したまま眠らない・待たない」と定めており、S13でこの前提を設計し直すと予告している。d-1で割り込みは届くようになったが、待ちはまだポーリングである。

実測:

- **BKL保持中はIF=0である**（`kernel/src/bkl.rs`のacquireがcliを先に置き、エラー文言も「the BKL is held with IF=0, so no interrupt can re-enter on the same core」と明記）
- **現状の切替はすべてIF=0の文脈で走る**——`on_yield`は`int`ゲート（`yield_now`）経由、`on_timer_tick`は割り込みゲート経由で、どちらも`irq_entry`の中（ゲートがIFを0にした後）である。**IF=1の任意点からの切替は新種である**
- ガードのDropは「enter時にIF=1だった文脈へ戻すだけ」で、IF=0だったら復元しない（`EntryInterruptGuard`／`InterruptGuard`）
- TaskStateにBlockedは在るが、I/O待ちで眠り完了通知で起きる経路・待ち行列・BKLのacquireが眠る形は無い（棚卸しの実測、変わらず）

## Decision

**I/O待ちに入るタスクは、BKLを解いてから眠る。**

- 出す側: (1)要求を発行 (2)完了フラグを検査 (3)未完了ならBlockedにしてBKLを解き、譲る (4)起きたらBKLを取り直して続きへ
- 受ける側: IRQハンドラ（BKLを取る入口）が完了フラグを立て、待っているタスクをReadyへ戻す
- 眠るのはBKLを解いた後だけ。**BKLを保持したまま眠らない**（§6）

## IFの規律（ADR-0035が要求した節）

取り逃しの窓の閉じが成り立つ条件を、IFの状態で確かめる。

- **BKL保持中のIF: 0である**（実測）。フラグの検査とBlockedへの遷移をBKL保持下で行えば、その区間に同じコアのIRQは入らない——完了通知はハンドラが立てるが、ハンドラはこの区間には走れない。「検査したら未完了と見てから眠るまでの間に完了が来て取り逃す」窓が、この区間では開かない
- **順序は「Blockedを書く→BKLを解く→譲る」**。BKLを解くとIF=1になりIRQが入りうる。解いた瞬間に完了IRQが来てReadyへ戻され、その後でBlockedを書くと、Readyを上書きして永久に眠る。**Blockedの書き込みをBKL保持下（IF=0）に入れる**ことで、ハンドラのReady化（これもBKLを取る）は必ずBlockedの後になる
- **「解いてから切替が終わるまで」の区間のIF: 0を保つ**。ここが新種の危険である——現状の切替はIF=0の文脈でしか走っておらず、IF=1の任意点で切替に入ると、状態の保存が途中の文脈にハンドラが乗りうる。**契約: Blockedを書いてから切替が終わるまでIF=0を保ち、`sti`は着地点（idleのhlt等、割り込みを受けてよい場所）で行う。** これなら起こしのIRQは切替の完了後にしか処理されず、lost-wakeupの閉じ（Blockedが先）もそのまま成り立つ。**実測がこの推奨と食い違ったら実測に従い理由を書く**が、既存の切替がIF=0で走り、ガードのDropがIF=0では復元しないことから、この契約は既存の構造と整合する
- **起こしが別コアのIRQ経由になる条件**: virtioのINTxは物理モードで宛先BSP（d-1の読み戻しで確認済み）。完了IRQはBSPに届く。BSP 1コアで眠ると起こすIRQも同じBSPに来る——**眠っているコアがIRQを受けられる形（IF=1のhlt）で着地する必要がある**。これは`run_timer_loop`の既存の待ちと同じ形である

**眠りをhltで作るかスケジューラの譲りで作るかは実装の最初の判断とする**（ADRでは縛らない）。**どちらを選んでも上のIFの契約が成り立つ**——hltなら着地点でIF=1にして受ける、譲りなら次タスクの再開がIF=0の切替を経て着地点でIF=1になる。

## 決めないこと

- **flush（書き込み）の単位と経路**——S13-e
- **眠りをhltで作るかスケジューラの譲りで作るか**——d-2の実装時
- **複数タスクが同じI/Oを待つ形**——利用者が1つの間は要らない（待ち行列がキーごとに要るのはそのとき）

## Alternatives Considered

**ポーリングのまま（BKL保持で回す）——却下。** §6が禁じる。シェルの文脈で数千万スピン回すと、その間BKLを離さないので他コアも他タスクも進めない。d-1まではIF=0の起動文脈だったので許されたが、post-bootの利用者では通らない。

**完了フラグだけ見てBlockedを使わない（スピンをyieldに変える）——却下。** 譲ってもReadyのままならスケジューラが選び続け、ポーリングと同じになる。Blockedにして「起こされるまで選ばれない」を作るのが要点である。

## Consequences

- §6の「BKLを保持したまま眠らない」を、初めて実際に守る利用者ができる
- 取り逃しの窓は、Blockedの書き込みをBKL保持下（IF=0）に入れ、切替の完了までIF=0を保つことで閉じる
- 代償: BSP 1コアで眠るなら、起こすIRQを受けるためにhlt（IF=1）が要る。眠り方の選択がd-2の実装の最初の判断になる

再訪条件: **複数のI/O利用者が同時に眠る形になったとき**（待ち行列がキーごとに要る）、**またはSMPで眠るコアと起こすコアが分かれる形を扱うとき**。
