# 0031. 開発エージェント向けの設定ファイルを公開する

## Status

Accepted

## Date

2026-08-14

## Context

このリポジトリの開発では、コーディングを補助するエージェントを使っている。
その運用ルールを書いた設定ファイル群は**追跡外に置いてきた**。
除外は`.gitignore`ではなく`.git/info/exclude`で行い、公開する成果物（コミットメッセージ・
README・docs・コード内コメント）には補助ツールの関与を示す記述を含めない、という方針である。
目的は、**リポジトリを実装内容そのもので評価できる状態に保つこと**だった。

**その方針が2つの費用を出している。どちらも実測できる。**

**1つ目。公開文書が既に壊れている。**
追跡下の**6ファイル**が、追跡外のファイルの節番号を指している。
うち**4件はコード内のコメント**（`kernel/src/apic.rs`・`kernel/src/bkl.rs`・
`kernel/src/smp.rs`・`xtask/src/main.rs`）で、いずれも
**「上限のない待機ループを書かない」の根拠として同じ節を指している。**
残る2件は`docs/verification-coverage.md`と`docs/deferred-decisions.md`である。
**公開リポジトリを読んだ人は、その先を開けない。**
同じ形が補助スクリプトにもあり、**3ファイル4箇所**が追跡外の`tools/docstyle.py`を指している。
**「公開文書は追跡外のファイルを参照しない」という規則自体は書いてあり、守られていなかった。**

**2つ目。追跡外に置いてある内容の半分近くは、補助ツールに固有ではない。**
実測で**472行15節**のうち、後ろの3節（成果物の記述方針・コミットの運用・
シェルコマンドの制約）が**216行、全体の45.8%**を占める。
**いずれも作業者の振る舞いの規約であって、人間が読んでも同じように効く。**
実際、そこにあった規約のうち5件は公開側の`docs/coding-standards.md`へそのまま移せた。

**この2つは同じ根から出ている**——**公開しないと決めた側に、公開する側が必要とするものが
混ざっている。** 参照を落とすか、内容を移すか、公開するかのいずれかが要る。

## Decision

**開発エージェント向けの設定ファイルを、公開できる水準へ整えた上でリポジトリへ追加する。**

- **ファイルごとに公開可否を判定する。** 判定の基準は、環境固有の絶対パス・個人を
  特定しうる情報・他者の著作物を含まないことである
- **公開しないものは`.git/info/exclude`に残す。** ただし**残す理由が変わる**（Consequences）
- **公開した後は、公開文書からこれらのファイルを参照してよい。** 参照は節番号ではなく
  名前で行う（節番号は編集で動く）

**この決定は、公開成果物にAIの関与を示す記述を含めないという従来の方針の変更である。**
**変更するのは「AI固有のファイルを追跡下に置かない」という部分であり、
「コミットメッセージやdocsを、実装内容そのもので読める状態に保つ」という目的は変わらない。**

## Alternatives Considered

**案2（公開する）を採った。以下は却下した2案である。**

- **案1 公開しない（現状維持）。**
  **却下。** Contextの費用が残る。
  参照を落とせば公開文書からは壊れが消えるが、**根拠を示せない記述が6箇所残る**——
  「上限のない待機ループを書かない」が**なぜそう決まっているのかを、公開側だけでは辿れない。**
  規則の本体を公開側へ移すなら、それは案3である。
- **案3 規約を公開側へ移し、追跡外のファイルを薄くする。**
  **却下。ただし部分的には実行した**——コード規約5件（学習目的の簡略化は行わない /
  命名は明確に / エラー処理を省略しない / マジックナンバーは名前付き定数にする /
  振る舞いを変えない変更は単独のコミットにする）は`docs/coding-standards.md`へ移してある。
  **それは公開の前提としてであって、案3の採用としてではない。**
  **区別は「移した後に何が残るか」で付く。** 案3は残りを追跡外に置き続けるので、
  **残った部分を指す参照は依然として壊れる。**
  そして移せるのは**人間にも効く規約**だけである——**エージェントの運用そのもの**
  （セッション開始時に読む文書、報告の形式、人間のレビューへ渡す条件）は移し先が無い。
  **薄くしても消えない。**

## ADRを書く条件に当てた結果

- **条件(1) 複数の有力案から一つを選ぶ——当たる。** 上の3案である。
- **条件(2) 後から変更すると作り直しが生じる——当たる。**
  **公開は取り消せない。** 追加した内容は履歴に残り、後から方針を戻しても、
  削除できるのは現在の状態だけである。
- **条件(4) 将来の保守者が単純化すると壊す——当たらない。**
  この決定は機構ではないので、単純化の対象にならない。

## Consequences

- **`.claude/settings.local.json`は公開しない。**
  **許可の記述が作業ディレクトリの絶対パスを含み、そのパスにはユーザー名が入っている。**
  そして**そこへ移った後の任意のコマンドを許可する形**になっている。
  前者は個人の環境そのもので、後者は他の環境では意味が変わる。
  **理由の1つ目がこの文書にも掛かるので、パスの実物はここに書かない。**
  `.git/info/exclude`に残す。
- **`.git/info/exclude`に残すものの理由が変わる。**
  以前の理由は「除外設定自体が痕跡になるため`.gitignore`に書かない」だったが、
  **公開後は「個人の環境設定を、公開リポジトリの設定に混ぜない」という普通の理由になる。**
  **`.gitignore`ではなく`.git/info/exclude`を使い続ける点は変わらない。**
- **`git add`が検査の対象を変える。**
  Markdownの文体検査は`git ls-files "*.md"`で対象を集めており、ディレクトリで絞っていない。
  **追跡下へ入れた時点で、そのファイルが検査の対象になる。**
  手順は`docs/coding-standards.md`の
  「操作それ自体が、検査の対象を変えることがある」にある。
- **公開文書がこれらのファイルを参照できるようになる。**
  既存の壊れた参照（6箇所と4箇所）は、参照の形を決めてから直す。
- **公開する内容には、規律が破られた回数の記録が含まれる。残す。**
  「破られた回数を数え続けるしかない」と書いた箇所は、**数えた結果が無ければ主張にならない。**
- **追跡下のファイルが増えるぶん、文体と参照の検査が掛かる範囲も増える。**
  以後、これらのファイルの編集は`cargo xtask check`の対象である。

## Addendum（2026-08-14、公開の作業が済んだ）

**`Context`が挙げた2つの費用は、どちらも解消した。** 決定そのものは変わっていない。

- **公開文書からの壊れた参照。** 節番号で指していた5ファイルを名前での参照へ変え
  （理由は`docs/coding-standards.md`の「番号で指すか名前で指すか」にある）、
  **設定ファイル自身を追跡下へ入れたので、指した先が実在する。**
- **`tools/docstyle.py`への参照。** 公開したので実在する。
  **なお`Context`のこの数（3ファイル4箇所）は、それを書いた`Context`自身を数えていない。**
  書いた時点で4ファイル5箇所である。**この形は`docs/coding-standards.md`の
  「規則を書く文書自身が、その規則の対象になることがある」へ3件目として記録した。**

**検査の対象が実際に増えた。** 追跡下の`.md`は41から43へ、`docstyle.py`の対象は40から42へ
増えた。**増えた状態で`cargo xtask check --full`は134項目すべて通過している。**

**`.git/info/exclude`に残っているのは`.claude/`の1行だけである。**

**監査の想定が2つ変わった。** どちらも、追跡下に入ったことで検査の入力が変わったために出た。

- **`CLAUDE.md`の監査の手順が例として置いているキリル文字が、監査の対象になった。**
  同じ節に「追跡下にあるのはその1つで、2つ以上出たら混入である」と書いた。
  **これが上の族の4件目である。**
- **想定するUnicodeブロックの一覧が、実測と合っていなかった。**
  `×`・`±`・`µ`・`⟹`は**以前から追跡下にあった**が、一覧が挙げるどのブロックにも入って
  いなかった。**混入ではなく、一覧のほうが実測と合っていない。** 一覧を実測へ合わせた。
  **公開しなくても偽だったものが、対象を数え直したときに出た。**
