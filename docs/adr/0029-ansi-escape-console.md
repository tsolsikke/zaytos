# 0029. 画面制御はANSIエスケープシーケンスで行い、専用のシステムコールを作らない

## Status
Accepted

## Date
2026-08-13

## Context

現在のカーネルコンソールは、受け取ったバイト列をそのまま字として描く。
改行と後退は解釈するが、**位置の指定・消去・色は解釈しない。**

ユーザープログラムが画面を制御したくなる場面が見えてきた。
直接の動機は`vision.md`の`zi`（vi風のエディタ）で、あれは**画面の任意の位置へ書く必要がある。**

方式を決めないまま`zi`の段に入ると、**「位置を指定するシステムコールを1つ足す」が最も近道に見える。**
その形は`ADR-0001`が避けると決めた方向（特定の利用形態に依存するAPIをカーネルへ置く）に当たるので、
**要求が出る前に決めておく。**

## Decision

**画面制御はANSIエスケープシーケンスで行う。** ユーザープログラムは`write`でバイト列を送り、
**カーネルコンソールがその中のエスケープシーケンスを解釈する。**

**専用のシステムコールを作らない。** `move_cursor(x, y)`・`clear_screen()`・`set_color()`のような
入口は置かない。

**解釈するもの（最小の範囲の案。着手時に確定する）**——カーソル移動（`CUP`）、
消去（`ED`・`EL`）、色と属性（`SGR`）、カーソルの表示と非表示。

**パーサは`common`に純粋ロジックとして置き、ホスト上で試験する。**
`keyboard::decode::Decoder`と同じ形である——**状態機械であって、装置に触らない。**

**着手の時期はこのADRでは決めない。** 動機は`zi`だが、`zi`は`vision.md`の構想であって段ではない。

## Alternatives Considered

- **画面制御用のシステムコールを足す**: 却下。**`ADR-0001`の「カーネルには汎用機構を置き、
  特定の利用形態に依存するAPIを置かない」に直接当たる。**
  `move_cursor(x, y)`はテキスト端末という形態を前提にしており、
  **その形態が変わった瞬間に、入口だけが残る。**
  そして**システムコールの数が増える**——`ADR-0020`の番号表に、Linuxに対応するものが無い番号を足すことになる。

- **フレームバッファをユーザーへ写像し、描画をユーザー側で行う**: 却下（**この段では**）。
  最も自由だが、**コンソールとの調停が要る**（誰が画面を持っているか）。
  `vision.md`のGUIはこの方向だが、**そこへ行く前に文字端末が要る。**

- **独自の制御コードを決める**: 却下。**「外から見える形はLinuxに合わせる」に反する。**
  ANSI（VT100由来）はUnixで最も標準的な形で、**既存の知識がそのまま使える。**
  独自にする利点は「実装が少し楽」だけで、**その差は解釈する範囲を絞れば消える。**

## Consequences

- **システムコールが1つも増えない。** `write`のバイト列として通る。
- **`vision.md`の「Linux互換のシステムコール」と噛み合う。** 端末制御をANSIで行うのはLinuxの形そのものである。
- **パーサをホスト上で試験できる。** 画面へ描かずに、状態機械の出力だけを突き合わせられる。
- **失うもの——エスケープシーケンスの解釈は状態を持つ。** 部分的に届いたシーケンス（`ESC [` まで来て次が来ない）を
  跨いで保つ必要があり、**コンソールが状態機械になる。** 現在の「バイトを字として描く」より複雑になる。
- **端末の設定（生モードと行モード）はこのADRの範囲外である。**
  あれは入力側の話で、`zi`が要求するものの別の1つである。**入力の配送を設計する段で決める。**

## Addendum（zi-b。解釈する範囲の確定）

「着手時に確定する」としていた解釈の範囲を、zi-bで確定した。

**解釈するのはCUP・ED・ELの3つである**（EDとELはパラメータ0/1/2の全部）。案にあった**SGRとカーソルの表示/非表示は入れなかった**——`zi`の再描画に要る最小はカーソル移動と消去で、色は要らない。**知らない終端は列ごと読み捨てる**（SGRを送っても`[31m`が画面へ化けて出ない——**無視は「化けない」を含む**）。知らない消去パラメータと3つ目以降のパラメータを持つ列も捨てる（間違って全消去するより、何もしないほうが安全側である）。

パーサは`common/src/ansi.rs`に置いた（本文の設計どおり。純粋な状態機械で、ホストテストが12本）。**解釈するのはコンソールの前景経路だけである**——カーネルのログの経路は通らない（ログの行にCSIは無く、通す理由が無い）。

**検証の所在は2層に分けた。** スコープの解釈（`0K`が"以後"であること等）は**ホストテスト**が固定する。**消去の挙動**（どのセルが背景へ戻るか）は**実機判定（`ansi-test`。起動シーケンスの実演で決定的）**が固定する——消去の真実はバックバッファ（描画層）にあり、ホストへ切り出すには描画の幾何を純粋関数へ分離する作り直しが要る。EL/EDの0・1・2すべてに実機判定がある。
