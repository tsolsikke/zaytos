# 0072. 割り込みの入口を、CPUの入口・機械の受け取りと完了・共通の振り分けの3つに分ける

## Status

Accepted（2026-09-28。運用者の決定）。実装は`ADR-0071`の手順2の9（機械固有を移す）で行う。入口を分ける所（下の8の9d）は振る舞いの形が変わるので、分けるコミットごとに差分を見せて承認を得てから入れる。

## Date

2026-09-28

## Context

いまの形（2026-09-28にコードで確かめた）。

- 入口は3つある。例外（`zaytos_exception_common`から`exception_entry`）、割り込み（`zaytos_irq_common`から`irq_entry`）、システムコール（`int 0x80`から`syscall_entry`）である。IDTの256の門は、例外216・割り込み39・システムコール1に分かれる（起動の確かめの行）。
- 割り込みの入口（`irq_entry`）が1つの関数の中で、IPIの探り（BKLを取らない）・BKL・yield・LAPICのスプリアス・LAPICのタイマ・ISAのIRQ番号で引く経路（8259のタイマ・キーボード・virtio-blk・8259のスプリアス）を順に判定し、EOIを送っている。そのため`arch`が共通の側を直に呼ぶ。依存の一覧（`arch`・`machine`から共通の側）の67項目のうち32項目を、割り込みの入口（`idt`と`interrupt_readiness`）が使っている（共通の側のカーネルのモジュールが26、commonの道具が6）。
- 番号が4種類混ざっている。ベクタ（IDTの添字）、ISAのIRQ番号（0〜15）、GSI（I/O APICの入力）、PCIの割り込み線の値（構成空間の0x3C）である。割り込み線の値を、MADTの上書きが無ければGSIとして使っている（持ち越しの「PCIのINTxを『割り込み線の値＝GSI』で配線している」。VirtualBoxではINTA#がI/O APICの20〜23番へ行く）。
- EOIの宛先（8259かLAPICか）は`irq`が決め、いつ送るかは`irq_entry`が決めている。
- TLBの整合は、BKLを取るときの世代の確かめが持つ（`ADR-0027`）。本番でIPIを送る所は無い。送るのは探りのfeatureの1か所だけである。
- 割り込みを止める命令（`cli`・`sti`・`sti; hlt`）はcommonの`arch/x86_64/cpu.rs`にあり、元の状態へ戻す決まりと入れ子の深さは共通の側の`InterruptGuard`が持つ。命令を直に呼ぶ所は、許可の表（`xtask`の`DIRECT_INTERRUPT_CONTROL_ALLOWLIST`）で限っている。

AArch64（`ADR-0070`）では、GICのIARを読むことが受け付けを兼ね、EOIはEOIRへ書く。RISC-VのPLICもclaimとcompleteの対である。x86の「ベクタで届く」形に合わせた入口のままでは、AArch64を足すときに作り直しになる。

第三者のレビュー（2026-09-28。運用者の追記）の観点も入れる。入口の責任を3つに分けること、番号の種類を型か名前で区別すること、例外・IPI・装置の割り込みを1つにまとめないこと、今の経路を新しい形で説明すること、`machine`に装置の一覧を持たせないこと、EOIを誰が出すかを、処理が無い・誤り・途中で戻る場合も含めて書くこと、割り込みを止める関数の置き場と保証を分けて書くこと、である。

## Decision

### 1. 責任を3つに分ける

- **A `arch`（CPUの入口）**: スタブ、レジスタの保存と復帰、DFとスタックの境界の確かめ、IST、門の種類（入るときIF=0）。入口の種類を分ける——CPUの例外（原因と、割り込まれた文脈の特権）、ソフトの入口（システムコール・yield）、外からの割り込み（それ以外）である。共通の側へは、機械に依らない形の情報（例外の種類、ユーザーから来たか、フォルトのアドレス、書き込みか、など）と、割り込まれた文脈（切り替えに使う）を渡す。出口の動き（元へ戻る、別のタスクへ切り替える、遠征を畳む）を実行する。
- **B `machine`（割り込みコントローラ・タイマ・IPI）**: 外からの割り込みを受け取り、完了させる（下の2）。源ごとの許可と禁止、源と経路の設定（8259の採番、I/O APICの経路、将来のGIC）、タイマの設定と較正、IPIを送る所とAPを起こす所。装置の割り込みを、ハードウェアの記述から解決する（ISAのIRQはMADTの上書きで、PCIのINTxはACPIの表で引く）。**装置の一覧を持たない**——ドライバが「この装置の割り込み」をBに解決させ、受け取った源の番号で処理を登録する。
- **C 共通の側とドライバ**: 割り込みの方針（BKLを取るか、数える、振り分ける）、登録した処理の呼び出し、装置の処理（PS/2のデータを読む、virtioのISRを読んで源を下ろす）、タスクを起こす、スケジューラの判断（切り替える、中断で畳む）。EOIを知らない。

外からの割り込みの流れは、Aの入口 → Cの1つの入口関数 → Bが受け取る → Cが方針を決め、登録した処理を呼ぶ → Bが完了させる → Cが出口の動きを決めてAへ返す → Aが実行する、である。

**目標**: 割り込みの入口から共通の側への依存を、入口関数4つほど（外からの割り込み・例外・システムコール・yield）にする（手順2の9の終わり）。

### 2. Bは「受け取る」と「完了させる」の対を持つ（運用者の決定）

- **受け取る（claim）**: このCPUに届いたものを1つ受け取り、源の番号かスプリアスを返す。コントローラによっては受け付けを兼ねる（GICのIAR、PLICのclaim）。BKLなしで呼べる。
- **完了させる（complete）**: 受け取ったもの（スプリアスを除く）に、ちょうど1回呼ぶ。
- x86では、受け取るはベクタから源を引くだけで、完了させるはEOI（8259かLAPICか）である。

### 3. 番号の種類を型で分ける

- **ベクタ**（x86のIDTの添字）: `arch`と`machine/pc`の中だけで使う。共通の側に出さない。
- **ISAのIRQ番号・GSI・PCIのINTx**（装置と足）: `machine/pc`の型にする。互いの変換は`machine`の中だけで行う。**割り込み線の値をGSIとして受け取る関数を作らない。**
- **GICのINTID**: 将来の`machine`の型である（今は作らない）。
- **源の番号**（カーネルの登録番号）: 共通の側の、中身の見えない型にする。Bが解決して返し、Cが処理の表の添字に使う。
- **例外・IPI・装置の割り込みを、1つの番号の空間にまとめない。** 例外はAからCへの別の入口（Bを通らない）、IPIは種類（今は探りだけ）、装置は源の番号、タイマはコアごとの別の種類として持つ。

### 4. 完了（EOI）の決まり

- 受け取った割り込みがスプリアスでなければ、Bがちょうど1回完了させる。**処理が戻った後で、戻らない動き（切り替え、遠征を畳むこと）より前に完了させる**（今のLAPICのタイマの形を決まりにする）。
- レベルで鳴る源は、処理が源を下ろしてから戻ること（virtioのISR、PS/2のデータ）。下ろさずに戻ると、完了の後に鳴り直す。
- スプリアスは完了させない（LAPICの0xFF、8259の7番と15番はコントローラの決まりに従う）。この決まりはBの中に閉じる。
- **処理が登録されていない源**: 許可するのは処理を登録した後だけにする（下の5）。それでも来たら、Bがその源を禁止してから完了させ、Cが数えて出す（鳴り続けさせない）。
- **受け取れない到着**（試しのベクタなどのソフトの`int`）: 数えるだけで、完了させない。
- **処理の中の誤り**: 止まる（Halt and Dump。`ADR-0004`）。完了は要らない。
- **途中で戻る道**: 登録した処理の中から`longjmp`しない。遠征を畳むのは出口の動きとして、完了の後にAが行う。
- BKLを取らない種類（IPIの探り）は、Cの入口関数の最初で分ける（`ADR-0027`の罠を踏まない）。完了は同じくBが行う。

### 5. 処理の登録は起動の間だけにし、起動の後は処理の表を変えない（運用者の決定）

- 登録は起動の途中、BKLの中で行い、処理を登録してから源を許可する。
- 起動の後（カーネル側のPML4の指紋を採るのと同じ時点）からは、登録を断る。断る形は、書く側の守り（`ensure_child`）と同じく、名前つきで止める。
- 起動の後は表が変わらないので、割り込みの中で表を読むのにロックが要らない（BKLを取らない種類からも読める）。
- 起動の後に源を増やす必要（USBの抜き差しなど）が出たら、そのときに設計し直す（持ち越しの「起動の後に割り込みの源を増やすか」）。
- 破壊テストを1本置く。起動の後に登録を試み、名前つきで止まること。

### 6. 割り込みを止める・許す関数の置き場と保証

- **`arch`（このCPUの割り込みの状態）**: 状態を読む、保存して止める、保存した状態へ戻す、許して待つ（許すことと止まることの間に隙間を作らない。x86は`sti; hlt`、AArch64は`wfi`の決まった並び）。機械に依らない名前でcommonの`arch`の直下に並べ、契約を書く。生の`cli`・`sti`は`arch`の中とガードの中だけで使い、許可の表を続ける。
- **`machine`（特定の源）**: 源ごとの許可と禁止、全部の禁止。
- **共通の側（使う決まり）**: `InterruptGuard`・`EntryInterruptGuard`・`Locked`・BKL。「元の状態へ戻す」契約（入れ子でも、既に止まっている所で入っても、外側が出るまで許さない）を保つ。
- 保証を分けて、契約に書く。
  - **このCPUの割り込みを止める**（`InterruptGuard`）: 止まるのはこのCPUだけで、ほかのCPUは走り続ける。例外とNMIは止まらない。メモリの順序は与えない。
  - **ほかのCPUとの排他**: 待って排他するのはBKLだけである。`Locked`は、同じCPUの入り直しを割り込みの禁止で止め、ほかのCPUとは取得の`swap`で止める（負けた側は待たずに止まる）。
  - **メモリの順序**: BKLの取得と解放、`Locked`の取得と解放（AcquireとRelease）が与える。割り込みを止めても、順序は与えない。
  - **NMIは止まらない。** NMIの処理はロックも確保も使わない（今はダンプして止まる）。
- 許して待つ関数は`enable_interrupts_and_wait`である（2026-09-28に`enable_interrupts_and_halt`から名前を変え、commonの`arch`の直下に並べた。契約は関数の説明にある）。

### 7. 今の経路を新しい形で説明する

- **タイマ**: BがLAPICのタイマ（起動の初めはPITと8259）を設定し、到着をコアごとのタイマとして受け取る。Cがティック・単調な時刻・スケジューラを進める。Bが完了させた後、Cが中断（Ctrl+C）で畳むか切り替えるかを決め、Aが実行する。較正と切り替えの読み戻し、APが自分のタイマを開ける所もBである。
- **PS/2**: ドライバが「ISAのIRQ 1」をBに解決させ（MADTの上書きでGSIへ）、源の番号で処理を登録する。BがI/O APICの経路を設定して許可する。到着すると、Bが受け取り、Cの処理がデータを読み（i8042のポートは`machine/pc`の関数で読む）、デコードして入力の待ち手を起こし、Bが完了させる。
- **virtio-blk**: ドライバがPCIの装置のINTxをBに解決させる。今は割り込み線の値をGSIにしているが、解決をBの仕事として閉じ、ACPIの表で正しく引くのは持ち越しの行の条件が来たときにする。到着すると、Cの処理がISRを読んで源を下ろし、完了した要求の待ち手を起こし（`ADR-0036`）、Bが完了させる。
- **IPIとTLBの撃ち落とし**: IPIの種類は今ある探りだけを持ち、送る所と受け取る所はBに置く。TLBの整合の正しさは世代の確かめのまま（`ADR-0027`）で、TLBのためのIPIを足すとしても、それは早めるための知らせである。
- **CPUの例外**: Aが原因と特権を読み、機械に依らない形でCへ渡す。Ring 3の畳める例外は、Cの方針で遠征を終わらせ、Aが畳む。それ以外はHalt and Dumpである。Bは関わらない（完了も無い）。NMIも例外の入口で止まる。
- **yieldとシステムコール**: ソフトの入口としてAが分け、C（スケジューラ、システムコールの振り分け）へ渡す。完了は無い。

### 8. 進め方（`ADR-0071`の手順2の9）

- 9a `apic`を`machine/pc`へ移す（ファイルごと。パスだけ）。
- 9b `irq`を`machine/pc`へ移す（ディレクトリごと。パスだけ）。
- 9c `interrupts`の残り（タイマの切り替えの読み戻しと、APがタイマを開ける所）を、`machine/pc`の直下の名前で呼ぶ形にする。
- 9d 入口を分ける（上の1・2・4・5）。**分けるコミットごとに差分を見せて承認を得て、依存の一覧（`arch`から共通の側）の項目が減っていく様子を報告に添える。**
- 9e 番号の型を分ける（上の3）。
- 9f 直下の名前を機械に依らない名前にする（`start_application_processor`の引数の型も、ここで見直す）。
- `acpi`・`pci`・`pmtimer`・i8042は、9の中の別のコミットにする。全検査は9dの後と、9の終わりに回す。

## Alternatives Considered

- **受け取るを「副作用の無い見分け」にする**（x86のベクタの形に合わせる）: 採らない。GICのIARとPLICのclaimは受け付けを兼ねるので、AArch64を足すときに契約が崩れる（運用者の調整）。
- **入口を今の1つの関数のまま、判定の順だけ整える**: 採らない。`arch`が共通の側を直に呼ぶ形が残り、`ADR-0071`の手順2の依存の向き（共通の側から`arch`・`machine`を呼ぶ一方通行）を満たせない。
- **番号を1つの整数の空間にまとめる**: 採らない。割り込み線の値をGSIとして扱った取り違え（持ち越しの行）と同じ形の誤りを、型で防げなくなる。
- **処理の表を、起動の後もロックつきで変えられる形にする**: 採らない。今の源は起動の後に増えず、ロックを割り込みの中で取る形は、BKLを取らない種類から表を読めなくする。要るようになったら設計し直す。
- **`machine`に装置の一覧を持たせる**: 採らない。装置を足すたびに`machine`を書き換えることになり、AArch64の`machine`とも中身が重なる。
- **TLBのためのIPIを正しさの手段にする**: 採らない（`ADR-0027`）。

## Consequences

- 割り込みの入口は、共通の側の入口関数4つほどだけを呼ぶ形になる（9の終わりの目標）。手順2の区切りで、依存の向きの機械検査を入れられる。
- AArch64を足すとき、Bの受け取ると完了させるをGICで実装すればよく、AとCの形は変えずに済む。
- 登録を起動の間に限ったので、USBの抜き差しのような源の増減は、今の形では扱えない（持ち越し）。
- 割り込み線の値をGSIとして受け取る関数を作らないので、PCIのINTxをACPIの表で引くまでは、virtio-blkのINTxの解決は今のQEMUの配線に乗ったままである（持ち越しの行のとおり）。
