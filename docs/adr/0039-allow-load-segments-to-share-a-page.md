# 0039. ロードする区画がページを共有する形を許す

## Status
Accepted

## Date
2026-08-19

## Context

zi-d-1で`/bin/zi`を起こそうとすると、シェルが`cannot run`を出して終わる。実測で分かったことは次のとおりである。

- `/bin/zi`は**PT_LOADを4本持つ**（像から`debugfs`で取り出して`readelf`で確認）。4本目は`.bss`で、`0x405248 filesz=0x0 memsz=0x2000 RW`である
- **カーネルが写像したのは3本だけである**（起動ログ）
- **3本目の最終ページと4本目の先頭ページが同じである**——3本目は`0x403000..0x405248`で最終ページが`0x405000`、4本目は`0x405248`から始まるので先頭ページも`0x405000`
- `map_user_4kib`は既に張られたページへ`AlreadyMapped`を返す。**これは推測ではなく、既存の破壊（`p_vaddr of the second segment moved into the first segment's page`）が同じ起動ログの中で実証している**
- **既存の7本はどれも`.bss`を持たない**（`zash.elf`に`.bss`セクションが無いことを実測）。**`zi`が「`.bss`を持つ最初のユーザープログラム」である。** ADR-0038の穴と同じ族で、**今まで出なかったのは運である**
- **区画がページを共有する形はELFの正当な配置である。** `lld`は`.bss`を`.data`の直後（同じページの途中）から始める。Linuxのローダーはこれを扱える

**切り分けが遠回りになった原因も記録する。** `spawn`は`ended ({child:?}) after N syscall(s)`の行を**ロードに失敗しても印字する**ので、走ったように読める。**ロードの誤りは1行も出ていなかった。**

## Decision

1. **ローダーは、区画が正当にページを共有する形を許す。** 許すのは**「そのページが直前の区画の最終ページと一致する場合」だけ**である。**任意の重なりは許さない**——それは不正なELFで、既存の破壊が突いている形である。
2. **共有ページでは、確保もゼロ埋めもやり直さない。** そのページは直前の区画が既にゼロ埋めしてファイルの中身を重ねてある。**新しい区画は`p_vaddr`がその中身の直後から始まる**ので、**残りは既にゼロである。** 上書きすると直前の区画の中身を消すことになる。
3. **ゼロ埋めの責任はローダーにある。既に正しい。** 区画のループはページごとに`write_bytes(dst, 0, PAGE_SIZE)`してからファイルの中身を重ねる形で、docにも「`p_memsz`が`p_filesz`より大きい分（`.bss`）はゼロのまま残る」と書いてある（実測で確認した）。**フレームアロケータがゼロを返す保証には依存していない。**
4. **ロードの失敗を1行で出す**——`spawn: {name} could not be loaded: {error:?}`。**遠回りの直接の原因への手当てである。**
5. **共有として許したことを判定行に出す。** 不正な重なりは依然として落ち、正当な共有は許され、**どちらであるかが行から読める。**

## Alternatives Considered

- **リンカスクリプトで`.bss`をページ境界から始める——却下。** 重なりは消えるが、**Cの移植で外から来るバイナリはリンカスクリプトを選べない。** 正当なELFを読めないローダーのほうが誤りである
- **`zi`を痩せさせて`.bss`を消す——却下。** 運任せであり、次に`.bss`を持つプログラムが来たら同じ形を踏む（ADR-0038で`zi`を小さくする案を却下したのと同じ理由）
- **既に張られていれば無条件に通す——却下。** 区画が任意に重なる不正なELFまで通る。**許す条件をELFの正当な配置から導く**

## Consequences

- `/bin/zi`が起こせるようになり、**`.bss`を持つプログラムが一般に動く**（Cの移植の前提が1つ整う）
- 既存の7本は**挙動が変わらない**——どれも区画がページを共有しない（`filesz == memsz`で、次の区画は`ALIGN(4096)`の先にある）
- 既存の重なりの破壊は、条件を狭めたので**従来どおり落ちる見込み**（実装後に実測して確かめ、繋ぎ替えが要るかを判断する）

## 決めないこと（着手時に決める）

- **ユーザースタックの拡張**——1ページの制約は別の話である（`zi`が16KiBの配列を`.bss`へ置いたのはこの制約による）。行を立てるか既存の行へ当てる
- **動的リンク**（`PT_INTERP`・`PT_DYNAMIC`）
- **`PT_TLS`**
- **`PT_GNU_RELRO`を見て`.got`を読み取り専用へ落とすこと**（`user.ld`が既に見直しの条件として書いている）

## 到達条件

1. `/bin/zi`が`spawn`で起こせること
2. **`.bss`を持つ検査用プログラムを像へ常設し、ゼロ初期化された領域が実際に0で読め、書けることを判定にすること。** `zi`が痩せて`.bss`が消えても、**能力が無検査に戻らない**（ADR-0038の`/data/sparse-hole`と同じ作法）。**あわせて、その1本のELFが本当に共有ページを持つことを確かめること**——`.bss`を持たせても、**たまたま`.bss`がページ境界から始まれば共有は起きない。** そのとき判定は「`.bss`は読める」を主張するだけで、**「共有ページを通った」ことは誰も見ていない状態へ黙って戻る**（`/data/sparse-hole`で「前後のブロックに中身が在ること」を同じ行で見たのと同じ形である）。区画の配置を判定に含めるか、build時に確認して落とす
3. **区画の本数の対**（`declared` / `mapped`）の判定行が一致すること
4. 破壊は「`memsz`ではなく`filesz`で張る」形。**`.bss`が張られず、上の判定が落ちる**
5. 既存の重なりの破壊を実測し、繋ぎ替えで済むか成立しなくなるかを分けること（成立しないなら理由をその場に残す）

## 再訪条件

**区画の配置の前提が変わったとき**——動的リンク（`PT_INTERP`）を扱うようになったとき、または**共有ページが「直前の最終ページ」以外の形で正当に現れるELFに出会ったとき。** そのとき許す条件の定義を見直す。
