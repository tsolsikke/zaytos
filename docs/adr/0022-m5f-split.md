# 0022. M5-fを「int 0x80システムコール」と「プロセス別アドレス空間」に分け、後者はhigher-half B完了後の独立マイルストーンにする

## Status
Accepted

## Date
2026-07-24

## Context

ADR-0019はM5-fを「システムコールとプロセスごとのアドレス空間」と定めた。
着手にあたり実コードとdeferred-decisionsを読み直したところ、この2つは前提が異なる。

- int 0x80システムコールは単一アドレス空間のまま実装できる。既存のIRQスタイルの復元経路（`zaytos_irq_common`）とRSP0の自動切替、`iretq`偽フレームによるRing 3遷移（M5-e）にそのまま乗る。
- プロセス別アドレス空間（下位を差し替え、上位=カーネルを共有）は「カーネルが上位半分だけに居る」ことに依存する。現在カーネルは`PML4[0]`（下位半分）に恒等マッピングで居るため、下位半分を差し替えられない。したがってhigher-half B（カーネルを上位半分へ移し恒等を外す）の完了が前提になる。この依存は`deferred-decisions.md`の「M5-eユーザー空間アドレスの暫定配置」に記録済みで、higher-half Bはまだ未着手である。

higher-half B自体が、恒等除去と全低位ポインタ（RSP・ヒープ・boot_info）の高位化を伴う、単独でも最もリスクの高い変更である。
これをシステムコール導入と同時に走らせると、障害の切り分け軸が二重化する。
M4以降くり返してきた「切り分け軸を一度に一つ」に反する。

## Decision

ADR-0019のM5-fの範囲を、この点について上書きする。

1. M5-fの範囲を「int 0x80システムコール（higher-half B非依存）」に絞る。内訳は次の内部段階とする。
   - M5-f-1: int 0x80の中核（ゲートDPL=3・専用スタブ・戻り値のRAX書き戻し・レジスタ規約）。単一アドレス空間、M5-eの暫定ユーザーサブツリー`PML4[1]`の上で完結する。
   - M5-f-2: ユーザーポインタ検証（実PTEを読んでユーザーアクセス可能性を確かめる）。同じく単一アドレス空間で、higher-half Bに依存しない。
2. プロセス別アドレス空間は、higher-half Bを先に独立したマイルストーンとして片付けたうえで着手する、別のマイルストーンとする。フレームアロケータの容量・データ構造の見直し（`deferred-decisions.md`）は、このマイルストーンの中でプロセスの生成・破棄を実装する直前に行う。

レジスタ規約（RAX=番号/戻り値、RDI/RSI/RDX/R10/R8/R9=引数、RCX/R11はクロバー扱い）はADR-0020のままで、この分割の影響を受けない。
`syscall`/`sysret`への差し替えが将来必須である点（ADR-0020）も変わらない。

## Alternatives Considered

- ADR-0019のままM5-fでシステムコールとプロセス別アドレス空間を一度に実装する: プロセス別アドレス空間がhigher-half B未完了では構造的に成立せず、Bを同時に走らせると切り分け軸が二重化する。却下。
- higher-half Bを先に割り込ませ、そのうえでM5-fをf-1からプロセス別アドレス空間まで通す: int 0x80より先に重いB（低位ポインタの高位化）を持ってくることになり、システムコールが「動く状態」に到達するまでが遠くなる。B非依存で先にシステムコールを動かせる以上、採る理由が薄い。却下。

## Consequences

- M5-fは単一アドレス空間のまま「システムコールが動く」まで到達する。roadmapとdeferred-decisionsは本ADRを参照して2分割を反映する。
- プロセス別アドレス空間はhigher-half Bの完了を解禁条件として持ち越す。着手時にADR-0019のこの点と本ADRを再確認する。
- ADR-0019は段階分割の骨格として有効なまま、M5-fの範囲についてのみ本ADRが上書きする（Supersededにはしない）。
