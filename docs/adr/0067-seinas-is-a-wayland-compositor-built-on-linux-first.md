# 0067. Seinas は Wayland のコンポジタで、Linux で先に作る——最初のアプリは zeyes

## Status

Accepted（運用者の決定。2026-09-07 と 2026-09-21）

## Date

2026-09-22

## Context

**第1段階（Wayland を使うための OS 基盤）は `ADR-0066` の Y-d で閉じた。** **次は Seinas 初版である。**

**Seinas の方針は運用者が決めていたが、記録が散っていた。** **決まった時期は 2 つある**——**2026-09-07 に「Seinas は Wayland のコンポジタで、ZaytOS でも Linux でも動く」、2026-09-21 に「Linux で先に作る」「最初のアプリは zeyes」ほか。** **前者は `docs/wayland-inventory.md` の冒頭に、着手順序と通信方針として書かれていた**（2026-09-08 に書いた。**あの文書は事実だけを記録する調べ物で、決定の置き場ではない**）。

**7 月の構想文書（v2。リポジトリの外）とも食い違っていた。** **v2 は「Wayland 互換は初期目標にしない」と、非目標「Linux evdev ABI 互換」を持っていた。** **どちらも新しい決定と食い違う。** **リポジトリの中には、この 2 つの文言はコピーされていない**（2026-09-22 に grep で確かめた。隣の古い作業ツリーにも無い）。

## Decision

**運用者の決定を 1 か所へ集める。**

1. **Seinas は Wayland のコンポジタである。** **ZaytOS でも Linux でも動く**（2026-09-07）。**通信は ZaytOS でも Linux でも Wayland を使う。** **Wayland のメッセージ解釈もウィンドウの管理も合成もユーザー空間で行い、カーネルへは入れない**（`ADR-0066` の Context）。
2. **Linux で先に作る**（2026-09-21）。**順序は次の 4 つで、それぞれを外の道具で確かめてから組み合わせる。**
   - **zeyes を既存の環境（GNOME・weston・sway など）で動かす**——zeyes の正しさ
   - **Seinas に既存のアプリを繋ぐ**——Seinas の正しさ
   - **zeyes と Seinas を繋ぐ**——組み合わせ
   - **ZaytOS へ載せる**（違いは OS の接続部だけ）
3. **ウィンドウシステムは重ねる型にする**（Windows と macOS のいいとこどり。2026-09-21）。**詳細は運用者に訊く。独断で決めない。** **初版（ウィンドウ 1 枚）では要らない。** **複数のウィンドウを扱う段階の設計時に、訊く項目をまとめて出す**（例: 閉じる等のボタンの位置、メニューバーをウィンドウごとか画面上部か、タスクバーか Dock か、ウィンドウ単位かアプリ単位の切り替え、画面端への吸着、最大化の意味）。
4. **ZaytOS で最初に出すアプリは zeyes（xeyes の ZaytOS 版）である**（2026-09-21）。**zeyes は ZaytOS の画面上のカーソルを、ウィンドウの外にあっても追う。** **QEMU や VirtualBox のホストのカーソルには頼らない。** **ウィンドウの外の位置は Wayland の標準では届かないので、Seinas の拡張を 1 つ設計する。** **拡張の無い環境（GNOME など）では、ウィンドウの上でだけ追う形に落ちる。**
5. **Seinas と Kieli（日本語 IME）は別のリポジトリで、この順に作る。** **ZaytOS へは `external/` などへ submodule で置く。** **`third_party/` は第三者の著作物の場所なので使わない。**
6. **v2 の 2 つの文言は、この ADR で置き換わる。** **「Wayland 互換は初期目標にしない」は 1 で、非目標「Linux evdev ABI 互換」は入力の fd を Linux の `struct input_event` に合わせた方針で置き換わった**（`ADR-0066` と `docs/architecture.md` の「ABIの形は合わせる。バイナリを走らせることは目標にしない」）。

## まだ決まっていないこと

- **Wayland の実装方式**（自作・wayland-scanner・wayland-server・smithay）。**ZaytOS は no_std なので、両 OS で動く中核がどこまで持てるかが効く。** **依存の実測は `docs/wayland-inventory.md` に在る**（2026-09-08）。**第2段階の設計で案を出す。**
- **zeyes がウィンドウの外のカーソルを受ける拡張の形。** **第2段階の設計で出す。**
- **重ねる型の詳細**（上の 3）。

## Alternatives Considered

- **決定を `docs/wayland-inventory.md` の冒頭に置く**——**却下**（レビューの指摘。2026-09-22）。**あの文書は事実だけを記録する調べ物で、決定を入れると事実と決定が混ざる。**
- **`docs/vision.md` に置く**——**却下。** **vision は構想であって決定ではない**（冒頭の規定）。
- **ZaytOS で先に作る**——**却下**（運用者の決定）。**Linux なら、外の道具（既存のコンポジタと既存のアプリ）でそれぞれの正しさを先に確かめられる。** **ZaytOS で先に作ると、コンポジタの誤りと OS の誤りが同じ場所に出る。**

## Consequences

- **`docs/vision.md` と `docs/roadmap.md` の GUI の節は、この ADR を名前で指す。** **コピーしない。**
- **`docs/wayland-inventory.md` は事実のまま残す**（日付だけ直した——決定は 2026-09-07、書いたのは 2026-09-08）。
- **ZaytOS 側に残る仕事は「OS の接続部」である**——**第1段階の入口（ソケット・共有メモリ・入力の fd・多重待ち・画面）の上に載せる。** **載せる段階で、`mmap` が参照を持つ形が要る見込みである**（`docs/deferred-decisions.md` の「`mmap`が参照を持たない」）。
