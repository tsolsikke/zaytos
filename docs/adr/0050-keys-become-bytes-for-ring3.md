# 0050. Home / EndとCtrl+英字をRing 3へ落とす形

## Status

Accepted

## Date

2026-08-28

## Context

**SE段で、Home / EndとCtrl+A / Ctrl+Eが要る**（運用者の要望。2026-08-22）。
**どちらも、いまRing 3へ届いていない。** **`ADR-0049`と分けたのは、
`terminfo`を書く日に引かれるのがこちらだけだからである**——展開の規則とは
読む文脈が違う。

**実測**（2026-08-28。源は`kernel/src/keyboard/decode.rs`と`kernel/src/input.rs`）。

- **Ctrlは既に追えている。** `Decoder`が`self.ctrl`を持ち、**Ctrl+Cのときだけ`0x03`を出す。**
  **同じ場所のコメントが「一般化してCtrl+英字を1..26へ落とす形も採れるが、採らない。
  使う者がいない機構は検算が置けない。使う道ができた時点で広げること」と書いている。**
  **SEがその道である。**
- **Ctrlの経路は2つあり、独立である。** もう1つは`kernel/src/input.rs`の
  `note_scancode_for_interrupt`で、**割り込みの側で`CTRL_DOWN`を追い、Ctrl+Cを
  中断の旗（`INTERRUPT_REQUESTED`）にする。** **こちらは子を止めるための経路で、
  デコーダのバイトとは別である。**
- **Home / Endは種を持たない。** `KeyEvent::Unsupported`になり、`bytes_for_event`が
  落としている。**そこのコメントが「扱うと決めたらdecode側で種を得る（zi-aの形）」と
  書いている。**
- **既に出している並びは`\x1b[3~`（Delete）と`\x1b[A`/`B`/`C`/`D`（矢印）である。**
  `\x1b[3~`は「本物の端末と同じ形にする。こちらの都合で1バイトを割り当てると、
  `terminfo`を書く日に合わなくなる」という理由で選ばれている（zi-f）。

## Decision

**2つ決める。**

### 1. Home / Endは`\x1b[1~`と`\x1b[4~`を出す

**`KeyEvent`に種を2つ足し、`bytes_for_event`がこの並びを返す。**

**`\x1b[H`と`\x1b[F`（xtermの形）を採らない理由は3つある。**

- **`\x1b[3~`と同じ「CSI 数字 ~」の族で揃う。** **入力を解釈する側の形が1つで済み、
  2つ目の経路を作らない**（`zash`も`zi`も、いまは終端の1バイトで分岐している）。
- **`\x1b[H`は出力側のCUPと終端が同じである。** **`ADR-0029`が決めた出力の解釈に
  `\x1b[H`が在るので、次に読む者が入力と出力を取り違える。**
- **端末はZaytOS自身なので、xterm互換の利得が無い。** **Deleteは全端末で`3~`だが、
  Home / Endは端末によって割れている**——**割れているものについては、互換ではなく
  自分の一貫性で選ぶ。**

### 2. Ctrl+英字を1..26へ一般化する

**`Ctrl`が押されているとき、英字は`0x01`から`0x1A`へ落ちる。**
**Ctrl+Cの`0x03`は、その規則の1つの場合になる。**

**「使う者がいない機構は増やさない」の当てはめは、ここでは逆である。**
**一般化は機構を増やさない。既に在る例外（Ctrl+Cだけ特別）を規則へ畳む。**
**2文字だけ通す案のほうが、例外の表を作ることになる。**

**条件が2つある。どちらも守れることを判定で主張する。**

- **割り込みの側の役割を変えない。** `note_scancode_for_interrupt`は触らない。
  **中断の旗は別経路で、デコーダが`0x03`を出すかどうかとは独立である。**
  **`--shell-test`の「ctrl-cが回っている子を止めた」が、いまのまま緑であること。**
- **`zash`は、知らない制御バイトを行へ入れない。** **いまは知らないバイトが
  そのまま挿入される**ので、**Ctrl+Dが`0x04`として行を汚す。**
  **`0x20`未満のうち、扱うと決めたもの以外は捨てる。**

**この条件を確かめるときに、同じ形が1つ見つかった。** **Tabは既に`0x09`として
Ring 3へ届いている**（`decode.rs`が`Char('\t')`を出し、`bytes_for_event`がASCIIを
そのまま通す）。**`zash`の`run_line`のコメントは「タブはまだ来ない——decode.rsが
Tabを文字として出さない」と書いており、これは誤りである。**
**Tabは行へ字として入り、語の区切りとしても扱われていない**（区切りは`0x20`だけ）。
**Ctrlの一般化を入れる前から在る**ので、**同じ手当てでまとめて処理する。**

### Tabを捨てるのは、既存の振る舞いの変更である

**いまTabは行へ入る。捨てると、押しても何も起きなくなる。** **明示しておく。**

**それでも捨てる。理由は、入るほうが害が大きいからである。**
**入った`0x09`は画面で幅を持たず、語の区切りにもならない**ので、
**`ls`と打ったつもりの語が`ls`＋見えない1バイトになり、`cannot run`が出る。**
**打った人には、なぜ動かないのかが読めない。** **見えない字が語に混ざる形は、
原因を追う手がかりを残さない。**

**失うものも明示する。** **多くのシェルでTabは補完なので、押した人は何かが
起きることを期待する。** **何も起きないのは、壊れているのか仕様なのかが
区別できない形である**——**この体制が繰り返し避けてきた形そのものである。**

**報せを出す案は採らない。** **エコーエリアは在る**（`ADR-0046`）**ので出せるが、
「補完はまだ無い」と報せることは、補完を作る話に半分入っている。**
**いま作らないと決めているものについて、報せだけを先に作らない。**
**持ち越しの行を立てた**（解禁は「補完を要る利用者が来たとき」）。

## Alternatives Considered

- **案 Home / Endに`\x1b[H`と`\x1b[F`を使う。却下。** 上の3つの理由。
  **xterm互換そのものは利得だが、この体制には受け手が居ない**——
  **端末を書いているのは自分で、`terminfo`もまだ無い。**
  **`terminfo`を書く日に、こちらの並びを書けばよい。**
- **案 Ctrlは`A`と`E`の2つだけ通す。却下。**
  **例外の表が育つ。** 使う鍵が増えるたびに表へ足すことになり、
  **「なぜこの2つだけか」を説明し続けることになる。**
  **一般化すれば、飛び先を決めるのは受け手（シェル）である。**
- **案 Ctrlを`Unsupported`のまま残し、シェルが`CTRL_DOWN`を読む。却下。**
  **修飾の状態をRing 3へ出す口が無く、作ると「押されている状態」を
  読む側が持つことになる。** **バイトで届けば状態を持たなくてよい。**

## 決めないこと

- **Alt / ファンクションキー / テンキー。** 使う者が居ない
- **Ctrlと記号の組み合わせ**（`Ctrl+[`など）。**英字だけを1..26へ落とす**
- **Caps LockのLED**（既に持ち越しに行がある）
- **`terminfo`の中身。** Cの移植の段で書く
- **Tabでの補完。** **持ち越しの行を立てた**（解禁は「補完を要る利用者が来たとき」）

## 判定

**`cargo xtask run --shell-test`を延ばす。**

1. **HomeとEndの打鍵が挿入点を行頭と行末へ動かす**
2. **Ctrl+AとCtrl+Eが同じ動きをする**（同じ判定を2つの経路で通す）
3. **Ctrl+Dを打っても行が変わらない**（知らない制御バイトが入らない）
4. **Tabを打っても行が変わらない**（上と同じ手当てが効いている）
**この5つがADR-0050の到達条件である。**

**到達条件とは別に、既存の判定を1つ引く。** **`--shell-test`の
「ctrl-cが回っている子を止めた」である。** **この判定そのものは変わらない。**
**引くのは破壊の影響範囲としてである**——**下の`keyboard-drop-ctrl-letters-test`を
入れたとき、この判定が緑のままであることが、2つの経路が独立であることを主張する。**

**到達条件と影響範囲を混ぜない。** **混ぜると、次に項目を数える者が二重に数える。**
**項目数は増えない**（既存の判定を1つも足していない）。

## 破壊

- **`keyboard-drop-home-end-test`**——Home / Endを`Unsupported`へ戻す。判定1が落ちる
- **`keyboard-drop-ctrl-letters-test`**——Ctrl+英字の一般化を外す（Ctrl+Cだけに戻す）。
  **判定2が落ち、上の「引く既存の判定」は緑のままである**——
  **2つの経路が独立であることを、この破壊が主張する**
- **`shell-keep-control-bytes-test`**——`zash`が制御バイトを捨てない。判定3と4が落ちる

## Consequences

- **Ctrl+英字がすべて届くようになる。** **使う道が在るのはAとEだけだが、
  受け手が捨てるので害は出ない**（判定3がそれを主張する）
- **`terminfo`を書く日に、Home / Endは`\x1b[1~`と`\x1b[4~`として書くことになる。**
  **xtermの`terminfo`をそのまま使えない**——**もともと使えない**（この端末は
  ZaytOS自身で、色も鍵も自分で決めている）
- **`zash`が制御バイトを捨てるようになる。** **捨てたことは画面に出ない**ので、
  **打った人には「効かない鍵」に見える。** 使う鍵が増えたら、そのつど通す
- **デコーダと`input.rs`に触るので、レビュー必須である**（`CLAUDE.md`の
  「人間レビューが必須の変更」——割り込みハンドラに関わる）
