# 0037. ファイルへの書き込みはRAM複製までとする

## Status
Accepted

## Date
2026-08-19

## Context

ziの:wに書き先が要る。S12でext2の書き（append/truncate/create等）はRAM複製に対して実装済みだが、syscallの面は読み取り専用である（openはO_RDONLY以外を-EROFSで拒み、writeは端末以外を拒む）。

装置への書き戻し（flush）は起動シーケンスで1回だけ走り（ADR-0034のAddendum）、IF=0・スケジューラ前で眠れない。装置ハンドルはkernel_mainのローカルで、シェルの文脈から呼ぶ静的な家は無い（実測）。

## Decision

1. **:wの行き先はRAM複製までとする。** 同じ起動の中では読み戻せる。再起動で消える——主張は「ファイルに書けた」であって「永続ストレージに書けた」ではない。
2. **読み取り専用FSの前提を狭める。** openの受理を**O_RDONLYとO_WRONLY|O_TRUNC（既存の通常ファイルのみ。openの時点で長さ0へ切る）の2形**にする。それ以外は従来どおり-EROFS。書きで開いたfdへのwriteは`append_to_file`で複製へ足す。
3. **fdの向きの取り違えは両方向とも-EBADFである**（Linuxの形）。読みで開いたfdへのwriteも、書きで開いたfdへのreadも-EBADF。従来のwriteの非端末への-EROFSはこれに置き換わる（名指しする既存判定は無い。実測）。
4. **システムコールは増えない。** openとwriteの受理が広がるだけである。

## 決めないこと（各段の着手時に決める）

- **O_CREAT（新規作成）**——:wは既存ファイルの上書きで足りる。部品（`create_file`）は在るが、面へは出さない
- **O_APPEND / O_RDWR / 位置書き（pwrite相当）**——使う者がいない機構は検算が置けない
- **flushの呼び場所と形**——**永続化はADR-0034の2つ目のAddendumの発火条件（disk0.imgを起動間で持ち越す形へ動くとき）と同じ判断点である。** BKLを解いてポーリングする形（sys_writeのコンソールの先例）とd-2のhlt形の選択も、そのとき一緒に決める

## Alternatives Considered

- **シェルの文脈からflushを呼ぶ（書くたび永続化）——却下。** §6の設計（BKL保持のまま待てない）と装置ハンドルの静的な家が先に要り、ziの段の大きさを超える。運用者の「最小限でよい」の判断に沿う
- **bare O_WRONLYでの位置上書き——却下。** write-at-offsetの部品が無く、:wの全置換にはO_TRUNCの形が正確に対応する
- **O_CREATを同時に開ける——却下**（上の「決めないこと」）

## Consequences

- ziの:wが成立する（書き→catの読み戻しが同じ起動で見える）
- **再起動で消える。「書いたのに消えた」はこのADRが引き受ける仕様である**
- writeの非端末への-EROFSが-EBADF（fdの向きの取り違え）へ変わる
- RAM複製への書き手の口が1つ開く（unsafe。BKLの直列化が根拠。複製への参照の生成箇所の全数列挙はvfsのSAFETYコメントが指す）
