# 0037. ファイルへの書き込みはRAM複製までとする

## Status
Accepted

## Date
2026-08-19

## Context

ziの:wに書き先が要る。S12でext2の書き（append/truncate/create等）はRAM複製に対して実装済みだが、syscallの面は読み取り専用である（openはO_RDONLY以外を-EROFSで拒み、writeは端末以外を拒む）。

装置への書き戻し（flush）は起動シーケンスで1回だけ走り（ADR-0034のAddendum）、IF=0・スケジューラ前で眠れない。装置ハンドルはkernel_mainのローカルで、シェルの文脈から呼ぶ静的な家は無い（実測）。

## Decision

1. **:wの行き先はRAM複製までとする。** 同じ起動の中では読み戻せる。再起動で消える——主張は「ファイルに書けた」であって「永続ストレージに書けた」ではない。
2. **読み取り専用FSの前提を狭める。** openの受理を**O_RDONLYとO_WRONLY|O_TRUNC（既存の通常ファイルのみ。openの時点で長さ0へ切る）の2形**にする。それ以外は従来どおり-EROFS。書きで開いたfdへのwriteは`append_to_file`で複製へ足す。
3. **fdの向きの取り違えは両方向とも-EBADFである**（Linuxの形）。読みで開いたfdへのwriteも、書きで開いたfdへのreadも-EBADF。従来のwriteの非端末への-EROFSはこれに置き換わる（名指しする既存判定は無い。実測）。
4. **システムコールは増えない。** openとwriteの受理が広がるだけである。

## 決めないこと（各段の着手時に決める）

- ~~**O_CREAT（新規作成）**~~ **e-5で決めた。下のAddendumにある**（行は消さず状態を書き換える）。**利用者が来た**——運用者が「新しいファイルを作れるようにしてほしい」と言い、`zi`が最初の利用者になった
- **O_APPEND / O_RDWR / 位置書き（pwrite相当）**——使う者がいない機構は検算が置けない
- **flushの呼び場所と形**——**永続化はADR-0034の2つ目のAddendumの発火条件（disk0.imgを起動間で持ち越す形へ動くとき）と同じ判断点である。** BKLを解いてポーリングする形（sys_writeのコンソールの先例）とd-2のhlt形の選択も、そのとき一緒に決める

## Alternatives Considered

- **シェルの文脈からflushを呼ぶ（書くたび永続化）——却下。** §6の設計（BKL保持のまま待てない）と装置ハンドルの静的な家が先に要り、ziの段の大きさを超える。運用者の「最小限でよい」の判断に沿う
- **bare O_WRONLYでの位置上書き——却下。** write-at-offsetの部品が無く、:wの全置換にはO_TRUNCの形が正確に対応する
- **O_CREATを同時に開ける——却下**（上の「決めないこと」）

## Consequences

- ziの:wが成立する（書き→catの読み戻しが同じ起動で見える）
- **再起動で消える。「書いたのに消えた」はこのADRが引き受ける仕様である**
- writeの非端末への-EROFSが-EBADF（fdの向きの取り違え）へ変わる
- RAM複製への書き手の口が1つ開く（unsafe。BKLの直列化が根拠。複製への参照の生成箇所の全数列挙はvfsのSAFETYコメントが指す）

## Addendum: O_CREAT（e-5で決めた）

**`O_WRONLY|O_CREAT|O_TRUNC` を受理する。** 番号は Linux から採る（`O_CREAT` = 0o100。実測）。

### 受理するのは3形ではなく2形である

**`O_CREAT` 単独は受けない。** **位置書きの部品が無いので、作った後にできるのは全置換だけである**——**`O_TRUNC` と同じ形になる。** **`O_WRONLY|O_TRUNC`（既存の上書き）と `O_WRONLY|O_CREAT|O_TRUNC`（無ければ作って全置換）の2形である。**

### 既に在るときは、作らずに開く

**POSIX と同じである**（`O_EXCL` が無ければ、在っても失敗しない）。**`O_EXCL` は受けない**——**「在ったら失敗する」を要求する利用者がいない。**

**実装は `lookup` の `NotFound` でだけ作る側へ入る。** **したがって `create_file` が `NameTaken` を返すのは、引けなかったのに在ったときだけである**——**像の側の食い違いなので `-EEXIST` を返して黙らない。**

### 断り方

- **親が無い / 親がディレクトリでない** → `-ENOENT` / `-ENOTDIR`（`lookup` がそのまま返す）
- **名前が空、`/` で終わる** → `-EINVAL`
- **空きが無い**（inode・ブロック・ディレクトリの隙間のどれでも）→ `-ENOSPC`。**使う側にできることは同じ（消して空ける）なので、分けない**
- **像の側の食い違い** → `-EIO`

### 作った後にもう一度引く

**`create_file` は inode 番号を返すが、開く側が要るのは `Inode` である。** **像を書き換えた後に引き直す**ので、**作った結果そのものを見る**——**書けたつもりで引けない形が、ここで落ちる。**

### 判定

**源を分けてある。** **`ls` を前後で撮り、後にだけ在ることを見る**——**`ls` は `getdents64` を通って像を読むので、`zi` とは別の道である。** **中身は `cat` の読み戻しで見る。** **破壊は1つ**（`open-ignore-create`。`O_CREAT` を受けても作らず `-ENOENT` を返す）で、**落ちるのはこの判定だけである。**

### まだ決めていない

- **`mkdir`**——**利用者が来るまで。** `create_file` はファイル用で、ディレクトリは `.` と `..` の始末と親の `i_links_count` が要る（S12 の締めに書いてある）
- **`O_EXCL` / `O_APPEND` / `O_RDWR` / 位置書き**——上の一覧のまま
- **消す道（`unlink`）**——**部品は在る**（`unlink_file`。起動時の検算が使っている）が、**面へは出していない。** **`zi` からファイルを消す利用者がいない**
