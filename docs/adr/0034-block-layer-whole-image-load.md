# 0034. ブロック層は全像ロードで始める

## Status
Accepted

## Date
2026-08-18

## Context

S13-cで、ext2の読み取り先をRAM上の埋め込み像から装置（virtio-blk）へ差し替える。`common::ext2::Ext2`は像全体のバイト列（`&[u8]`）を借りる形で書かれており、装置を挟むには「像をどう供給するか」の境界を決める必要がある。

実測:

- 像（`fs.img`）は2MiB（`IMAGE_BYTES = 2097152`）。RAMは256MiB
- 像をフレームへ載せる経路は既にある——`try_copy_fs_image_to_frames`が`allocate_contiguous_aligned`で512フレームを確保している（S12-a）。ヒープは通らない
- ヒープの持ち越しの行の実文言は「1MiBで不足した時点」（`deferred-decisions.md`）。内容の側に「ext2のブロックキャッシュとユーザーランドが載ると不足しうる」とあり、キャッシュ案を採ればこの判断が要る

## Decision

**全像ロードで始める。** 起動時に装置から像全体をRAMのフレームへ読み、以後の読み書きは今までどおりRAM上の複製に対して行う。装置層の仕事はload（S13-c）とflush（S13-e）だけである。

- `try_copy_fs_image_to_frames`の複製元を、`.rodata`の`FS_IMAGE`から装置からのvirtqueue読みへ差し替える。下流（`set_root_image`・S12の実演・判定）は無傷である
- `Ext2`には触れない——借り方（全像スライス）はそのまま成立する

## 決めないこと（ADR-0025と同じ形。各段の着手時に決める）

- **書き込みの経路とflush**（`VIRTIO_BLK_T_OUT`をいつ・どの単位で発行するか）——S13-e
- **割り込み**（ポーリングをやめる時機と方式）——S13-d
- **ブロックキャッシュの導入**——再訪条件と一体である（下記）
- **埋め込み像（`include_bytes!`）を外すか**——S13-eの後。ホストテストと一致判定の参照として当面残す（**S13の締めで決めた。下の2つ目のAddendum**）

いずれも本ADRのDecisionからは導かれない——全像ロードは、書き戻しの単位・割り込みの方式・埋め込みの要否を何も制約しない。

## Alternatives Considered

**ブロックキャッシュ——却下。**

- `Ext2`の借り方（全像スライス）そのものの作り直しになる。読む側・書く側の全関数が「像はメモリに全部ある」を前提にしており、部分的にしか無い像への書き換えはS13の範囲を大きく超える
- キャッシュの置き場でヒープの持ち越しの行（「カーネルヒープの拡張」）が発火する。全像ロードはフレーム直取りの既存経路で済み、発火しない
- 要る土台が小さい方を採る（ADR-0033と同じ判断）。像が2MiBでRAMが256MiBである限り、キャッシュが節約するものは無い

## Consequences

得るもの:

- `Ext2`と既存の判定群が無傷で残る。差し替えは複製元の1点である
- 既存の「read-back identical」（複製と埋め込みのバイト一致）が、そのまま「装置経由で読んだ像は正しい」という主張になる

代償と、当たらない理由:

- **像全体ぶんの物理連続フレームが要る。** 2MiBは256MiBの0.8%で当たらない。**ただしこれは現在の像の大きさへの依存であって、性質ではない**——像を育てる判断をするときは、この前提を一緒に見ること
- **起動のたびに全像を読む。** 2MiB / 512Bで4,096リクエスト（4KiBずつなら512）。ポーリングの実測は数スピンで返るので、起動時間には効かない見込み（実装で測って報告する。判定行へ固定するかは、揺れを見てから別途決める）

再訪条件: **像がRAMに載らない大きさになったとき、または部分読みが実測で要る場面が出たとき。** そのときブロックキャッシュ（とヒープの行）を再訪する。

## Addendum（S13-eの着手時。書き戻しは全像フラッシュ）

S13-eで、RAM複製への書き込み（S12で実装済みの`exercise_*`）を装置へ書き戻す。**「決めないこと」に開けていた「書き込みの経路とflush」を、ここで決める。**

**全像フラッシュで書き戻す（全像ロードと対称）。** `write_at`を`read_at`と対称にvirtioへ足し（`VIRTIO_BLK_T_OUT`。512の倍数）、`flush_fs_image_to_device`が像全体を4KiBずつ書き戻す（`copy_fs_image_to_frames`の対称）。**Ext2には触れない**——本体のDecisionと同じく、像全体を借りる形がそのまま成立する。

**契機はkeep系変種の最終状態である。** S12の実演はどれも「書いて元へ戻す」ので、戻した後の像は建てた像と同じ——それをフラッシュしても`disk0.img`が変わらず、**書き戻したことを主張できない**（案Aの却下理由）。既にpmemsaveがkeep系変種（`fs-alloc-keep`等）で「書いたままの像」を取り出しているので、**同じ変種でフラッシュすれば`disk0.img`に書いたままの像が残り、ホストが`e2fsck`で直接見られる。**

**ダーティ管理（変更ブロックだけを追って書き戻す）は却下。** 本体がブロックキャッシュを却下したのと同根で、Ext2の借り方（全像スライス）の作り直しになる。像が2MiBでRAMが256MiBである限り、全像を書き戻す代償（2MiB / 512Bで4096リクエスト、4KiBずつなら512）はロードと同じで、起動時間に効かない見込み（実装で測って報告する）。

**flushはポーリングである（S13-d-2の眠りの利用者ではない）。** 起動シーケンスのflushはIF=0・スケジューラ前（`copy_fs_image_to_frames`と同じ位置）で、眠れない。ADR-0036のAddendumがこの前提を書く。

再訪条件: 本体の再訪（像がRAMに載らない大きさになったとき）と重なる。そのとき全像ロードと全像フラッシュを一緒にブロックキャッシュへ作り直す。

## Addendum（S13の締め。埋め込み像は条件つきで残す）

「決めないこと」に開けていた「埋め込み像（`include_bytes!`）を外すか」を、ここで決める。

**条件つきで残す。** 外す条件は**`disk0.img`を起動間で持ち越す（永続化する）形へ動くとき**である。いまは`stage_esp`がQEMUを起こすたびに建てた像から`disk0.img`を作り直すので、「装置から読んだ複製 == 埋め込み」のバイト一致（read-back identical）は成立し続ける。持ち越しが始まると装置の中身は建てた像から離れ、この一致は原理的に成立しなくなる——外す判断がそのとき自然に発火する。

依存の実測（S13の締めで数えた）。カーネル側は6箇所——ロード/フラッシュの大きさの出所（`FS_IMAGE.len()`）、read-back identicalの参照、T3-1（埋め込みを直接parse）、corrupt-fs系の複製元、`vfs::root_image()`の複製前フォールバック、埋め込みを参照する破壊feature 2つ（`fs-load-from-embedded-test`・`fs-read-from-rodata-test`）。ホスト側は依存しない——commonのext2テストは合成像を組み、xtaskの判定は`OUT_DIR`のビルド産物を読む。

却下した案:

- **いま外す——却下。** 得るものはカーネル像の2MiB減だが、read-back identicalの参照を失う（ハッシュで代替しなければ`dumpe2fs`+`e2fsck`の系統まで弱まる）。上の6箇所の載せ替えとレイアウト移動（2MiB境界の既知の族）・起動ログ参照の録り直しを買うことになり、決め急ぐ理由が無い（RAMにもカーネル像の大きさにも困っていない）
- **無条件で残す——却下。** 「いつ外すか」を開けたままにすると、この行が二度と発火しない。持ち越しという具体の契機に結び付けておく

## Addendum（2026-08-28。P-e。条件が満たされたので外す）

**上の「外す条件」は`disk0.img`を起動間で持ち越す形へ動くときだった。** **その条件が満たされた。**

**実測で壁に当たった**（`cargo xtask run --persist-probe`）。**1度目を`fs-alloc-keep-test`で起こすと、割り当てたブロックが解放されずにフラッシュされ、ホストが`dumpe2fs`で`Free blocks: 381`を読んだ**——**持ち越しの機構そのものは既に効いている。** **2度目を、像を作り直さずに起こすと`read-back identical=false`になり、`fs-image-copy: the copy does not match the embedded image; halting`で止まった。** **持ち越した瞬間に起動しなくなる。**

### 決定

**埋め込み像（`include_bytes!`）を外す。** **像の源は`disk0.img`だけになる。**

### 依存の数と、数え方

**数え方を書く。数は数え方とセットである。** **符号の中で`FS_IMAGE`を書いている行を数え、コメントとdocは数えない。`CORRUPT_FS_IMAGE`は別名なので含まない。**

**14箇所である**（`vfs.rs` 4、`main.rs` 10。実測。2026-08-28）。**役割で括ると6つになる**——像の定義／複製前の読み先のフォールバック／大きさの出所／一致の守り／起動時の埋め込み像の検査／破壊の像の複製元。**上のContextが書いた「6箇所」は、おそらくこの括り方である**（あちらは数え方を書いていないので、突き合わせられない）。

### 中身の源は、外す前から既に装置である

**既定の経路は装置から4KiBずつ複製先へ直接読んでいる。** **`FS_IMAGE`から複製する経路は`fs-load-from-embedded-test`の下にしかない。** **外して消えるのは参照であって、源ではない。**

### 代わりの守り——検査値を独立な2つの源から取る

**失うのは`copied == FS_IMAGE`である**（装置から読んだ像が期待どおりかを毎起動で守っていた）。

**代わりに、複製先の全体の検査値をカーネルが判定行へ出し、ホストが`disk0.img`から独立に同じ計算をして突き合わせる。** **源が独立である**——**ファイルを直に読む側と、virtioを通って読む側である。** **持ち越しでも成立する**（毎回中身が変わってよい）。

**これはハッシュではない。重み付き和である**（`byte * (index + 1)`の総和）。**上のContextは「ハッシュで代替しなければ」と書いているので、違う道具を採ったことを明示する。**

**それで足りる理由は、源が独立で、狙って合わせる者が居ないことである。** **暗号的な強さが要るのは、値を合わせにくる相手が居るときである**——**ここに居るのは、装置の読みが壊れる／複製の番地を間違える／ホストが別のファイルを見る、といった事故だけである。** **重み付き和は位置を見るので、順序の入れ替えも捕まえる。**

**同じ式が既に在る**（virtioの読みの検査値）。**式を2つに増やさない。** **実際、その式は起動ログの差の分解でも働いた**——**空きブロックが12番地から4減って重み13、空きinodeが16番地から1減って重み17で、検査値の差`-69`が算術で合った**（2026-08-28）。

**費用の上限は言える。** **いまの守りは2MiBのスライス比較で、毎起動で既に2MiBを歩いている。** **検査値も2MiBを1回歩くだけなので、同じ位である。** **正確なTCGでの時間は測っていない**——**置いた後に判定行へ出すこと。**

### 引き継ぎの表——外した結果、誰が何を守るか

| 消す／落とすもの | 守っていた主張 | 引き継ぐ者 |
|---|---|---|
| `fs-read-from-rodata-test` | 読む先が複製へ向いている | **構造的に真になる**（読む先が1つしかない） |
| `fs-load-from-embedded-test` | 複製の源が装置である | **構造的に真になる**（源が1つしかない） |
| `copied == FS_IMAGE` | 装置から読んだ像が期待どおり | **新しい検査値の突き合わせ**（カーネルが出し、ホストが`disk0.img`から独立に計算） |
| `verify_embedded_fs_image`（像がext2として解析できる） | 建てた像が壊れていない | **`cargo xtask check`の`fs image e2fsck`**（建てた像に当てている。外の道具） |
| `verify_embedded_fs_image`（大きさが`build.rs`の定数と一致） | 埋め込みと定数がずれていない | **引き継ぎ手は要らない**——**埋め込みが消えるので、ずれる対象そのものが消える。** **落としてよい主張である** |
| `verify_embedded_fs_image`の判定行（像の大きさと`mke2fs`の版） | 作り手が変わったことを人が読んで気づく | **`fs image e2fsck`の判定行**（`MKE2FS_VERSION`と`IMAGE_BYTES`を既に出している。実測） |

**持ち手が無いまま落とす主張は1つも無い。** **1行だけ「引き継ぎ手は要らない」があるが、それは主張の対象が消えるためで、守りが減るのとは違う。**

**外す範囲の外に、既に持ち手が無い主張が1つある**（この決定が作るものではない）。**装置の容量が像の大きさ以上であることを、誰も確かめていない**——**capacityは判定行に出ているが、比べていない。** **持ち越しで像の大きさが変わる形が来たら、ここが要る。** **いまは行を立てるにとどめる。**

### `CORRUPT_FS_IMAGE`の前提

**複製元を`FS_IMAGE`から、装置から読んだ複製（`vfs::root_image()`）へ移す。** **寸法の出所（`fsimage_info::FIRST_FREE_BLOCK`）は`build.rs`の定数のままにする。**

**前提を明記する。** **破壊の検査は、作り直した像でしか走らない。** **持ち越す構成では、装置の中身の使用上端が起動ごとに動きうるので、定数の寸法が実態と合わなくなる。** **いまは偶然そうなっているだけで、前提として書かれていなかった。** **持ち越す構成では走らせないこと。**
