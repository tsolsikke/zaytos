# 0061. 待つタスクは合図で起こす。上限で止めるのは検査の側である

## Status
Accepted

## Date
2026-09-16

## Context

**W1で2本のRing 3が同時に走るようになった**（`ADR-0060`）。**しかし、どちらも待てない。**

**実測が3つある。**

- **`read(0)`は溜まっていなければ`-EAGAIN`を返し、シェルは`continue`で回す**（`kernel/userland/zash.rs`）。**1セッションで1,282,916回のシステムコールを出した**（`--shell-test`のログ）。**そのほぼ全部が空振りの`read`である**（推測。内訳の計器は無い）。**毎秒約25,000回は導出である**（項目の51.6秒に建てと起動が入っている）。
- **`sti; hlt`は3箇所しか無い**（`kernel/src/interrupts.rs`のハートビートのループ、`kernel/src/smp.rs`のAPの定常ループ、`kernel/src/virtio.rs`のI/O待ち）。**1つ目は`init`より前に抜けるので、`init`が引き取った後のBSPは1度も眠らない。**
- **待てるシステムコールが1つも無い**（実測。`read`・`write`・`open`・`close`・`stat`・`getdents64`・`lseek`・`mkdir`・`rmdir`・`unlink`・`brk`・`ioctl`・`exit`・`spawn`と、私物の3つ）。**`spawn`は親を止めるが、それは遠征の入れ子であって、スケジューラの待ちではない。**

**穴も1つ見つけた。** **`pick_next`の落ち先は固定でタスク0である**（`default_task_for`）——**タスク0が走行不可でも選ばれる。** **待たせ始めると、ここに当たる。**

## Decision

**5つ決めた**（運用者の承認。2026-09-16）。

1. **待てるのは前景の持ち主だけである。** **持たない1本の`read(0)`は`-EBADF`のままにする**（いまと同じ）。**取り合いも待ち行列も作らない**——**政策が要り、その利用者が居ない。** **「待てないことと、回ることは別である」**——**`-EBADF`は即返るので、2本目は回さずに終われる。**
2. **BSP用のアイドルタスクを足す**（`TASK_COUNT`を1つ増やす）。**本体は`sti; hlt`のループで、落ち先をコアごとのアイドルにする。** **足さない形（落ち先のタスクがその場で`hlt`する）は採らない**——**割り込みハンドラの中で眠ることになる。**
3. **`TaskState::Waiting(Wait)`を`Blocked`と分ける。** **`Blocked`はいま2つの意味を持っている**（メインの帰り先／締切で止めたワーカー）。**混ぜると、締切で止めたワーカーをキー入力で起こす。**
4. **起こす合図は、まずキーボードだけにする。** **タイマは任意の段（W2-d）へ回す。** **I/Oはvirtioが既にBKLを解いて眠る形を持っているので触らない。**
5. **刻みは4つである。** **W2-a（アイドルタスクを足す。振る舞い不変）／W2-b（`Waiting`の欄と遷移だけ。振る舞い不変）／W2-c（`read(0)`が待つ。振る舞いが変わる）／W2-d（タイマ。任意）。**

### 上限の置き場——**本番の待ちは上限で止めない**

**「上限の無い待ちを書かない」は道具と検査の規律である**（`CLAUDE.md`。**`--full`を待つ側に上限が無くて残骸が4時間39分ぶら下がった件**）。**本番のキー待ちに持ち込まない**——**人が席を外しただけで落ちる。**

**破壊「起こさない」を観測するには上限が要る。** **置き場は2つのどちらかである。**

- **検査の構成の側に上限を置く**（featureで囲った構成だけが止まる）
- **上限に当たっても止めず、計器へ出して待ち直す**（本番にも置ける形）

**W2-cで、どちらを採るかを実装の前に決めること。**

### 破壊の下ごしらえ（W2-cで要る）

**`bkl-hold-across-hlt-test`は流用できない**（実測。2026-09-16）。**あの破壊の項目が待つのは`bkl: recursive acquisition on cpu`と`halting`で、仕込む場所はハートビートのループである**（`interrupts.rs`）——**`init`より前に走るので、同じfeatureをアイドルの`hlt`へ足しても、先にあちらが発火して新しい場所は観測されない。** **アイドルの側には別のfeatureを立てること。**

## W2-aで測ったもの（2026-09-16）

**BSP用アイドルタスクを足した。** **誰も選ばない形で入れてある**——**`pick_next`の巡回にも落ち先にも入っていない**（S4-c-2でAP用アイドルを入れたときと同じ形）。

| 何 | 前 | 後 | 差 |
|---|---|---|---|
| `SCHEDULER` | 544バイト | 648バイト | **+104**（タスク1本ぶん） |
| `FP_AREAS`（`.data`） | 2,560バイト | 3,072バイト | **+512** |
| `BSP_IDLE_STACK` | ——— | 20,480バイト | **+20,480**（ガード4,096 + 本体16,384） |
| `.bss`の合計 | 1,841,696バイト | 1,862,280バイト | **+20,584**（= 20,480 + 104） |

**「1本あたり約20.6KiB + スタック」の見込みと合った。**

### 起動ログは3行増えた——「番地だけ」ではない

**559行から562行になった。** **増えたのは3行で、どれも新しいスタックの塊が出すものである。**

- ガードページが手つかずだったことの行（`install_guard_page`）
- ガードページを`unmap`した行（同じ）
- 登録の行（`registered the bsp idle task as index 5 ... nothing picks it yet (W2-a)`）

**登録の行を消して差分を綺麗にする手は採らなかった**（運用者の承認。2026-09-16）——**登録されたことの観測が消える。**

**残りの食い違いは、全部この20,480バイトで説明できる。** **`.bss`の終わりが`0x453000`から`0x458000`へ動き**（+0x5000）、**カーネル像の終わりとヒープの入れ物と遠征スタックの番地がそれに続く。** **10進が2つ動いた**——**カーネルのページテーブルの項が4212から4217（+5ページ）、プロセスごとの監査が2834から2838（+4）。** **差の1つはガードページである**（`unmap`するので、あちらからは見えない）。

### 伏せる突き合わせの道具は、行が増える段では使えない

**`tools/boot-log-compare.py`は添字で対応を取るので、3行挿入されると以降が1行ずつずれる**——**実測で「食い違い282行」と出た。** **`diff`で行単位に分解した**（上）。**道具の側に「行が増減したら、そう言って降りる」を足すこと**（運用者の指摘。2026-09-16）。

## Alternatives Considered

- **前景を持たない1本を「前景になるまで待たせる」**——**却下。** **誰へ渡すかの政策（前面へ出す操作、持ち主が終わったときの引き継ぎ）が要る。** **利用者が居ない。**
- **前景を取り合わせる（最後に取った者が勝つ）**——**却下。** **「入力の消費者は同時に1つ」の不変条件を壊す**（`kernel/src/input.rs`）。
- **落ち先のタスクがその場で`hlt`する**——**却下。** **落ち先が選ばれるのは`schedule_switch`の中、すなわち割り込みハンドラの中である。** **そこで眠ると、BKLと割り込みの状態を持ったまま止まる。**
- **`Blocked`を使い回す**——**却下。** **起こす側が合図で引けない。** **締切で止めたワーカーをキー入力で起こす形が作れてしまう。**
- **タイマの待ちを同じ段に入れる**——**却下（W2-dへ回す）。** **最初の利用者（シェル）はキーだけで足りる。** **新しいシステムコールを足す判断を、待ちの仕組みと同じ段に混ぜない。**

## Consequences

**得るもの。**

- **シェルが回さずに待つ。** **1セッションのシステムコールが桁で落ちる見込みである**（いま1,282,916回）。
- **BSPが眠る。** **`init`が引き取った後に眠る経路が、初めて出来る。**
- **`default_task_for`の穴が塞がる**（落ち先が走行不可のタスクになる形が消える）。
- **「2本が待ち合わせる形」がW2-dで作れる**——**キーとタイマで、2本が同時に待つ。**

**失うもの・残る限界。**

- **2本のRing 3が同時にキーを待つ形は作れない**（決定1）。**持ち越しの「キーボード入力をどのタスクが受け取るか」は閉じない**——**範囲を狭めたと書く。**
- **アイドルタスクの費用**（16KiBのスタック + ガードページ + タスク1本ぶんの静的領域）。**W2-aで測る。**
- **空振りの起床を許す形になる**（離鍵などで起きて、読めずにまた待つ）。**それが正しい形である**——**条件を確かめてから眠る並びを保つ。**
- **`--full`の余裕が減る**（いま303項目・84.6分。上限120分に対して35分）。**W2-cで項目数と所要を見ること。**
