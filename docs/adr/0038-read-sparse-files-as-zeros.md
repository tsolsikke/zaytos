# 0038. 穴（sparse）のあるファイルを読めるようにする

## Status
Accepted

## Date
2026-08-19

## Context

zi-d-1で`/bin/zi`を像へ足したところ、`spawn`が起こせなかった。シェルは`zi: cannot run`を出すだけで、カーネル側のログは1行も出ない——`spawn`の像の写しループが`file_block`の`SparseBlock`で返るのが、最初のログ行より前だからである。

実測:

- `debugfs -R "stat /bin/zi"`のBLOCKSは`(0-4):50-54, (6):55`で、**ブロック5が無い**（穴）
- `zi.elf`を4096バイトずつ検査すると、**ブロック5だけが全0**である（`.bss`とページ整列の組み合わせでできた）
- 既存の6本（hello / spawn-test / ls / cat / zash / spin）は**4KiB境界に揃った全0の連なりを持たない**ので踏まなかった。**今まで出なかったのは運である**
- `common::ext2`のモジュールdocは「`mke2fs -d`は穴を作らない」と書いていたが、**この前提は誤りだった**（上の実測）

**読み手は「ext2を読める」と主張しながら、合法なext2ファイルを読めていない。** これは機能追加ではなく、主張と実装の食い違いの是正である。**穴のあるファイルはext2の正当な形で、読み出しは0を返すのが仕様である。**

## Decision

**読み側で穴を0として読む。** `block_number_of`が0を見つけたときにエラーを返すのをやめ、**`file_block`が「全0の1ブロック」を返す。** 実装は、`common`に1ブロックぶんのゼロを静的に置いて借りる形を採る（モジュールdocが挙げていた2案のうちの1つ目。**戻り値の型が変わらないので、呼び出し側5か所に手が入らない**）。

**`Ext2Error::SparseBlock`は残すが、`common::ext2`からは到達不能になる。** 穴もi_sizeの水増しも、`block_number_of`から見えるのは同じ「0の項目」で、**区別が付かない**。残す理由は`kernel/src/userland.rs`の像の写しループが防御としてこの値を構成することで（そちらも実際には到達しない）、**消すとerrnoの対応表とあちらの防御に手が入り、得るものが無い。** 区別する機序（`i_size`と`i_blocks`の照合など）は**この判断に混ぜない**——照合そのものに価値があるなら独立の正当化を持つ別の判断であり、破壊を生かすためだけに新設しない。

## 決めないこと（着手時に決める）

- **書き側の穴の扱い**（穴を作る / 穴へ書いて埋める）——使う者が来るまで作らない。いまの書き（append・truncate・create）は穴を作らない
- **二重・三重間接**——S10の宣言のまま、実装しない
- **`i_size`と`i_blocks`の照合**（上記。別の判断である）

## Alternatives Considered

- **像を作る側で穴を作らせない（build.rs）——却下。** 契約は変わらないが、**「たまたま全0のブロックを持つ実行ファイルは載せられない」という制約が暗黙に残る。** Cの移植で`.bss`を持つバイナリが増えれば、近いうちに誰かが同じ形を踏む
- **ziを小さくして穴を消す——却下。** 運任せであり、コードが伸びれば再発する。**踏んだ側を直しても、機構は直っていない**
- **戻り値を「借りたバイト列」か「長さだけの穴」かの列挙にする——却下（この段では）。** モジュールdocが挙げていたもう1案で、ゼロを静的に持たずに済むが、**呼び出し側5か所すべてに分岐が増える。** 静的なゼロ（`1024 << 6`が上限なので64KiB）の費用のほうが小さい

## Consequences

- `/bin/zi`が起こせるようになる。**Cの移植で来るバイナリも同じ形を踏まなくなる**
- **`common`に64KiBの静的なゼロが増える**（`.bss`）
- **既存の判定が2件、意味を変えた**（実測して確かめた。下の到達条件4）
- ホストテスト4本の期待が「エラー」から「全0が返る」へ変わる
- **S10の「実装しない = sparse」は、読み側について訂正される**（`docs/roadmap.md`。行は消さず状態を書き換える）

## 到達条件

1. `/bin/zi`が`spawn`で起こせること
2. **穴を持つデータファイルを像へ常設し、読み出しが全0を返すことを判定にすること。** **今回の発覚は偶然である**——ziがたまたま穴を持った。ziが伸びて穴が消えれば、**穴を読む能力は誰にも検査されない機構に戻る**。`build.rs`が`/data/sparse-hole`（中身・穴・中身の3ブロック）を置き、起動時の判定行が全0を返すことを見る。**前後のブロックに中身が在ることも同じ行で見る**——「全部0の像を読んで全部0が返った」では、穴を読めたことにならない
3. 破壊は「穴を0として読まない」形（`ext2-sparse-as-error`。従来の挙動へ戻す）。**上の判定が落ちる**
4. ホストテスト4本とcorrupt-fsの2件の期待を処置し、`--full`が緑であること。**2件は実測して処置を分けた**——ルートディレクトリの`i_size`水増しは**捕まえ方が変わっただけで残る**（全0のブロックを**ディレクトリとして**歩くので`rec_len`が0で拒まれる。実測で`DirEntryRecordTooSmall { rec_len: 0, name_len: 0 }`）。**`/etc/motd`の`i_size`水増しは成立しなくなった**——ext2において「`i_size`が割り当て済みブロックより大きい通常ファイル」は疎ファイルの定義そのもので、**壊れた像を作れていない。** 黙って消さず、理由をコードのその場所に残した

## 再訪条件

**書き側で穴を扱う必要が生じたとき**——Cの移植で疎な出力を作る道具（`lseek`で飛ばして書く形）が来たときが候補である。そのとき「穴を作る」と「穴へ書く（埋める）」を一緒に決める。
