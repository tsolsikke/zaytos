# 0052. 環境の源は`/etc/environment`で、カーネルが起動時に読む

## Status
Accepted

## Date
2026-08-31

## Context

`ADR-0041`のDecision 2は「環境はカーネルが1つ持ち、すべてのプロセスへ同じものを積む」だった。**前半（カーネルが静的な表として持つ）が、P段で成り立たなくなった。**

**`ADR-0041`は`/etc/environment`を却下している。** **理由は「書き込みが永続しないので、ファイルにしても像を建て直すことになる」であった。** **`ADR-0051`でその理由が消えた**——**書き込みは装置まで届き、再起動をまたいで残る。**

**同じ発火で3件が動く**（`docs/deferred-decisions.md`）。**環境の源 / `export`と`set` / 履歴の保存である。** **群として棚卸しし、着手順を f-1・f-2・f-3 と決めた。** **これは f-1 である。**

**運用者の提案で`/root`が加わった**（2026-08-30）。**「先にrootのログイン機能を」という提案を、「ログイン」と「rootのホーム」に切り分けた**——**要るのは後者である。** **認証は作らない**（`deferred-decisions`に行が在る。**守る対象が無い**）。**ホームを先に作ると、履歴と`profile`の置き場が決まる**——**置き場が決まらないまま持ち越しを増やさずに済む。**

## Decision

**6つ決める。**

### 1. 環境の源は`/etc/environment`である

**`ADR-0042`が`/etc`を「設定」と規約しており、「環境の源を置くならここである」と既に書いてある。** **その行をそのまま使う。**

**形は1行1つの`NAME=VALUE`である。** **空行と`#`で始まる行は無視する**（慣行）。

### 2. 読むのはカーネルで、時点は像の複製の直後・最初のRing 3の前

**窓は実測で挟まっている**（`kernel/src/main.rs`。2026-08-31）。**像の複製が1713行、最初のRing 3プログラムが1809行で、この間に読む。**

**`init`が読む形は採らない**——**`init`はRing 3なので、`init`自身の環境を誰が積むのかという鶏卵になる。**

**置き場が主張を決める。** **P-eで像の検査を1つ後ろに置いていたために`exercise`が書き換えた後を見ていた、という族と同じである。** **動かすときは何が変わるかを見ること。**

### 3. 無いとき・壊れているときは既定へ落ちる。**読めた行だけ使う**

**3段に分ける。**

- **ファイルが無い・開けない**——**既定へ落ちる。止めない。** **既定はいまの定数と同じである。** **理由は、利用者が`rm /etc/environment`を打てることである**——**そこで止まる形は、P-cで踏んだ「利用者の普通の操作でカーネルが止まる」と同じである。**
- **行が壊れている**——**その行だけ落とす。** **「1行でも壊れていたら全部捨てる」は採らない**（下のAlternatives）。**壊れの形は3つで、どれもその行を落とす**——**`=`が無い / 名前が空 / 名前に使えない字が在る / 行が`ENV_LINE_MAX`を超える。**
- **本数が`MAX_ENVP`を超える**——**先頭から採り、残りを落とす。** **拒んで既定へ落ちる形は採らない**——**1行足しただけで全部消えるのは驚きが大きい。**

**落とした行は必ずシリアルへ出す。黙って落とさない。**

### 4. 判定は落とす前を見る

**出す行を2本に分ける**——**読めた本数と落とした本数・理由が1本、積む中身が1本である。**

**判定は前者を見る。** **後者だけを見ると、「ファイルから読めた」と「無くて既定へ落ちた」が同じ値になる。**

**EVの前例と同じ形である**（`kernel/userland/userlib.rs`の`WindowSize::or_default`。**「判定は落とす前の値を見る——落とした後を見ると、訊けた場合と落ちた場合が同じ値になる」**）。

### 5. `/root`を作り、`HOME=/root`を最初の中身に加える

**`ADR-0042`の表へ`/root`の行を足す**（**FHSでは`/root`が`root`のホーム、`/home`が一般利用者で、別物である**）。**`/home`の「作らない」は変えない。**

**`ADR-0041`のDecision 3（最初の中身は`TERM`だけにする）との関係を書く。** **あの決定の理由は「読む者が居ないものを積まない」で、`PS1`と`KEYMAP`を外した。** **`HOME`には読む者が居る**——**同じ段でシェルが`~`を展開する**（`ADR-0049`のAddendum）。**したがってDecision 3の原則を破らない。** **原則のほうを引き継ぐ**——**このADRで積むのは`TERM`・`PATH`・`HOME`の3つで、どれも読む者が同じ段に居る。**

**認証は作らない。** **権限の判定も作らない**（`deferred-decisions`に行が在る）。**`/root`はいま「ホームという置き場」だけを意味する。**

### 6. 全プロセスへ同じものを積むのは変えない

**`ADR-0041`のDecision 2の後半は生きる。** **面（ユーザーポインタの数）を増やさない。** **プロセスごとに違う環境を持つのは f-2 の話である。**

## 決めないこと

- **`export`と`set`**——**f-2である。** **`ADR-0041`のDecision 2の後半が変わり、面も変わる。**
- **`/etc/profile`と`~/.profile`**——**f-2の後である。** **両方持つかも、そのときに決める。**
- **書き戻し**——**カーネルは`/etc/environment`を読むだけで、書かない。** **書くのは利用者（`zi`）である。**
- **キーボード配列の選択**——**同じ口で解くが、同じ段では解かない**（下のAlternatives）。**f-1bで`KEYMAP`として作る。**

## Alternatives Considered

- **`init`が読む——却下。** **`init`はRing 3で、自分の環境を誰が積むのかという鶏卵になる**（Decision 2）。
- **1行でも壊れていたら全部捨てる——却下。** **理由は2つ。** **編集の失敗で全部失うほうが害が大きい。** **そして「全部捨てる」は「ファイルが無い」と同じ結果になり、両者が区別できない**（緑の4形の「状態が変わらない」に当たる）。
- **本数が上限を超えたら拒んで既定へ落ちる——却下**（Decision 3）。
- **キーボード配列の選択を同じ段で解く——却下。** **1つの段で2つの主張を立てると、落ちたときにどちらが壊れたか分からない。** **f-1bとして、この口の上に別に立てる**（運用者の決定。2026-08-31。**US配列に対応すると決まった**）。**表は既に2組ある**（実測。`kernel/src/keyboard/decode.rs`の`#[cfg]`の分岐を数えた）——**無いのは実行時に選ぶ手段だけである。**
- **`ADR-0041`を丸ごとSupersededにする——却下。** **変わるのはDecision 2の前半だけで、Decision 1・3・4・5は生きている。** **`ADR-0037`で作った前例（Decisionを1つだけ打ち消して指す）を使う。**
- **認証を作る——却下**（`deferred-decisions`に行が在る。**守る対象が無い**）。
- **履歴を`/var`へ置く——却下。** **一度そう決めたが、`/root`を先に作るほうが安いと分かって覆した**（2026-08-31）。

## Consequences

- **運用者が環境を変えられるようになる。** **`ADR-0043`のDecision 4が「`PATH`はいま固定の既定と同じくらい固定である。承知のうえで採る」と書いていたが、その但し書きが要らなくなる。**
- **`zi`で`/etc/environment`を壊すと、次の起動が既定へ落ちる。** **止まらない。** **落ちたことはシリアルに出る。**
- **`/root`ができる。** **履歴と`profile`の置き場が決まる**——**`/root/.zash_history`と`~/.profile`である。**
- **`~`の展開が要る。** **`ADR-0049`（シェルは行を語へ切る前に`$NAME`を展開する）の族なので、あちらのAddendumで足す。**
- **持ち越しの2度起こす項目が3つ目になる。** **「1度目に`/etc/environment`を書き換え、2度目に効く」が、源がファイルであることの最も強い主張だからである。**
