# ZaytOS ロードマップ

マイルストーンの現在地を管理する。細く長く進める前提のため、
各段階は「ここで中断しても死なない」区切りになるよう意識する。

M6 より先の興味の方向は `vision.md` に別途書いてある。**あちらは構想であって
決定ではなく、現在の設計判断を縛らない。** 先回りの抽象化の根拠にはならない。

## M2. メモリ管理の基礎 [x]

M2-0a〜M2-0c で bootloader/kernel 分離（ADR-0008）と ELF ローダーを実装した
結果、当初の「UEFI メモリマップ取得」「ExitBootServices」は M2-0c の中で
実質的に完了している。以降は M2-c（自前ページテーブル構築）・M2-d
（物理フレームアロケータ）の**実装順序を入れ替えている**: ページテーブルを
構築するにはページテーブル自身を置く物理フレームが必要であり、それを
供給するのがフレームアロケータであるため、フレームアロケータを先に
実装しなければ成立しない。

- [x] M2-0a: crate 再編（`kernel` → `bootloader` へ改名、`serial`/`log`/`cpu`
  を `common` クレートへ共有化、ADR-0008）
- [x] M2-0b: kernel クレート新規作成（`x86_64-unknown-none` + リンカスクリプト、
  最小カーネル。リンクアドレスは ADR-0009）
- [x] M2-0c: ELF ローダー実装（bootloader が kernel.elf をロードし、GOP
  フレームバッファ情報取得 → ExitBootServices → BootInfo 経由で kernel へ
  ジャンプ。UEFI メモリマップ取得・ExitBootServices はここに含まれる）
- [x] M2-a: UEFI メモリマップ取得（M2-0c で完了。`BootInfo.memory_map` 経由で
  kernel へ引き渡し、内容をシリアルへログ出力済み）
- [x] M2-b: ExitBootServices 実行（M2-0c で完了。以降もシリアルログが生存
  することを確認済み）
- [x] M2-c: 物理フレームアロケータ（`BootInfo` のメモリマップを解析し、
  空き物理フレームを管理。範囲リスト方式、ADR-0011）。「空き」の判定は
  `EfiConventionalMemory` のみとし、`EfiBootServicesCode`/`Data` は
  ADR-0010 により当面除外。kernel 本体・`BootInfo`・メモリマップバッファ
  は予約済みとして除外する。ロジックはホスト `cargo test` で検証済み
- [x] M2-d: 自前ページテーブル構築（M2-c のフレームアロケータから物理

## M4. 割り込み [x]

**着手前に `docs/deferred-decisions.md` の「M4 で解禁・見直しになるもの」を
通しで読むこと。** M4 は複数の保留項目の解禁条件を同時に満たす節目であり、
一覧を見ないと解禁できる状態に気づかないまま進むことになる。

設計は ADR-0018。**`sti` は M4-d の 1 箇所だけで行い、その時点で下の層が
すべて実機検証済みになる**よう下から積む。例外は `IF` に関係なく発生するため、
IDT と例外ハンドラは割り込みを有効化しないまま検証しきれる。

- [x] M4-a: GDT / TSS / 自前カーネルスタック（`.bss` の静的領域。通常 64KiB、
  ダブルフォルト用 IST1 が 16KiB）。切り替え後の RSP・ローカル変数の位置・
  旧スタック不参照・読み書き・カナリアを実機で検証済み
- [x] M4-b: IDT / 例外ハンドラ / 例外時の GPR フルダンプ
  - [x] M4-b-1: IDT エントリの符号化、全 256 ベクタへの割り込みゲート、
    `lidt`/`sidt` の読み戻し検証、`--exception-test divide-by-zero` と
    `invalid-opcode`（シリアルと `-d int` の突き合わせ）
  - [x] M4-b-2: GPR フルダンプ、CR2、エラーコードの解釈、IST を使う
    ダブルフォルト（`--exception-test page-fault` / `double-fault`）。
    GPR の並び順は既知値 15 個で実値検証。ダブルフォルトは #PF ゲートの
    Present ビットを落として誘発し、IST1 の使用と CPU Reset 非増加を確認
- [x] M4-c: クリティカルセクション、`Locked<T>` の差し替え、PIC 再マップ
  - [x] M4-c-1: `InterruptGuard`（RAII の `cli`/`sti`）。入れ子でも余計に
    有効化しないこと、Drop で元の状態へ戻ることを実機の RFLAGS で確認
  - [x] M4-c-2: `Locked<T>` を `common::critical` へ移し、取得中だけ割り込みを
    禁止する形に差し替え。前提が「割り込み常時禁止」から「取得中は割り込み
    禁止」に変わった（ADR-0012 Addendum）。二重取得検出つき
    （`--critical-test double-lock`）
  - [x] M4-c-3: PIC を 0x20-0x2F へ再マップし、全 IRQ をマスク。再マップ前の
    IMR を記録し、再マップ後は IMR を読み戻して照合する。**ベクタオフセット
    自体は ICW2 が書き込み専用のため検証できず、M4-d で最初のタイマ割り込みが
    ベクタ 0x20 で届くまで未検証のまま持ち越す**（ADR-0018 Addendum）。
    IF=1 から入る復元経路もここで確認済み（`--critical-test restore-enabled`）
- [x] M4-d: タイマ割り込み（**PIT**。ここで初めて `sti`）。APIC は ACPI を
  辿る必要があり、切り分け軸が増えるため M4 の範囲外とする。
  「`sti` すること」と「割り込みが実際に来ること」を別々に検証するため
  2 段階に分けた
  - [x] M4-d-1: `sti` できる状態を作る（タイマは動かさない）。IRQ 用の
    復帰経路（GPR 退避・復元 + `iretq`、例外経路とは独立）、DS/SS の
    読み戻し、`sti` 前 7 項目の実行時検証と fail-fast、全 IRQ をマスクした
    ままの `sti`。スタックの 16 バイト境界は実測値で検証し、わざと外して
    両経路で発火することを確認済み（ADR-0018 Addendum 2）
  - [x] M4-d-2: タイマを動かす。PIT を 100Hz（分周値 11932、実周波数
    99.998Hz）で設定し、IRQ0 を解禁して EOI を発行する。ADR-0018 §2 の
    項目 4（PIC のベクタオフセット）と項目 7（EOI）が Verified へ移った。
    前者は最初のティックがベクタ 0x20 で届いたことと `alt-offset-test`
    （0x30-0x3F へ再マップしても追随すること）で、後者はティックが増え
    続けることと `no-eoi-test`（落とすと 1 回で止まること）で証明した。
    スプリアス割り込みの判定も実装（純粋ロジックはホストテストで固定）。
    **通常起動でタイマが動くため、カーネルは停止しなくなった。**
    到達点の目印は `kernel: halting` から「最初のティックがベクタ 0x20 で
    届いた」行へ変えた
- [x] M4-e: キーボード割り込み（PS/2、IRQ1）。i8042 のコンフィグバイトを
  読んで翻訳（セット 1）と割り込みが有効かを確認してから解禁する。ハンドラは
  リングバッファへ積むだけで、**バッファが満杯でもデータポートは必ず読む**
  （読まないと以後の IRQ1 が来ず、症状が EOI 忘れと区別できなくなる）。
  変換は純粋ロジックとしてホストテストで固定。エコーはメインループが行う。
  `cargo xtask run --interrupt-test keyboard` で monitor の `sendkey` により
  自動検証する（キーリピートだけは `sendkey` が模擬しないため手動確認）

## M5. マルチタスク（プリエンプティブ）

段階分割と方式は ADR-0019。ページング拡張を先頭に置いて下から積む。
途中に `PhysAddr`/`VirtAddr` の型分離と higher-half 移行（ADR-0009 の
見直し。物理メモリへのアクセスは ADR-0021 の direct physical map）を挟む。
システムコールのレジスタ規約は ADR-0020 で決定済み。

- [~] M5-a: `PageTableBuilder` のページ分割・アンマップ対応
  - [x] M5-a-1: エントリのビット操作を `paging::entry` へ分離（2MiB と 4KiB で
    位置が違う PAT の移送を含む。ホストテストで固定）。稼働中テーブルの
    読み戻し（`paging::active`）を実装し、起動時に計画と突き合わせる。
    CR4.PGE が無効で G ビットも未使用のため、CR3 リロードで TLB を全部
    追い出せることを実測で確認

## 中断可能な区切り
- **M1 到達**で「何か画面に映る + ログが取れる」状態になり、
  他プロジェクトにリソースが移っても死なないプロジェクトになる。
- 以降は各 M 単位で区切り、到達ごとに ADR とロードマップを更新する。

## スコープ外（ロードマップに載せない）
SMP / 他アーキテクチャ移植 / 動的モジュール / 独自 FS / ネットワーク。
着手する場合はまず ADR で方針を決めてから。

このうちいくつかは `vision.md` に「その先の構想」として挙げてあるが、
**構想に挙がっていることと、着手が決まっていることは別である。**
ロードマップに載っていないものは、今は手を出さない。
