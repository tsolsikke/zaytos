## M4. 割り込み [x]

着手前に`docs/deferred-decisions.md`の「M4で解禁・見直しになるもの」を通しで読むこと。
M4は複数の保留項目の解禁条件を同時に満たす節目であり、一覧を見ないと解禁できる状態に気づかないまま進むことになる。

設計はADR-0018。
`sti`はM4-dの1箇所だけで行い、その時点で下の層がすべて実機検証済みになるよう下から積む。
例外は`IF`に関係なく発生するため、IDTと例外ハンドラは割り込みを有効化しないまま検証しきれる。

- [x] M4-b: IDT / 例外ハンドラ / 例外時のGPRフルダンプ
  - [x] M4-b-1: IDTエントリの符号化、全256ベクタへの割り込みゲート、`lidt`/`sidt`の読み戻し検証、`--exception-test divide-by-zero`と`invalid-opcode`（シリアルと`-d int`の突き合わせ）
  - [x] M4-b-2: GPRフルダンプ、CR2、エラーコードの解釈、ISTを使うダブルフォルト（`--exception-test page-fault` / `double-fault`）。GPRの並び順は既知値15個で実値検証。ダブルフォルトは #PFゲートのPresentビットを落として誘発し、IST1の使用とCPU Reset非増加を確認
- [x] M4-c: クリティカルセクション、`Locked<T>`の差し替え、PIC再マップ
  - [x] M4-c-1: `InterruptGuard`（RAIIの`cli`/`sti`）。入れ子でも余計に有効化しないこと、Dropで元の状態へ戻ることを実機のRFLAGSで確認
  - [x] M4-c-2: `Locked<T>`を`common::critical`へ移し、取得中だけ割り込みを禁止する形に差し替え。前提が「割り込み常時禁止」から「取得中は割り込み禁止」に変わった（ADR-0012 Addendum）。二重取得検出つき（`--critical-test double-lock`）

  - [x] M4-d-1: `sti`できる状態を作る（タイマは動かさない）。IRQ用の復帰経路（GPR退避・復元 + `iretq`、例外経路とは独立）、DS/SSの読み戻し、`sti`前7項目の実行時検証とfail-fast、全IRQをマスクしたままの`sti`。スタックの16バイト境界は実測値で検証し、わざと外して両経路で発火することを確認済み（ADR-0018 Addendum 2）

## その先（S0からS13の段階列）

臨界経路「ストレージ → ファイルシステム → exec → ユーザーランド」を意識し、基本設計までをロードマップに置く。

**順序はS0からS13で確定している。** かつてこの節は「基本設計を置く場であって番号どおりの実行順ではない」と書いていたが、長期方針を実コードと照合して依存関係を洗い出し、順序を決めた。各段は「振る舞い不変の準備を積んでから危険な一手を打つ」形に分けてある（higher-half Bで採った形）。M5-f-3（プロセス別アドレス空間）はS7として、この列の中に位置づける。

各段に「到達条件」と「その段階では実装しないもの」を書く。細かい実装分割は着手時に決める（ADR-0022 / ADR-0023 / ADR-0025）。

### SMP（BKLファースト。ADR-0023）

- [x] **S0-a. seam整備**（先行。振る舞い不変。ADR-0023 §3の3項目）: 項目3（per-CPUアクセサ）= 3a器の導入 / 3b入れ子深さ / 3c GDT・TSS / 3d現在タスク。項目2（排他の監査）= 直接`cli`/`sti`を許可リスト方式の静的検査で固定（許可エントリ数と出現数は`cargo xtask check`が毎回印字する。いずれも排他目的ではない。ただしasm内の`GPR_BUF`保護のみ例外で、S3-aで扱う）。項目1（割り込み層の境界）= `kernel/src/irq/`へ`pic`/`pit`を集約し、呼び出し側を問いと観測値のAPIへ寄せ、内部を非公開にしたうえで、可視性を静的検査で固定した（1aから1d）。**到達条件は満たした**: `pic`/`pit`への参照は境界の外に無く、外から触るとビルドが落ちる。その保証が外されないことを検査が守る。`--full`が緑。実装しなかったもの=APIC、IPI、trait化（実装が2つになるまではモジュール集約でよい。traitはS2で切る）
- [x] **S0-b. `SCHEDULER`の別名違反の解消**（振る舞い不変。単独の段。**seam整備（ADR-0023 §3）の3項目には含まれない別作業である**。番号がS0-aに続くのは実施順が隣り合うためで、seam整備の4項目目ではない）: 2つの`&mut Scheduler`が同一コア上で並行しうる現在のUBを解消した。実体を`kernel/src/task/scheduler.rs`へ移し、外へはフィールド単位の操作だけを出したので、構造体全体への参照はモジュールの外から書けない（コンパイラが保証する。`static_mut_refs` lintでは解けないことを実測で確認した）。書き手と読み手が並行する3つのフィールド（`iterations` / `resumes` / `switches`）を`volatile`にした（それまでは素の読みで、たまたま動いていた）。**到達条件は満たした**: `&mut Scheduler` / `&Scheduler`を作る箇所が0、`--full`が緑、`task-test`6種が緑、起動ログの会計判定行が不変。実装しなかったもの=`Scheduler`の分解、`Locked<Scheduler>`化（S4）、`TIMER_TICKS`や`GPR_BUF`のper-CPU化（S3）
- [ ] **S1. SMPの下ごしらえ**（単一コアのまま。APは起こさない）: bootloaderがRSDPの物理アドレスを`BootInfo`へ載せる。`BOOT_INFO_VERSION`のbumpを伴う（ExitBootServices後はUEFIのconfiguration tableを引けないので、渡せるのはbootloaderだけである）。ACPIテーブル領域をマッピング計画へ足す。direct mapは`classify()`が通した範囲だけを写すので、ACPI・Local APIC・IO-APICの領域は現在マップされていない。MADTを解析してLocal APIC IDを列挙しログへ出す。APトランポリン用フレームの確保方式を決めて実装する。**ACPIテーブル用の一時マッピングは不要と結論した**（テーブルが載る記述子の型がマップ対象であり、型が変われば実行時の`translate`チェックが検出する。`verification-coverage.md`の「ACPIテーブルへ触る前提」）。到達条件=単一コアで`--full`が緑、`-smp 2`で起動しても列挙結果がQEMUの指定と一致すること、トランポリン用フレームが1MiB未満であることを起動時に検証してログへ出すこと。実装しない=AP起こし、APIC移行、BKL、IPI
- [ ] **S2. Local APIC / IO-APICへの移行**（単一コアのまま）: S0-aの境界の裏でPIC/PITからLocal APICタイマとIO-APICへ差し替える。到達条件=既存のinterrupt-test一式が緑、PICを無効化した状態でタイマとキーボードが動くこと。実装しない=AP、IPI、`TIMER_TICKS`のper-CPU化（方針が見えるのはS3）
- [ ] **S3. AP起こし**（APは起きて待つだけ。BKLはまだ無い）: S3-a（振る舞い不変の準備）=`GPR_BUF`の排他をper-CPUへ移す / タスクの状態を`runnable: bool`から状態機械（Ready・Running(cpu)・Blocked・Finished）へ広げる（単一コアで等価に導入できる）。S3-b=AP用一時ページテーブル / INIT-SIPI-SIPI / per-CPUスタック・GS・GDT・TSS・IDTR / `cpu_id()`の実装と`MAX_CPUS > 1`。**`smp::trampoline_frame()`が実際に読まれること**（S1では誰も呼ばず、`pub`だから`dead_code`にならないだけである。読み忘れても気づけないので到達条件に入れる）。**S1で先送りした2件をここで致命へ格上げする**: トランポリン用フレームの予約失敗（S1では検出して報告し継続する。APを起こすこの段では起動できない）と、**トランポリンが1ページに収まらない場合の隣接ページの確保**（S1は1枚しか予約せず、隣が空いている保証も与えない）。到達条件=`-smp 2`と`4`で全APが起動署名を出すこと、カーネルCR3に`PML4[0]`が無いことをAP側でも読み戻すこと、per-CPUスロットの会計が起きたコア数と一致すること、`deferred-decisions.md`の「`MAX_CPUS > 1`で顕在化する前提」が全て閉じていること、**asmから自コアのper-CPUスロットを選べること**（S3-aの`GPR_BUF`のper-CPU化は`MAX_CPUS = 1`でスロット0が固定オフセットになるから振る舞い不変で済むのであって、asmは`cpu_id()`も`this_cpu_ptr`も呼べない。APが自分のスロットを選ぶ手段はS3-bで用意する）。実装しない=BKL、APでのタスク実行、IPI、TLBシュートダウン
- [ ] **S4. BKL本体**: BKLの取得と解放を入れる（カーネル入口で取りRing 3復帰で離す）。カーネル入口を分類する（syscall・IRQ・例外・ダブルフォルト・パニック・AP起動直後）。`Locked<T>`の中身をスピンロック併用へ差し替える。APをスケジューラへ参加させる。**危険の形が恒等除去とは違う。** 恒等除去は真に不可逆なので復帰経路（書き戻してhalt）を用意したが、BKLはcfgで切れるし失敗しても再起動できる。危険は「デッドロックして静かに止まる」ことなので、前段に要るのは復帰可能性ではなく進行性の観測である。到達条件=カーネル内の同時進入数が1であることの実測、全コアが進行していることの実測（コアごとのハートビート）、デッドロック時にタイムアウトして原因を出すこと、`-smp 1`と`2`と`4`で緑、ある入口でBKLを取らないと同時進入が2になることの実証。実装しない=細粒度ロック、IPI、TLBシュートダウン、NUMA、負荷分散
- [ ] **S5. IPIとTLBシュートダウン**: BKL取得待ちのIF=0とIPIのデッドロックを構造的に避ける方式を選ぶ（`deferred-decisions.md`に4案）。世代番号による要求の識別、完了通知、タイムアウト、全対象コアの完了前に物理フレームを再利用しないこと。到達条件=リモート無効化を意図的に省く破壊で検査が落ちること、`-smp 2`と`4`で緑、タイムアウトが無言で継続しないこと。実装しない=`AddressSpace`単位のシュートダウン（この段の対象はカーネル領域と仮想アドレス指定に限る。使用中CPU集合はS7で設計する）
- [ ] **S6. SMPの安定化**: 機能を足さず、反復・長時間・異なるコア数・意図的破壊で、デッドロック・競合・停止・会計不一致を洗う。到達条件=S4とS5の破壊featureがすべて意図どおりに落ちること、通常構成が長時間緑であること
- フル細粒度SMP（性能向上）はロードマップに載せず`vision.md`（長期目標）に据え置く

### ユーザーランドとファイルシステム（M5-f-3とM6）

- [ ] **S7. プロセス別アドレス空間**（M5-f-3。ADR-0022。上のM5-f-3節はここへのポインタである）: 下位を差し替え上位=カーネルを共有する。M5-eの暫定配置（`PML4[1]`=512GiB）を通常の低位へ広げる。フレームアロケータの容量とデータ構造の見直しは、この中でプロセスの生成と破棄を実装する直前に行う。`user_range_accessible`と`copy_from_user`のレイアウト・構造条件依存の再評価も含む（`verification-coverage.md`）。到達条件=プロセスAとBの同じ仮想アドレスが異なる物理ページを指すこと、Aの書き込みがBから見えないこと、ユーザーからカーネル領域へアクセスできないこと、CR3切り替え後もカーネルが動くこと、`AddressSpace`破棄後に古いTLBでアクセスできないこと、稼働中テーブルの共有カーネル部分が一致すること。実装しない=fork、Copy-on-Write、共有メモリ、複数スレッド
- [ ] **S8. ユーザー例外の区別**: Ring 0の致命的例外は従来どおりfail-fastで停止し、Ring 3の通常の違反は該当プロセスだけを終了してカーネルは継続する。現在はRing 3由来の違反でもカーネルが止まるので、S9の前提になる。到達条件=Ring 3の #PF・#UD・#GP・#DEでプロセスだけが終了しカーネルが継続すること、Ring 0の同じ例外はfail-fastのままであること、例外フレーム自体が壊れている場合にカーネル停止を選べること。実装しない=シグナル、コアダンプ
- [ ] **S9. 埋め込みELFからのユーザープログラム起動**: ファイルシステムに依存せず、ELFローダー・アドレス空間・Ring 3遷移を検証する。対応範囲はELF64・x86_64・静的リンク・非PIE・`PT_LOAD`のみ。**ユーザーELFの読み込みは、いかなる入力に対してもカーネルをfail-fastさせず、プロセスを終了させるエラーを返す**（`common::elf`は信頼済みの`kernel.elf`向けで境界検査を持たない箇所がある。共有はパース骨格までとする）。到達条件=hello・syscall-test・fault-testが動くこと、壊したELFでカーネルが止まらずプロセスだけが失敗すること。実装しない=動的リンク、共有ライブラリ、PIE
- [ ] **S10. RAM上のext2読み取りと最小VFS**（ADR-0025）: `BlockDevice`から`RamBlockDevice`を介してext2イメージを読む。VFSはext2を最初の実装として、実際に必要になった操作から最小の共通境界を抽出する。ファイル関連syscall（open・read・close・stat・readdir相当）を足す。薄いVFSトレイト境界を先に引くかは未決（`deferred-decisions.md`）。着手前に決めること=ヒープの方針（現在1MiB固定で拡張機構が無い。ADR-0012）とイメージの持ち方（カーネルへ埋め込むか、bootloaderが別モジュールとして読むか）。到達条件=`mke2fs`で作ったイメージを読めること、壊したイメージでカーネルメモリを壊さずエラーを返すこと、パーサのホストテスト。実装しない=書き込み、double/triple indirect、symlink、拡張属性
- [ ] **S11. initと簡易シェル**: 到達条件=シェルから`ls`と`cat /etc/motd`と`/bin/hello`を実行できること。実装しない=POSIX互換、Linux syscall ABI互換、ジョブ制御
- [ ] **S12. ext2書き込み**: bitmap・割り当て・作成・書き込み・mkdir・unlink・rmdir・truncateを段階的に足し、各段でメタデータの会計を閉じる。Linux側（`e2fsck`とマウント）を独立検証器に使うため、RAM上のイメージをホストへ取り出す手段が要る（xtaskは既にQEMUのmonitorを駆動しているので`memsave`が素直）。到達条件=ZaytOSが書いたイメージを`e2fsck`が無傷と判定し、Linuxでマウントして内容とディレクトリ構造が読めること。実装しない=ジャーナリング、電源断耐性
- [ ] **S13. 永続ブロックストレージ**: 一次案はvirtio-blk（QEMU前提で最も素直。確定は着手時判断）。実ストレージではI/O待ちが出るので、BKLを保持したままI/O完了を待たない設計が要る（wait queue、Blocked状態、割り込みによる完了通知）。DMAのため、フレームアロケータに物理連続確保と物理アドレス取得の能力が要る（direct map窓でphys↔virt変換の土台は整っている）。到達条件=実ストレージ上のext2を読み書きできること、ストレージIRQハンドラとBKL保持タスクが循環待ちを作らないこと

### GUI（M6完了後の独立マイルストーン）

粒度は粗いままにする。
カーネル側の責務はフレームバッファへの安全なアクセス・入力イベント・マウス・最小限の共有メモリとIPCまでとし、ウィンドウサーバー・コンポジタ・GUIライブラリ・TTFラスタライズはユーザー空間へ置くことを第一候補とする。
最終判断はM6完了時点のIPCと共有メモリの設計を見てから行う。
カーネルコンソールは起動ログ・診断・パニックのために残し、GUI描画と責務を混ぜない（コンソールのフォントは現行のGNU Unifontのままとする）。
最初のGUIアプリは依存の少ないものから進める（電卓・テキストビューア・簡易エディタ・ファイルマネージャ・ターミナルエミュレータの順が候補）。
ターミナルエミュレータは標準入出力とPTY相当を必要とするので、最初のシェル（S11）はGUIを待たず既存コンソール上で動かす。
