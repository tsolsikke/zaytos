あちらは構想であって決定ではなく、現在の設計判断を縛らない。

## M2. メモリ管理の基礎 [x]

M2-0a〜M2-0cでbootloader/kernel分離（ADR-0008）とELFローダーを実装した結果、当初の「UEFIメモリマップ取得」「ExitBootServices」はM2-0cの中で実質的に完了している。
以降はM2-c（自前ページテーブル構築）・M2-d（物理フレームアロケータ）の**実装順序を入れ替えている**: ページテーブルを構築するにはページテーブル自身を置く物理フレームが必要であり、それを供給するのがフレームアロケータであるため、フレームアロケータを先に実装しなければ成立しない。

## M4. 割り込み [x]

着手前に`docs/deferred-decisions.md`の「M4で解禁・見直しになるもの」を通しで読むこと。
M4は複数の保留項目の解禁条件を同時に満たす節目であり、一覧を見ないと解禁できる状態に気づかないまま進むことになる。

設計はADR-0018。
`sti`はM4-dの1箇所だけで行い、その時点で下の層がすべて実機検証済みになるよう下から積む。
例外は`IF`に関係なく発生するため、IDTと例外ハンドラは割り込みを有効化しないまま検証しきれる。

- [x] M4-a: GDT / TSS / 自前カーネルスタック（`.bss`の静的領域。通常64KiB、ダブルフォルト用IST1が16KiB）。切り替え後のRSP・ローカル変数の位置・旧スタック不参照・読み書き・カナリアを実機で検証済み
- [x] M4-b: IDT / 例外ハンドラ / 例外時のGPRフルダンプ
  - [x] M4-b-1: IDTエントリの符号化、全256ベクタへの割り込みゲート、`lidt`/`sidt`の読み戻し検証、`--exception-test divide-by-zero`と`invalid-opcode`（シリアルと`-d int`の突き合わせ）
  - [x] M4-b-2: GPRフルダンプ、CR2、エラーコードの解釈、ISTを使うダブルフォルト（`--exception-test page-fault` / `double-fault`）。GPRの並び順は既知値15個で実値検証。ダブルフォルトは #PFゲートのPresentビットを落として誘発し、IST1の使用とCPU Reset非増加を確認
- [x] M4-c: クリティカルセクション、`Locked<T>`の差し替え、PIC再マップ
  - [x] M4-c-1: `InterruptGuard`（RAIIの`cli`/`sti`）。入れ子でも余計に有効化しないこと、Dropで元の状態へ戻ることを実機のRFLAGSで確認
  - [x] M4-c-2: `Locked<T>`を`common::critical`へ移し、取得中だけ割り込みを禁止する形に差し替え。前提が「割り込み常時禁止」から「取得中は割り込み禁止」に変わった（ADR-0012 Addendum）。二重取得検出つき（`--critical-test double-lock`）
  - [x] M4-c-3: PICを0x20-0x2Fへ再マップし、全IRQをマスク。再マップ前のIMRを記録し、再マップ後はIMRを読み戻して照合する。ベクタオフセット自体はICW2が書き込み専用のため検証できず、M4-dで最初のタイマ割り込みがベクタ0x20で届くまで未検証のまま持ち越す（ADR-0018 Addendum）。IF=1から入る復元経路もここで確認済み（`--critical-test restore-enabled`）
- [x] M4-d: タイマ割り込み（**PIT**。ここで初めて`sti`）。APICはACPIを辿る必要があり、切り分け軸が増えるためM4の範囲外とする。「`sti`すること」と「割り込みが実際に来ること」を別々に検証するため2段階に分けた
  - [x] M4-d-1: `sti`できる状態を作る（タイマは動かさない）。IRQ用の復帰経路（GPR退避・復元 + `iretq`、例外経路とは独立）、DS/SSの読み戻し、`sti`前7項目の実行時検証とfail-fast、全IRQをマスクしたままの`sti`。スタックの16バイト境界は実測値で検証し、わざと外して両経路で発火することを確認済み（ADR-0018 Addendum 2）
  - [x] M4-d-2: タイマを動かす。PITを100Hz（分周値11932、実周波数99.998Hz）で設定し、IRQ0を解禁してEOIを発行する。ADR-0018 §2の項目4（PICのベクタオフセット）と項目7（EOI）がVerifiedへ移った。前者は最初のティックがベクタ0x20で届いたことと`alt-offset-test`（0x30-0x3Fへ再マップしても追随すること）で、後者はティックが増え続けることと`no-eoi-test`（落とすと1回で止まること）で証明した。スプリアス割り込みの判定も実装（純粋ロジックはホストテストで固定）。通常起動でタイマが動くため、カーネルは停止しなくなった。到達点の目印は`kernel: halting`から「最初のティックがベクタ0x20で届いた」行へ変えた
- [x] M4-e: キーボード割り込み（PS/2、IRQ1）。i8042のコンフィグバイトを読んで翻訳（セット1）と割り込みが有効かを確認してから解禁する。ハンドラはリングバッファへ積むだけで、**バッファが満杯でもデータポートは必ず読む** （読まないと以後のIRQ1が来ず、症状がEOI忘れと区別できなくなる）。変換は純粋ロジックとしてホストテストで固定。エコーはメインループが行う。`cargo xtask run --interrupt-test keyboard`でmonitorの`sendkey`により自動検証する（キーリピートだけは`sendkey`が模擬しないため手動確認）

途中に`PhysAddr`/`VirtAddr`の型分離とhigher-half移行（ADR-0009の見直し。
物理メモリへのアクセスはADR-0021のdirect physical map）を挟む。
システムコールのレジスタ規約はADR-0020で決定済み。

- [x] M5-a: `PageTableBuilder`のページ分割・アンマップ対応
  - [x] M5-a-1: エントリのビット操作を`paging::entry`へ分離（2MiBと4KiBで位置が違うPATの移送を含む。ホストテストで固定）。稼働中テーブルの読み戻し（`paging::active`）を実装し、起動時に計画と突き合わせる。CR4.PGEが無効でGビットも未使用のため、CR3リロードでTLBを全部追い出せることを実測で確認
  - [x] M5-a-2: 2MiBページの分割・アンマップ・TLB無効化
    - [x] M5-a-2-1: `split_huge_page` / `unmap_4kib` と、影響のない領域での一巡。分割はPTを確保・512エントリを書いてからPDエントリを8バイト1回で差し替え、CR3リロードでTLBを落とす。アンマップは`invlpg`。物理フレームもPTも解放しない。操作全体を`InterruptGuard`で囲む。照合は`split_child_entry`と同じ式では行わず`translate()`経由で行う。対象はフレームアロケータから確保した2MiB境界の未使用領域（2MiBを恒久的に予約する）

- [x] 型分離: `PhysAddr` / `VirtAddr`（恒等マッピングのまま導入し、取り違えをコンパイルエラーにする。higher-half移行で触るべき箇所をコンパイラに列挙させるための布石。T-1からT-4、H-1、H-2で完了）

## 中断可能な区切り
- **M1到達**で「何か画面に映る + ログが取れる」状態になり、他プロジェクトにリソースが移っても死なないプロジェクトになる。
- 以降は各M単位で区切り、到達ごとにADRとロードマップを更新する。

## スコープ外（ロードマップに載せない）
SMP / 他アーキテクチャ移植 / 動的モジュール / 独自FS / ネットワーク。
着手する場合はまずADRで方針を決めてから。

このうちいくつかは`vision.md`に「その先の構想」として挙げてあるが、構想に挙がっていることと、着手が決まっていることは別である。
ロードマップに載っていないものは、今は手を出さない。
